# Wallets

Add Tempo to a wallet, or let your users pay with the wallet they already have.

If you build a wallet such as MetaMask, Rabby, or Ledger, your users expect to hold and send stablecoins on Tempo from it. If you build an app, some of your users already have one of those wallets and want to pay with it. Either way, the account is a [single-key account](/docs/accounts/how-it-works#address): one private key, held in the wallet, approves every transaction. Single-key accounts work on mainnet and testnet.

## Recommended wallet setup

- **Wallet teams:** add the Tempo networks, show stablecoin balances instead of a native balance, and send [Tempo Transactions](/docs/guide/tempo-transaction) so users can pick a fee token, batch calls, and use sponsored fees and access keys.
- **Apps:** keep wagmi's `injected` connector for users who have a browser wallet, and create new accounts with a [passkey or device key](/docs/accounts/authentication).
- **Users who want backup signers:** an [account upgrade](/docs/accounts/account-configuration/account-upgrade) adds them at the same address. Devnet until T14.

## Connect a browser wallet

Connect your wallet to add Tempo mainnet to it.

<ConnectWallet network="mainnet" />

In your app, wagmi's `injected` connector connects the browser's wallet. wagmi also finds every other installed wallet that announces itself ([EIP-6963](https://eips.ethereum.org/EIPS/eip-6963)) and lists it in `useConnectors()`.

```ts [wagmi.config.ts]
import { tempo } from 'viem/chains'
import { createConfig, http } from 'wagmi'
import { injected } from 'wagmi/connectors'

export const config = createConfig({
  chains: [tempo],
  connectors: [injected()], // [!code hl]
  transports: { [tempo.id]: http() },
})
```

From there, `useConnect` and wagmi's transaction hooks work as on any EVM chain. Tempo has no native gas token: the wallet pays each fee in a stablecoin, [by default](/docs/accounts/fees#fee-token-precedence) the one a payment sends and pathUSD for most other calls. A wallet may also show a placeholder native balance, so [show stablecoin balances](/docs/quickstart/evm-compatibility#handling-eth-native-token-balance-checks) in your app instead.

## What a browser wallet's account can't do

A browser wallet signs standard Ethereum transactions, which differ from [Tempo Transactions](/docs/guide/tempo-transaction), Tempo's own transaction type, in these ways:

| | Standard Ethereum transactions (browser wallet) | Tempo Transactions |
| --- | --- | --- |
| Signers | One private key, in the wallet | [Passkeys, device keys, or private keys](/docs/accounts/authentication); several per configurable account |
| Lost key | Loses the account and its funds | On a configurable account, [another signer replaces it](/docs/accounts/account-configuration#plan-for-recovery). On a single-key account, losing the key loses the account. |
| Network fees | Paid by the user | [Sponsored by your app](/docs/accounts/fees/fee-sponsorship), if you choose |
| Several calls | One call per transaction | Several calls that succeed or fail together |
| [Access keys](/docs/accounts/access-keys) | The wallet authorizes one with an `authorizeKey` call to the [Account Keychain](/docs/development/account-keychain#authorize-an-access-key). The access key then signs its own Tempo Transactions in your app. | Authorized in the transaction that first uses the key |

A hardware wallet also holds one private key, so its account is a single-key account like any other EOA, with the same limits. A wallet that [adds Tempo](/docs/accounts/wallets/add-tempo-to-your-wallet) and sends Tempo Transactions lets its users pick a fee token, batch calls, and accept sponsored fees.

Several signers per account and lost-key replacement need a configurable account, which until T14 runs only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), not on mainnet or testnet.

### Create new accounts with a passkey or device key

For accounts you create for your users, prefer a [passkey or device key](/docs/accounts/authentication). A user moving off a browser wallet sends the funds to a new account whose key is a passkey or device key: on mainnet or testnet, a [single-key account](/docs/development/single-key-accounts); on the Tempo Accounts devnet, a [configurable account](/docs/accounts/create) with that key as its first signer.

### Upgrade an existing address in place

To keep the address instead, [upgrade the account in place](/docs/accounts/account-configuration/account-upgrade): it adds signers, and the original key signs the upgrade as a Tempo Transaction, so the wallet holding that key must support Tempo Transactions.

## Connect a wallet to your app

If a user already has a self-custodial wallet, such as Tempo Wallet, connect it with the [Accounts SDK](https://accounts.tempo.xyz/docs). The wallet holds the keys and signs; your app uses the address the user selects. Tempo Wallet sends transactions through its own RPC endpoint, not your devnet client, so the demo and code run on Moderato testnet, whose stablecoins have no value.

```bash [Terminal]
pnpm add --save-exact accounts@0.18.4 viem
```

<span id="connect-tempo-wallet-from-your-application" />

```ts [connect.ts]
import { Provider } from 'accounts'
import { tempoModerato } from 'viem/chains'

const provider = Provider.create({ chains: [tempoModerato], testnet: true }) // [!code hl]
const [address] = await provider.request({ method: 'eth_requestAccounts' }) // [!code hl]
if (!address) throw new Error('No account was selected')
```

Track the wallet connection separately from your app's signed-in session. On `accountsChanged`, update the selected address, or clear it when the wallet disconnects; on `chainChanged`, refresh network-dependent state before you enable transactions. To send payments, create wallet and public clients from this provider as in the [browser wallet setup](/docs/guide/payments/send-a-payment/examples#browser-wallet-setup). [Wallet partners](/docs/partners/wallets) lists other wallets you can connect.
