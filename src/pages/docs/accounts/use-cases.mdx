# Use cases

Find the setup and guides for what you're building.

Tempo accounts serve consumer apps, backends and agents, custodians and treasuries, and wallets. What changes between them is who holds which key: a customer's passkey, a provider's key, your backend's access key, or an approver's signer. Each can do only what the account allows, and Tempo enforces those limits on every transaction.

Single-key accounts, access keys, fee sponsorship, virtual addresses, and receive policies work on mainnet and testnet. Accounts with several signers and a threshold run only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet).
