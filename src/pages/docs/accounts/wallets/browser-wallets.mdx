# Browser wallets

<span id="legacy-accounts" />

Browser wallets such as MetaMask and Rabby work on Tempo as they are, on every network including mainnet.

People can pay with the wallet they already have: connect it in your app with wagmi's `injected` connector. Each browser wallet holds a [single-key account](/docs/accounts/how-it-works#address), one private key like a standard Ethereum account, and sends standard Ethereum transactions, so it can't use sponsored fees, batched calls, or extra signers. For accounts you create for your users, prefer a [passkey or device key](/docs/accounts/authentication).

## Connect a browser wallet

Connect your wallet to add Tempo mainnet to it.

<ConnectWallet network="mainnet" />

In your app, wagmi's `injected` connector connects the browser's wallet. wagmi also finds every other installed wallet that announces itself ([EIP-6963](https://eips.ethereum.org/EIPS/eip-6963)) and lists it in `useConnectors()`.

```ts [wagmi.config.ts]
import { tempo } from 'viem/chains'
import { createConfig, http } from 'wagmi'
import { injected } from 'wagmi/connectors'

export const config = createConfig({
  chains: [tempo],
  connectors: [injected()], // [!code hl]
  transports: { [tempo.id]: http() },
})
```

From there, `useConnect` and wagmi's transaction hooks work as on any EVM chain. Tempo has no native gas token: the wallet pays each fee in a stablecoin, [by default](/docs/accounts/fees#fee-token-precedence) the one a payment sends and pathUSD for most other calls. A wallet may also show a placeholder native balance, so [show stablecoin balances](/docs/quickstart/evm-compatibility#handling-eth-native-token-balance-checks) in your app instead.

## What a browser wallet's account can't do

A browser wallet's account has one key and sends standard Ethereum transactions, so it misses these Tempo account features:

| | Browser wallet account | Tempo account |
| --- | --- | --- |
| Signers | One private key, in the wallet | [Passkeys, device keys, or private keys](/docs/accounts/authentication), several per account |
| Lost key | Loses the account and its funds | [Another signer replaces it](/docs/accounts/key-management#plan-for-recovery) |
| Network fees | Paid by the user | [Sponsored by your app](/docs/accounts/fees/fee-sponsorship), if you choose |
| Several calls | One call per transaction | Several calls that succeed or fail together |

Each of these needs a [Tempo Transaction](/docs/guide/tempo-transaction), Tempo's own transaction type. Several signers per account, and replacing a lost key, also need a configurable account, which works only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), not on mainnet or testnet.

<span id="move-a-legacy-account-to-modern-signers" />

## Move to a passkey or device key

Send the funds to a new account whose key is a passkey or device key: on mainnet or testnet, a [single-key account](/docs/development/single-key-accounts); on the Tempo Accounts devnet, a [Tempo account](/docs/accounts/create) with that key as its first signer. To keep the address instead, [upgrade the account in place](/docs/accounts/key-management/account-upgrade): it adds signers, and the original key signs the upgrade as a Tempo Transaction, so the wallet holding that key must support Tempo Transactions. Upgrades also work only on the devnet.
