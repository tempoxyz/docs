# Browser wallets

<span id="legacy-accounts" />

If your users connect MetaMask or another browser wallet, they bring a single-key account they already control.

A browser wallet such as MetaMask or Rabby holds one private key, like a standard Ethereum account, and the user approves every transaction in the wallet. Each one is a [single-key account](/docs/accounts/how-it-works#address) and works on Tempo as it is, on every network including mainnet: connect it with wagmi's `injected` connector. Because browser wallets send standard Ethereum transactions, not [Tempo Transactions](/docs/guide/tempo-transaction), the wallet's own transactions can't use sponsored fees or batched calls.

## Connect a browser wallet

Connect your wallet to add Tempo mainnet to it.

<ConnectWallet network="mainnet" />

In your app, wagmi's `injected` connector connects the browser's wallet. wagmi also finds every other installed wallet that announces itself ([EIP-6963](https://eips.ethereum.org/EIPS/eip-6963)) and lists it in `useConnectors()`.

```ts [wagmi.config.ts]
import { tempo } from 'viem/chains'
import { createConfig, http } from 'wagmi'
import { injected } from 'wagmi/connectors'

export const config = createConfig({
  chains: [tempo],
  connectors: [injected()], // [!code hl]
  transports: { [tempo.id]: http() },
})
```

From there, `useConnect` and wagmi's transaction hooks work as on any EVM chain. Tempo has no native gas token: the wallet pays each fee in a stablecoin, [by default](/docs/accounts/fees#fee-token-precedence) the one a payment sends and pathUSD for most other calls. A wallet may also show a placeholder native balance, so [show stablecoin balances](/docs/quickstart/evm-compatibility#handling-eth-native-token-balance-checks) in your app instead.

## What a browser wallet's account can't do

A browser wallet's account has one key, and the wallet sends standard Ethereum transactions. Here's what that changes compared with [Tempo Transactions](/docs/guide/tempo-transaction), Tempo's own transaction type:

| | Standard Ethereum transactions (browser wallet) | Tempo Transactions |
| --- | --- | --- |
| Signers | One private key, in the wallet | [Passkeys, device keys, or private keys](/docs/accounts/authentication); several per account only on the devnet |
| Lost key | Loses the account and its funds | Devnet only: [another signer replaces it](/docs/accounts/key-management#plan-for-recovery). On mainnet and testnet, losing the key loses the account. |
| Network fees | Paid by the user | [Sponsored by your app](/docs/accounts/fees/fee-sponsorship), if you choose |
| Several calls | One call per transaction | Several calls that succeed or fail together |
| [Access keys](/docs/accounts/access-keys) | The wallet authorizes one with an `authorizeKey` call to the [Account Keychain](/docs/development/account-keychain#authorize-an-access-key). The access key then signs its own Tempo Transactions in your app. | Authorized in the transaction that first uses the key |

Several signers per account, and replacing a lost key, need a configurable account, which works only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), not on mainnet or testnet.

## What we recommend

### Support browser wallets for users who have one

People can pay with the wallet they already have, so keep the `injected` connector in your app for them.

<span id="move-a-legacy-account-to-modern-signers" />
<span id="move-to-a-passkey-or-device-key" />

### Create new accounts with a passkey or device key

For accounts you create for your users, prefer a [passkey or device key](/docs/accounts/authentication). A user moving off a browser wallet sends the funds to a new account whose key is a passkey or device key: on mainnet or testnet, a [single-key account](/docs/development/single-key-accounts); on the Tempo Accounts devnet, a [Tempo account](/docs/accounts/create) with that key as its first signer.

### Upgrade an existing address in place

To keep the address instead, [upgrade the account in place](/docs/accounts/key-management/account-upgrade): it adds signers, and the original key signs the upgrade as a Tempo Transaction, so the wallet holding that key must support Tempo Transactions. Upgrades work only on the devnet.
