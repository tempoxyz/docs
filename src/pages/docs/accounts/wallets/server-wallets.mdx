# Server wallets

If you're building a server wallet, give it an access key so Tempo limits what your server can do.

A server wallet is a key your backend signs with, in a KMS, an HSM, or a provider such as Privy or Turnkey. It works on Tempo as it is, on mainnet and testnet today: any key that signs Ethereum transactions can send stablecoins. On Tempo, you can make the server's key an [access key](/docs/accounts/access-keys) instead: Tempo then rejects any payment over its [spending limit](/docs/accounts/access-keys/spending-limits), to a [recipient](/docs/accounts/access-keys/scopes) you didn't list, or after its [expiry](/docs/accounts/access-keys/expiry).

<span id="give-the-backend-an-access-key-not-the-account-key" />

## Why an access key, not the account key

If the server holds the account key and is breached, the attacker can move the whole balance. If it holds an access key, the attacker can pay only within that key's limit, recipients, and expiry, and you can [revoke](/docs/accounts/access-keys/revocation) the key.

Keep the account's own key with the user, or with your own signers for a business account, and give the backend the access key. The backend then pays without asking each time. [Pay out from a backend](/docs/accounts/guides/automations/pay-out-from-a-backend) walks through it.

## Sign with a KMS key

AWS KMS and Google Cloud KMS keys work as access keys, and the private key never leaves the KMS. An access key signs the 32-byte digest of each [Tempo Transaction](/docs/guide/tempo-transaction), and both KMSs sign digests with secp256k1 and P-256 keys. Wrap the KMS signing call as a viem account, as in [Keep the key in your KMS](/docs/accounts/guides/automations/pay-out-from-a-backend#keep-the-key-in-your-kms).

## Sign with a server wallet provider

Privy server wallets and Turnkey both sign Tempo Transactions and raw hashes:

| Provider | How it signs on Tempo |
| --- | --- |
| [Privy](https://docs.privy.io/wallets/using-wallets/tempo/send-a-transaction) server wallets | Sends Tempo Transactions through its wallet API, or signs raw hashes with `raw_sign` |
| [Turnkey](https://docs.turnkey.com/features/networks/overview) | Signs Tempo Transactions with `sign_transaction`, which its policies can inspect, or raw hashes with `sign_raw_payload` |

To use one as an access key, wrap its raw-hash signing as a viem account, as in [Authorize access keys from an embedded wallet](/docs/accounts/guides/users/authorize-access-keys-from-an-embedded-wallet#wrap-the-providers-signing-as-an-account).

## Rotate and revoke backend keys

Save each access key's address with the service that holds it. To rotate, authorize a new key, switch the service to it, then [revoke](/docs/accounts/access-keys/revocation) the old one. A key can't be extended past its expiry, so [renew it](/docs/accounts/access-keys/expiry#renew-an-expiring-key) before then.
