# Fees

Every Tempo transaction pays its network fee in a USD stablecoin, never a gas token. Decide two things per account: which stablecoin pays the fee, and who pays it, the account itself or a fee payer that sponsors it.

## How Tempo account fees work

The fee comes from the transaction's fee payer, which is the account itself unless a fee payer signs. Before execution, Tempo deducts the maximum fee, the gas limit times the gas price, from the fee payer's balance in the fee token, then refunds the unused gas afterward. A standard TIP-20 transfer costs about $0.0006 at the base-fee cap and about $0.00003 at the floor.

The block's validator may want a different stablecoin. The [Fee AMM](/docs/protocol/fees/spec-fee-amm) converts the fee token to it, so the fee token needs enough liquidity there. If the balance or the liquidity falls short, the transaction is invalid and isn't included. A transaction that's included and then reverts still pays its fee.

<span id="set-an-accounts-default-fee-token" />

## Fee token precedence

Tempo picks the fee token from the first of these that's set:

1. `feeToken` on the transaction.
2. The fee payer's default fee token.
3. The token being transferred, when every call is a `transfer` or `transferWithMemo` on the same USD token and the account pays its own fee.
4. The input token of a single Stablecoin DEX swap.
5. pathUSD.

Tempo checks only the first token it finds. If the fee payer lacks the balance or the token lacks liquidity, the transaction is invalid; Tempo doesn't try the next one. Set a default fee token explicitly so the account doesn't fall back to pathUSD: see [Set a default fee token](/docs/accounts/fees/fee-tokens#set-a-default-fee-token). Full rules: [fee token preferences](/docs/protocol/fees/spec-fee#fee-token-preferences).

## Who pays the fee

By default, the account pays its own fees from its balance. A fee payer can sponsor a transaction instead by adding its own signature, and then the fee comes from the fee payer's balance in the token it chooses. The fee payer's signature authorizes only the fee: it can't approve the account's calls or move its funds. See [Fee sponsorship](/docs/accounts/fees/fee-sponsorship).
