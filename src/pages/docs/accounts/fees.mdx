# Fee Management

Pays each Tempo transaction's network fee in a USD stablecoin, with no separate gas token.

## Overview

Fee management decides who pays each transaction's network fee and which stablecoin pays it. Every Tempo transaction pays its fee in a USD stablecoin, so accounts need no separate gas token.

Fee tokens and fee sponsorship work on mainnet and testnet. The same fee rules apply to configurable accounts, which run only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet) until T14.

## Fee Payment

Each transaction pays its fee in one of three ways:

- **By Default:** The account pays its own fee. A plain transfer pays in the stablecoin it sends.
- **With a Fee Token:** The fee is paid in a different stablecoin, the [fee token](/docs/accounts/fees/fee-tokens).
- **With a Fee Payer:** A [fee payer](/docs/accounts/fees/fee-sponsorship) pays for your customers. It can't change the account's calls or move its funds.

## Fee Costs

A standard stablecoin transfer costs about $0.00003 when the network is quiet. It costs about $0.0006 at the base fee's cap.

Before the transaction runs, Tempo deducts its maximum fee from the fee payer's balance in the fee token. The maximum fee is the gas limit times the gas price. Afterward, Tempo refunds the unused part.

When the validator producing the block wants a different stablecoin, the [Fee AMM](/docs/protocol/fees/spec-fee-amm) converts the fee to it. The Fee AMM is a set of built-in exchange pools.

Insufficient balance, unavailable conversion liquidity, or other failed [fee token checks](/docs/accounts/fees/fee-tokens#supported-fee-tokens) make the transaction invalid. Tempo never includes it, so it costs nothing. A transaction that's included and then fails still pays its fee.

## Fee Token Order

Tempo uses the first of these that applies:

1. `feeToken` on the transaction.
2. The fee payer's default fee token.
3. The token being transferred. This applies when every call is a `transfer` or `transferWithMemo` on the same USD token. The account must also pay its own fee.
4. The input token of a single Stablecoin DEX swap.
5. The protocol fallback tries pathUSD, then OUSD.

If one of the first four rules selects a token, Tempo uses only that token. If its fee checks fail, the transaction is invalid. An explicit pathUSD choice does not fall back to OUSD.

Without a token selected by those rules, Tempo uses the [protocol fallback](/docs/protocol/fees/spec-fee#ordered-fallback-from-t13). It tries pathUSD first, then OUSD when the fee payer's pathUSD balance cannot cover the maximum fee. One token must cover the entire maximum fee; balances are not combined. Only an insufficient balance advances the fallback, not policy, pause, access-key, or Fee AMM liquidity failures.

[Set a default fee token](/docs/accounts/fees/fee-tokens#set-a-default-fee-token) to choose which stablecoin an account pays fees in.
