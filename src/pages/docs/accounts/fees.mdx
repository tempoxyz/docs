# Fee management

Tempo has no native gas token. Every transaction pays its network fee in a USD TIP-20 stablecoin, either from the account's own balance in a fee token it chooses, or from a fee payer that sponsors the transaction.

## How an account pays fees

The fee comes from the transaction's fee payer, which is the account itself unless a fee payer signs. Before execution, Tempo deducts the maximum fee (gas limit times gas price) from the fee payer's balance in the fee token, then refunds the unused gas after execution. A standard TIP-20 transfer costs about $0.0006 at the base-fee cap and about $0.00003 at the floor.

The fee token can be any USD-denominated TIP-20 token with enough liquidity on the [Fee AMM](/docs/protocol/fees/spec-fee-amm), which converts it to the stablecoin the block's validator receives. If the balance or the liquidity falls short, the transaction is invalid and isn't included. A transaction that is included and then reverts still pays its fee.

## Set an account's default fee token

An account sets a default fee token once, and Tempo uses it for every transaction the account pays for. Set one explicitly: otherwise Tempo infers the token from the transaction and falls back to pathUSD. For most accounts, the recommended default is [OUSD](/docs/guide/ousd).

```ts [set-fee-token.ts]
const { receipt } = await client.fee.setUserTokenSync({
  token: '0x20c0000000000000000000006a37da5c996874be', // OUSD on Tempo mainnet
})
```

To pay one transaction's fee in another stablecoin, pass `feeToken` on that transaction. It overrides the default for that transaction only:

```ts [transfer.ts]
import { parseUnits } from 'viem'

await client.token.transferSync({
  amount: parseUnits('25', 6),
  feeToken: usdc, // this transaction's fee token
  to: recipient,
  token: ousd,
})
```

Tempo picks the fee token from the first of these that's set:

1. `feeToken` on the transaction.
2. The fee payer's default fee token.
3. The token being transferred, when every call is a `transfer` or `transferWithMemo` on the same USD token and the account pays its own fee.
4. The input token of a single Stablecoin DEX swap.
5. pathUSD.

Tempo checks only the first token it finds. If the fee payer lacks the balance or the token lacks liquidity, the transaction is invalid; Tempo doesn't try the next one. See [Choose a fee token](/docs/guide/payments/pay-fees-in-any-stablecoin) for examples in each SDK and [fee token preferences](/docs/protocol/fees/spec-fee#fee-token-preferences) for the full rules.

## Sponsor fees with a fee payer

A fee payer pays an account's fees so the account needs no fee balance, such as a new account sending its first payment right after the customer creates it. The account signs its calls with the fee token left blank. The fee payer checks the transaction against its policy, chooses the fee token, and adds its own signature. Tempo verifies both signatures and takes the fee from the fee payer's balance.

The fee payer's signature covers one specific transaction and authorizes only the fee:

| A fee payer can | A fee payer can't |
| --- | --- |
| Pay the fee from its own balance | Approve a transaction or count toward the account's threshold |
| Choose the fee token for transactions it sponsors | Change the calls the account signed |
| Refuse or delay sponsorship | Move the account's funds |

Because the fee payer holds no signer or access key, a fee payer that stops working can't take funds. The account can still pay its own fees when it holds a fee token.

To use one, point the client's relay at a fee payer service and mark each sponsored transaction with `feePayer: true`:

```ts [client.ts]
import { http, parseUnits } from 'viem'
import { tempoModerato } from 'viem/chains'
import { createClient, withRelay } from 'viem/tempo'

export const client = createClient({
  chain: tempoModerato,
  transport: withRelay(http(), http('https://sponsor.moderato.tempo.xyz')),
})

await client.token.transferSync({
  account,
  amount: parseUnits('25', 6),
  feePayer: true, // request sponsorship
  to: recipient,
  token: alphaUsd,
})
```

The endpoint above is the public fee payer on Moderato testnet and needs no API key. In production, use the hosted [Fee Payer API](/docs/api/fee-payer) with a Tempo API key, or run your own. [Sponsor fees](/docs/guide/payments/sponsor-user-fees) walks through the full flow with a live demo.

## Run your own fee payer

Anyone can run a fee payer: you, your wallet provider, or another operator. Host one with viem's `Relay` and its `Relay.feePayer` plugin, funded with the stablecoins it pays fees in. Its `validate` callback receives each transaction request and decides whether to sponsor it:

```ts [fee-payer.ts]
import { http, type Hex } from 'viem'
import { privateKeyToAccount } from 'viem/accounts'
import { tempoModerato } from 'viem/chains'
import { createClient, Relay, withRelay } from 'viem/tempo'

const plugins = [
  Relay.feePayer({
    account: privateKeyToAccount(process.env.FEE_PAYER_KEY as Hex),
    validate: async (request) => request.from !== undefined && (await isCustomer(request.from)),
  }),
]

export const client = createClient({
  chain: tempoModerato,
  transport: withRelay(http(), { plugins }),
})
```

Only `true` sponsors the transaction. `false`, or a named reason such as `'spend_limit_exceeded'`, refuses it, and the relay returns the transaction for the account to pay itself. Without `validate`, the fee payer sponsors every request it receives, so add authentication and rate limits before you fund it.

To serve the fee payer to other clients, pass the same plugins to `Relay.create({ client, plugins })` and serve `relay.fetch`. When the relay also runs `Relay.accounts`, list `Relay.accounts` first.
