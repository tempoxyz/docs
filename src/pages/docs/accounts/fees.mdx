# Fee management

Every Tempo transaction pays its network fee in a USD stablecoin, so accounts need no separate gas token.

For each transaction, you decide who pays the fee and which stablecoin pays it. Fee tokens and fee sponsorship work on mainnet and testnet. The same fee rules apply to configurable accounts, which run only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet) until T14.

## How it works

- **By default.** The account pays its own fee. A plain transfer pays in the stablecoin it sends.
- **With a fee token.** The fee is paid in a different stablecoin, the [fee token](/docs/accounts/fees/fee-tokens).
- **With a fee payer.** A [fee payer](/docs/accounts/fees/fee-sponsorship) pays for your customers. It can't change the account's calls or move its funds.

A standard stablecoin transfer costs about $0.00003 when the network is quiet. It costs about $0.0006 at the base fee's cap. Before the transaction runs, Tempo deducts its maximum fee (gas limit times gas price) from the fee payer's balance in the fee token. Afterward, Tempo refunds the unused part.

If the validator producing the block wants a different stablecoin, the [Fee AMM](/docs/protocol/fees/spec-fee-amm) converts the fee to it. The Fee AMM is a set of built-in exchange pools. If the fee token fails any of [Tempo's fee token checks](/docs/accounts/fees/fee-tokens#supported-fee-tokens), the transaction is invalid. Tempo never includes it, so it costs nothing. A transaction that's included and then fails still pays its fee.

## Fee token order

Tempo uses the first of these that applies:

1. `feeToken` on the transaction.
2. The fee payer's default fee token.
3. The token being transferred, when every call is a `transfer` or `transferWithMemo` on the same USD token and the account pays its own fee.
4. The input token of a single Stablecoin DEX swap.
5. pathUSD, the first stablecoin deployed on Tempo.

Tempo checks only that first token. If the fee payer can't pay in it, the transaction is invalid, even when a later token would work. Without a default, a transaction that isn't a transfer or swap falls back to pathUSD. The fee payer may not hold pathUSD, so [set a default fee token](/docs/accounts/fees/fee-tokens#set-a-default-fee-token).

Specification: [fee token preferences](/docs/protocol/fees/spec-fee#fee-token-preferences).
