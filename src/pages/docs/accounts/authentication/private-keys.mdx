# Private keys

A private key is a secp256k1 or P-256 key that you or a provider already hold, in a wallet, a KMS, or an HSM. It approves for a Tempo account as a weighted signer, or pays alone within limits as an [access key](/docs/accounts/access-keys).

The key stays where it is: the account lists only its address or public key, and the wallet, KMS, or HSM signs each approval. A private key trusts whoever controls it and the infrastructure that holds it, and depends on no outside service. Use it for treasury approvers, servers, scripts, and recovery keys.

<span id="recommended-roles-for-your-keys" />

## Private key sources

| Source | Examples | Recommended role |
| --- | --- | --- |
| CLI wallets | The [Tempo CLI wallet](/docs/cli/wallet), Foundry `cast` | Access key for scripts and agents |
| Hardware wallets | A treasury approver's hardware wallet | Signer at weight 1, so each approval needs a person and a device |
| Browser wallets | An operator's browser extension wallet | Signer at weight 1 for operator approvals |
| Other crypto wallets | Mobile wallets, and [wallet providers](/docs/accounts/guides/wallet-provider) such as Turnkey or Privy | Signer at weight 1. A provider's policies apply before it signs. |
| KMS or HSM | Keys in your cloud KMS or HSM | Signer for recovery, or [access key](/docs/accounts/guides/automate-backend) for automation |

## Require two treasury signers

Two keys at weight 1 and a threshold of 2 means neither approver can pay alone:

```ts [treasury.ts]
import { Account } from 'viem/tempo'

const finance = Account.fromSecp256k1(process.env.FINANCE_SIGNER_KEY as `0x${string}`)
const operations = Account.fromSecp256k1(process.env.OPERATIONS_SIGNER_KEY as `0x${string}`)
const account = Account.fromConfig({ address: 'infer', owners: [finance, operations], threshold: 2 })
```

The example reads raw keys from the environment. To keep a key in its wallet, KMS, HSM, or provider, use that source's viem account adapter instead.

A secp256k1 key in the account's first configuration can also recover funds sent to the same address on another EVM chain. See [cross-chain recovery](/docs/accounts/guides/self-custody#recover-funds-sent-on-another-chain).

For walkthroughs, see [Set up a company treasury wallet](/docs/accounts/guides/company-treasury) and [Automate a backend](/docs/accounts/guides/automate-backend). For other methods, see [Signing methods](/docs/accounts/authentication).
