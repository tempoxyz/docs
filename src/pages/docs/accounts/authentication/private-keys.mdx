# Private keys

A private key lets you sign for a Tempo account with a key you already hold in a wallet, KMS, or HSM.

A private key is one of three signing methods for a Tempo account, with [device keys](/docs/accounts/authentication/device-keys) and [passkeys](/docs/accounts/authentication/passkeys). Tempo accepts secp256k1 keys, the kind Ethereum wallets use, and P-256 keys, and verifies each signature onchain.

## Roles

Add each key as a signer, which approves toward the account's [threshold](/docs/accounts/policies/signing-thresholds), or as an [access key](/docs/accounts/access-keys), which pays alone within its limits:

| Where the key lives | Add it as |
| --- | --- |
| CLI wallet, such as the [Tempo CLI wallet](/docs/cli/wallet) or Foundry `cast` | Access key for scripts and agents |
| Hardware, browser, or mobile wallet | Signer at weight 1, one per approver |
| [Wallet provider](/docs/accounts/apps/self-custodial-wallets), such as Turnkey or Privy | Signer at weight 1. The provider signs only when its own policies allow. |
| Cloud KMS or HSM | Signer for recovery, or access key for [backend payouts](/docs/accounts/automations/pay-out-from-a-backend) |

On mainnet and testnet today, a private key can be a single-key account's one key, as in a standard Ethereum account, or an access key on that account. Signers need a configurable account, which runs only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), so the next example works only there.

## Add a private key

Give each key a weight below the threshold, so no single holder can pay alone, and keep each approver's key in its own wallet or HSM. Here both signers must approve:

```ts [treasury.ts]
import { Account } from 'viem/tempo'

const finance = Account.fromSecp256k1(process.env.FINANCE_SIGNER_KEY as `0x${string}`)
const operations = Account.fromSecp256k1(process.env.OPERATIONS_SIGNER_KEY as `0x${string}`)

const account = Account.fromConfig({ // [!code hl]
  // derive the address from these first signers
  address: 'infer', // [!code hl]
  // weight 1 each
  owners: [finance, operations], // [!code hl]
  threshold: 2, // [!code hl]
}) // [!code hl]
```

The example reads raw keys from the environment. To keep a key in its wallet, KMS, HSM, or provider, pass the Viem account that source provides instead. For a raw P-256 key, use `Account.fromP256`. [Set up a team multisig](/docs/accounts/custodians/team-multisig) walks through the full setup.

## Limits

- Anyone who can make the key sign, including anyone with signing access in your KMS, approves at its weight until you [remove it](/docs/accounts/account-configuration/configuration-updates#remove-a-lost-or-compromised-signer).
- A signer has no spending limit. To cap what a key can pay, make it an access key instead.
- Only the secp256k1 signers you create the account with could [recover funds sent to its address on another chain](/docs/accounts/account-configuration#recover-funds-sent-on-another-chain), and no chain supports that recovery yet.
