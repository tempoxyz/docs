# Device keys

A device key lets the customer's phone, computer, or browser pay with no prompt, within limits a signer sets once. Add it as an [access key](/docs/accounts/access-keys), not a signer, so a lost or unlocked device can spend only up to those limits until the key expires.

## What a device key is

A device key is a P-256 key that the device creates in its platform key store and can't export. The key store signs without revealing the key. The customer's passkey authorizes it once with a spending limit and an expiry, and Tempo checks those limits on every payment it makes.

## Device key stores by platform

| Platform | Key store |
| --- | --- |
| iPhone and iPad | Secure Enclave |
| Mac | Secure Enclave |
| Android | Android Keystore, hardware-backed, or StrongBox where available |
| Windows | TPM, through the Microsoft Platform Crypto Provider |
| Browsers | WebCrypto non-extractable key, kept in IndexedDB |

For keys on servers, use a KMS or HSM. See [Private keys](/docs/accounts/authentication/private-keys).

## What a device key trusts

A device key trusts only the device that holds it. Whoever unlocks the device can pay up to the key's limits until it expires. No app server or wallet provider holds the key or can use it.

## Create a device key

<P256KeyDemo />

The demo creates a key in this browser, funds its Moderato test account, and pays with it. Reload the page and the key is still here.

In code, the device creates the key, a signer authorizes it with limits, and the first payment carries that authorization:

```ts [device-key.ts]
import { Account, Expiry, WebCryptoP256 } from 'viem/tempo'

const keyPair = await WebCryptoP256.createKeyPair() // non-extractable; store keyPair in IndexedDB

const deviceKey = Account.fromWebCryptoP256(keyPair, { access: account })
const keyAuthorization = await client.accessKey.signAuthorization({
  accessKey: deviceKey,
  account, // approved by the customer's passkey
  expiry: Expiry.days(30),
  limits: [{ token: alphaUsd, limit: parseUnits('500', 6), period: 86_400 }],
})

await client.token.transferSync({
  account: deviceKey,
  amount: parseUnits('5', 6),
  keyAuthorization, // first payment only
  to: recipient,
  token: alphaUsd,
})
```

Later payments omit `keyAuthorization`.

## Device key limits

- A browser key lives in IndexedDB and is gone if the customer clears site data. Sign in again to authorize a new one.
- A key can't move to a new device. Each device authorizes its own key.
- A P-256 key can also be a weighted signer, but a signer has no spending limits, so keep device keys as access keys.
- For a lost device, [revoke its key](/docs/accounts/access-keys/revocation#revoke-an-access-key). The account's signers don't change.
- Limits, expiry, and scopes work as for any access key: see [Spending limits](/docs/accounts/access-keys/spending-limits), [Expiry](/docs/accounts/access-keys/expiry), and [Scopes](/docs/accounts/access-keys/scopes).

For other methods, see [Signing methods](/docs/accounts/authentication).
