# Device keys

A device key is a P-256 key that the customer's phone, computer, or browser creates and can't export. A signer authorizes it once as an [access key](/docs/accounts/access-keys), and it then pays within limits with no prompt.

The key lives in the platform's key store, which signs without revealing it. A device key trusts only that device: whoever unlocks it can pay up to the key's limits until it expires. Use it for everyday payments, with the customer's passkey or login approving the key and anything above its limits.

## Device key stores by platform

| Platform | Key store |
| --- | --- |
| iPhone and iPad | Secure Enclave |
| Mac | Secure Enclave |
| Android | Android Keystore, hardware-backed, or StrongBox where available |
| Windows | TPM, through the Microsoft Platform Crypto Provider |
| Browsers | WebCrypto non-extractable key, kept in IndexedDB. Gone if the customer clears site data. |

For keys on servers, use a KMS or HSM. See [Private keys](/docs/accounts/authentication/private-keys).

## How a device key starts paying

<P256KeyDemo />

The demo creates a key in this browser, funds its Moderato test account, and pays with it. Reload the page and the key is still here.

In code, the device creates the key, a signer authorizes it with limits, and the first payment carries that authorization:

```ts [device-key.ts]
import { Account, Expiry, WebCryptoP256 } from 'viem/tempo'

const keyPair = await WebCryptoP256.createKeyPair() // non-extractable; store keyPair in IndexedDB

const deviceKey = Account.fromWebCryptoP256(keyPair, { access: account })
const keyAuthorization = await client.accessKey.signAuthorization({
  accessKey: deviceKey,
  account, // approved by the customer's passkey or login
  expiry: Expiry.days(30),
  limits: [{ token: alphaUsd, limit: parseUnits('500', 6), period: 86_400 }],
})

await client.token.transferSync({
  account: deviceKey,
  amount: parseUnits('5', 6),
  keyAuthorization, // first payment only
  to: recipient,
  token: alphaUsd,
})
```

Later payments omit `keyAuthorization`. A P-256 key can also be a weighted signer, but a signer has no limits, so keep device keys as access keys.

For a lost device, [revoke its key](/docs/accounts/access-keys#revoke-an-access-key). The account's signers don't change.

For a sign-in that authorizes a device key, see [Enterprise SSO login](/docs/accounts/guides/enterprise-sso). For other methods, see [Signing methods](/docs/accounts/authentication).
