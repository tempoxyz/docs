# Device keys

A device key lets the customer's phone, computer, or browser pay without asking the customer to approve each payment. The customer's passkey authorizes the key once as an [access key](/docs/accounts/access-keys), and Tempo rejects any payment over its spending limit or after it expires.

## What a device key is

A device key is a P-256 key that never leaves the device: the device's key store creates it and signs with it, but won't export it.

<span id="device-key-stores-by-platform" />

| Platform | Key store |
| --- | --- |
| iPhone, iPad, and Mac | Secure Enclave |
| Android | Android Keystore, backed by StrongBox or other secure hardware where available |
| Windows | TPM, through the Microsoft Platform Crypto Provider |
| Browsers | Non-extractable WebCrypto key, kept in IndexedDB |

On a server, use a [private key](/docs/accounts/authentication/private-keys) in your KMS or HSM instead.

<span id="what-a-device-key-trusts" />

No app server or wallet provider holds the key, but anyone who unlocks the device can pay with it, up to its [spending limit](/docs/accounts/access-keys/spending-limits) and until it [expires](/docs/accounts/access-keys/expiry). That cap is why you add a device key as an access key, not a signer: a signer has no spending limit.

## Create a device key

<P256KeyDemo />

The demo makes the device key its own account on the Tempo Accounts devnet, to show signing without a prompt. Reload the page and the key is still there.

In your app, add the key to the customer's account as an access key instead. The device creates the key, the customer's passkey authorizes it for up to 500 AlphaUSD a day for 30 days, and the first payment carries that authorization. This works on mainnet and testnet today when the customer's account is a single-key account whose one key is the passkey.

The example below uses a configurable account with the passkey as its signer. Configurable accounts run only on the Tempo Accounts devnet, so `client.ts` connects there ([set up the devnet key](/docs/accounts/create#connect-to-the-devnet)).

In `device-key.ts`, `account` is the customer's funded account, built as in [Passkeys](/docs/accounts/authentication/passkeys#create-a-passkey-signer), and `recipient` is the payee's address:

```ts [device-key.ts]
import { parseUnits } from 'viem'
import { Account, Expiry, WebCryptoP256 } from 'viem/tempo'
import { client } from './client'

const alphaUsd = '0x20c0000000000000000000000000000000000001' // AlphaUSD, a devnet test stablecoin

// Non-extractable. Save keyPair in IndexedDB so it survives a reload.
const keyPair = await WebCryptoP256.createKeyPair()

const deviceKey = Account.fromWebCryptoP256(keyPair, { access: account })
const keyAuthorization = await client.accessKey.signAuthorization({
  accessKey: deviceKey,
  account, // approved by the customer's passkey
  expiry: Expiry.days(30),
  limits: [{ token: alphaUsd, limit: parseUnits('500', 6), period: 86_400 }],
})

await client.token.transferSync({
  account: deviceKey,
  amount: parseUnits('5', 6),
  keyAuthorization, // first payment only
  to: recipient,
  token: alphaUsd,
})
```

## Device key limits

- Each device needs its own key, authorized by the customer's passkey.
- Clearing site data deletes a browser key. Authorize a new one the same way.
- If a device is lost, [revoke its key](/docs/accounts/access-keys/revocation#revoke-an-access-key). The account's signers don't change.
