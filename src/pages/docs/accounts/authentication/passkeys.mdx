# Passkeys

A passkey lets only the customer approve the account's transactions, with Face ID, a fingerprint, or a security key.

<span id="what-a-passkey-is" />

## Overview

A passkey is the WebAuthn credential behind passwordless sign-in. It's a P-256 key that stays on the customer's device or security key and signs only when the customer approves. Tempo checks each passkey signature onchain. For payments without a prompt, add a [device key](/docs/accounts/authentication/device-keys). On a server, use a [private key](/docs/accounts/authentication/private-keys) instead.

<span id="passkey-authenticators" />
<span id="how-it-works" />

## Supported Authenticators

Passkeys work with Face ID and Touch ID, Windows Hello, an Android screen lock, and security keys such as YubiKey.

<span id="what-a-passkey-trusts" />

Your servers and wallet providers never hold the passkey. Its security rests on the customer's device. A synced passkey also rests on the service that syncs it: iCloud Keychain, Google Password Manager, or a password manager.

## Create a Passkey

<PasskeyAccountDemo />

The demo creates a passkey and shows the single-key account it signs for. On mainnet and testnet today, a passkey can be a single-key account's one key. Losing it loses the account.

<ConfigurableAccountsT14 />

On the Tempo Accounts devnet, make the passkey the first signer of a configurable account instead. It approves alone.

```ts [passkey.ts]
import { Account, WebAuthnP256 } from 'viem/tempo'

const credential = await WebAuthnP256.createCredential({ label: 'Acme' }) // [!code hl]
const passkey = Account.fromWebAuthnP256(credential) // [!code hl]
const account = Account.fromConfig({ address: 'infer', owners: [passkey] }) // [!code hl]
```

`account.address` receives stablecoins right away. The account's first transaction registers it onchain. Next, [add a recovery signer](/docs/accounts/apps/self-custodial-wallets) so a lost passkey doesn't lock the customer out. [Recommended signer setups](/docs/accounts/policies/signing-thresholds#recommended-signer-setups) gives the weights for customer accounts and treasuries.

<span id="passkey-limits" />

## Limits

- A passkey works only on its domain, the relying party ID (`rpId`), and that domain's subdomains. Pick the `rpId`, such as `acme.com`, before customers create passkeys. Pass it to both `WebAuthnP256.createCredential` and `Account.fromWebAuthnP256`.
- WebAuthn returns the public key only at creation. Save `credential.id` and `credential.publicKey`. Pass them to `Account.fromWebAuthnP256` when the customer returns.
- Passkeys work only over HTTPS or on `localhost`. A cancelled or timed-out prompt fails with `NotAllowedError`.
- A passkey on a security key isn't synced, so losing the key loses the signer.
- On mainnet and testnet, a passkey account is a single-key account and can't add a signer or swap its key. A synced passkey survives a lost phone only through its sync provider, such as iCloud Keychain or Google Password Manager. If the customer loses every synced copy, they lose the account and its funds.
