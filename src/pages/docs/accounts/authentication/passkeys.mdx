# Passkeys

A passkey is the signer only the customer holds, so it keeps the account in their control. Give it enough weight to approve alone, and add a second signer so a lost passkey doesn't lock the customer out.

## What a passkey is

A passkey is a WebAuthn P-256 key that the customer approves with their face, fingerprint, PIN, or security key. The private key never leaves the customer's authenticator, and Tempo checks each WebAuthn signature on chain.

## Passkey authenticators

| Authenticator | How the customer approves |
| --- | --- |
| Apple devices | Face ID or Touch ID |
| Windows | Windows Hello face, fingerprint, or PIN |
| Android | The device's fingerprint, face, or screen lock |
| Security keys | A touch on a key such as YubiKey |

Synced passkeys follow the customer to new devices through iCloud Keychain, Google Password Manager, or a password manager. A security key's passkey stays on that key.

## What a passkey trusts

A passkey trusts the customer's device and, for a synced passkey, their passkey provider. No app server or wallet provider is involved, so no one but the customer can approve with it. Use it for customer approvals, signer changes, and recovery of other signers.

## Create a passkey signer

<PasskeyAccountDemo />

The demo creates a passkey on Moderato testnet and shows its account address.

```ts [passkey.ts]
import { Account, WebAuthnP256 } from 'viem/tempo'

const passkey = Account.fromWebAuthnP256(await WebAuthnP256.createCredential({ label: 'Acme' }))
const account = Account.fromConfig({ address: 'infer', owners: [passkey] })
```

`account.address` receives stablecoins right away. The first transaction registers the account.

For weights alongside backup and recovery keys, see [Recommended signer setups](/docs/accounts/policies/signing-thresholds#recommended-signer-setups). To add a passkey to an existing account or back it up with other keys, see [Add a recovery signer](/docs/accounts/guides/users/add-a-recovery-signer).

## Passkey limits

- A passkey works only on the domain it was created for, its relying party ID. Set `rpId` in `WebAuthnP256.createCredential` to choose it before customers create passkeys.
- The prompt fails with `NotAllowedError` when the customer cancels or the page isn't served over HTTPS.
- A passkey on a security key isn't synced. Losing the key loses the signer, so add a second signer for [recovery](/docs/accounts/guides/users/recover-an-account).

For other methods, see [Signing methods](/docs/accounts/authentication).
