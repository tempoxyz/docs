# Passkeys

A passkey lets only the customer approve payments and signer changes, with Face ID, a fingerprint, or a security key.

A passkey is one of three signing methods for a Tempo account, with [private keys](/docs/accounts/authentication/private-keys) and [device keys](/docs/accounts/authentication/device-keys). On mainnet and testnet today, a passkey can be a single-key account's one key, but losing it loses the account. On the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), the only network that runs configurable accounts, make a customer's passkey a signer that approves alone, and add a second signer so a lost passkey doesn't lock the customer out. Treasuries use [different weights](/docs/accounts/policies/signing-thresholds#recommended-signer-setups).

<span id="passkey-authenticators" />

## What a passkey is

A passkey is the WebAuthn credential behind passwordless sign-in: a P-256 key that stays on the customer's device or security key and signs only when the customer approves. It works with Face ID and Touch ID, Windows Hello, an Android screen lock, and security keys such as YubiKey. Tempo checks each passkey signature onchain.

<span id="what-a-passkey-trusts" />

Your servers and wallet providers never hold the passkey. Its security rests on the customer's device and, for a synced passkey, the service that syncs it across their devices: iCloud Keychain, Google Password Manager, or a password manager.

## Create a passkey signer

<PasskeyAccountDemo />

The demo creates a passkey and shows the single-key account it signs for. On the Tempo Accounts devnet, make the passkey a configurable account's first signer instead:

```ts [passkey.ts]
import { Account, WebAuthnP256 } from 'viem/tempo'

const credential = await WebAuthnP256.createCredential({ label: 'Acme' }) // [!code hl]
const passkey = Account.fromWebAuthnP256(credential) // [!code hl]
const account = Account.fromConfig({ address: 'infer', owners: [passkey] }) // [!code hl]
```

`account.address` receives stablecoins right away, and the account's first transaction registers it onchain. On the devnet, next [add a recovery signer](/docs/accounts/guides/users/add-a-recovery-signer) with the weights in [Recommended signer setups](/docs/accounts/policies/signing-thresholds#recommended-signer-setups). On mainnet and testnet, a single-key passkey account can't add a signer or swap its key ([Passkey limits](#passkey-limits)).

## Passkey limits

- A passkey works only on its domain, the relying party ID (`rpId`), and that domain's subdomains. Pick the `rpId`, such as `acme.com`, before customers create passkeys, and pass it to both `WebAuthnP256.createCredential` and `Account.fromWebAuthnP256`.
- WebAuthn returns the public key only at creation. Save `credential.id` and `credential.publicKey`, and pass them to `Account.fromWebAuthnP256` when the customer returns.
- Passkeys work only over HTTPS or on `localhost`. A cancelled or timed-out prompt fails with `NotAllowedError`.
- A passkey on a security key isn't synced, so losing the key loses the signer.
- On mainnet and testnet, a passkey account is a single-key account and can't swap its key. A synced passkey survives a lost phone only through its sync provider, such as iCloud Keychain or Google Password Manager. If the customer loses every synced copy, they lose the account and its funds.
