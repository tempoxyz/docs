# Delegation

Access keys let a device, a backend service, or an AI agent pay from an account on its own, within limits Tempo enforces on every transaction.

## Authorize an access key

The account's signers approve a key's limits once, and the key then pays alone until it expires or is revoked.

<AccessKeyDemo />

The demo authorizes a key on Moderato testnet, pays with it, shows Tempo rejecting an overspend, then revokes it.

| Control | Example |
| --- | --- |
| **Spending limit** per stablecoin, one-time or renewing | 500 USD a day |
| **Expiry** | 30 days |
| **Allowed calls**: contracts, functions, and recipients | Payments to approved recipients only |

<span id="authorize-a-limited-key" />

In this example, a 2-of-3 treasury gives a payout key 10 AlphaUSD for one hour, payable to one recipient:

```ts [access-keys.ts]
import { parseUnits } from 'viem'
import { tempoModerato } from 'viem/chains'
import { Account, createClient, Expiry, P256 } from 'viem/tempo'

const env = (name: string) => process.env[name] as `0x${string}`
const alphaUsd = '0x20c0000000000000000000000000000000000001'
const recipient = env('TEMPO_RECIPIENT')
const client = createClient({ chain: tempoModerato })

const account = Account.fromConfig({
  address: 'infer',
  owners: [
    Account.fromSecp256k1(env('FINANCE_SIGNER_KEY')),
    Account.fromSecp256k1(env('OPERATIONS_SIGNER_KEY')),
    env('CONTROLLER_PASSKEY_ADDRESS'),
  ],
  threshold: 2,
})

const accessKey = Account.fromP256(P256.randomPrivateKey(), { access: account })
const keyAuthorization = await client.accessKey.signAuthorization({
  accessKey,
  account,
  expiry: Expiry.hours(1),
  limits: [{ token: alphaUsd, limit: parseUnits('10', 6), period: 0 }],
  scopes: [{ address: alphaUsd, recipients: [recipient], selector: 'transfer(address,uint256)' }],
})

await client.token.transferSync({
  account: accessKey,
  amount: parseUnits('2', 6),
  keyAuthorization, // first payment only
  to: recipient,
  token: alphaUsd,
})
```

<span id="read-the-remaining-permission" />

Read what's left with `client.accessKey.getRemainingLimit({ account, accessKey, token: alphaUsd })`.

Build it with viem: [Authorize access keys](https://viem.sh/tempo/guides/access-keys/authorize) and [Set permissions and limits](https://viem.sh/tempo/guides/access-keys/permissions), for each control and its options.

## Scope an access key

Scopes list the contracts, functions, and recipients a key can call. Spending limits cover only direct payments and token approvals, so scope every backend, agent, and card key to the calls its task uses.

| Task | Scope |
| --- | --- |
| Payments to approved recipients | `transfer(address,uint256)` on the stablecoin, with `recipients` |
| Payments with a reference | `transferWithMemo(address,uint256,bytes32)` on the stablecoin |
| Earn deposits | `approve(address,uint256)` on the stablecoin and `deposit(uint256,address,uint256)` on the vault |

Signers can change a live key's allowed calls with `setAllowedCalls`, or its limit with `updateSpendingLimit`, which resets what's left, without revoking it.

## Revoke an access key

```ts [revoke.ts]
await client.accessKey.revokeSync({ accessKey: accessKeyAddress, account })
```

The account's signers approve the revocation. A revoked key can't pay and can't be authorized again. Save each key's address with a device or service name when you authorize it, so you can match a lost device or a leaked backend key to its key.

## Access key limits

- Authorizing a key costs about $0.003, whatever the limits. The authorization travels with the key's first payment.
- Access keys can't authorize other keys, change signers, or count toward the threshold.
- Changing signers doesn't revoke access keys. Revoked keys can't return.
- Spending limits cover direct payments and token approvals. Pair them with allowed recipients or functions.
- An account's payments share one sequential nonce by default, so they land in order. Send concurrent payments with expiring nonces or separate nonce keys. See [Parallel payments](/docs/guide/payments/send-parallel-transactions).
- Access keys can't spend while the account has [approval escalation](/docs/accounts/security-policies#approval-escalation-for-larger-payments) on.
- To cancel a signed authorization before it lands, bind a witness to it and burn the witness. See [Witnesses](https://viem.sh/tempo/guides/access-keys/witnesses).
- To check that a signature came from an active access key of an account, see [Verify signatures](https://viem.sh/tempo/guides/access-keys/verify).
