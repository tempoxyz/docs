# Expiry

An expiry is the Unix timestamp at which an access key stops working, and Tempo rejects every transaction the key signs from that second on. Set it to how long the holder needs the key, and authorize a replacement before it passes, because an existing key's expiry can't be extended.

<span id="access-key-expiry" />

## How expiry works

Tempo checks the expiry when it validates each transaction the key signs. Once the current block time reaches the expiry, the transaction fails with `KeyExpired` and never executes. An expired key also reads as zero remaining limit and denies every call.

A key with no `expiry` never expires. Admin keys have no expiry.

## Set an expiry

Pass `expiry` when you [authorize the key](/docs/accounts/access-keys#authorize-an-access-key). viem's `Expiry` helpers return a timestamp relative to now, such as `Expiry.hours(1)`, `Expiry.days(30)`, or `Expiry.months(3)`:

```ts [expiry.ts]
const keyAuthorization = await client.accessKey.signAuthorization({
  accessKey,
  account,
  expiry: Expiry.days(30),
  limits: [{ token: alphaUsd, limit: parseUnits('500', 6), period: 86_400 }],
})
```

Match the expiry to the holder: hours for a one-off task, 30 days for a device, 90 days for a backend. Read it back with `client.accessKey.getMetadata({ account, accessKey })`, which returns `expiry`.

## Renew an expiring key

There's no call to extend an expiry. To keep a holder paying:

1. Generate a new key where the holder signs.
2. Have the signers, or an admin key, authorize it with a new expiry.
3. Switch the holder to the new key.
4. [Revoke](/docs/accounts/access-keys/revocation) the old key if it hasn't expired yet.

Schedule renewal before the expiry, since the signers have to approve it. For walkthroughs, see [Automate a backend](/docs/accounts/guides/automate-backend) and [Set up a spending account](/docs/accounts/guides/spending-account).

## Expiry limits

- A new authorization needs an expiry in the future. A past expiry reverts with `ExpiryInPast`, and `0` counts as past.
- An expired key's spending limit can't be changed. `updateLimit` reverts with `KeyExpired`.
- Expiry is checked against block time, not your server's clock.
