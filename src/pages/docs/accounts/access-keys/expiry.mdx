# Expiry

An expiry makes an access key stop working at a set time, so a forgotten or leaked key ends on its own.

Expiry is one of an [access key](/docs/accounts/access-keys)'s three bounds, with [spending limits](/docs/accounts/access-keys/spending-limits) and [scopes](/docs/accounts/access-keys/scopes). You set it as a timestamp when you authorize the key, and once block time reaches it, Tempo rejects every transaction the key signs. Choose the shortest window the key's holder needs.

## How expiry works

Tempo checks the expiry against block time (the current block's timestamp), not your server's clock. Once block time reaches the expiry, Tempo rejects every transaction the key signs with [`KeyExpired`](/docs/protocol/transactions/AccountKeychain#error-keyexpired). The expired key's remaining limit reads as zero, and changing it with `updateLimit` reverts with [`KeyExpired`](/docs/protocol/transactions/AccountKeychain#error-keyexpired).

## Set an expiry

Pass `expiry`, a Unix timestamp in seconds, when you [authorize the key](/docs/accounts/access-keys#authorize-an-access-key). A key without `expiry` never expires, and admin keys can't have one. The `Expiry` helpers in `viem/tempo` return a timestamp relative to now, such as `Expiry.days(30)` or `Expiry.hours(1)`. See viem's [`accessKey.authorize`](https://viem.sh/tempo/actions/accessKey.authorize).


Use the shortest window the holder needs: hours for a one-off task, 30 days for a device, 90 days for a backend. An expiry at or before the current block time reverts with [`ExpiryInPast`](/docs/protocol/transactions/AccountKeychain#error-expiryinpast).

## Renew an expiring key

You can't extend an expiry, so replace the key before it passes. To renew, authorize a new key: Tempo never authorizes the same key address twice for an account. Read the old key's `expiry` with `client.accessKey.getMetadata({ account, accessKey })`, and before that time:

1. Generate a new key where the holder signs.
2. Have the signers, or an admin key, authorize it with a new expiry.
3. Switch the holder to the new key.
4. [Revoke](/docs/accounts/access-keys/revocation) the old key if it hasn't expired yet.

Specification: [Account Keychain key expiry](/docs/protocol/transactions/AccountKeychain#key-expiry).
