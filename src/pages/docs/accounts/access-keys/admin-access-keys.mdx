# Admin access keys

An admin access key manages an account's other access keys, so a customer's trusted device can add their new phone, or your key-management service can rotate keys, without the signers approving each change. It has no spending limit, expiry, or scopes, so whoever holds it can spend the whole balance.

## What an admin access key can do

An admin key can:

- Authorize any access key, including another admin key.
- Change a limited key's [spending limit](/docs/accounts/access-keys/spending-limits) or [scopes](/docs/accounts/access-keys/scopes).
- [Revoke](/docs/accounts/access-keys/revocation) any access key, including itself.
- Approve a message that a contract checks with [`verifyKeychainAdmin`](/docs/sdk/foundry/signature-verifier#how-signature-verification-works-in-foundry).

It doesn't count toward the signing threshold, so it can't change the signers or the threshold, or lock the signers out. A key-management call from a limited key reverts with `UnauthorizedCaller`.

## When to use an admin key

Give an admin key only to a party you'd trust with the whole balance. Everyone else, including an [AI agent](/docs/accounts/guides/agents/give-an-agent-a-wallet), a [backend that pays out](/docs/accounts/guides/automations/pay-out-from-a-backend), or a [card program](/docs/accounts/guides/automations/fund-a-card-program), gets a limited key.

Store an admin key as carefully as a signer: in a KMS or HSM, or as a [device key](/docs/accounts/authentication/device-keys) that can't be exported. A leaked admin key compromises the account, because its holder can authorize a new admin key before you revoke the leaked one.

## Authorize an admin key

Enough signers to reach the threshold, or an existing admin key, authorize it like any [access key](/docs/accounts/access-keys#authorize-an-access-key), with `admin: true`. viem ignores `limits`, `expiry`, and `scopes` on an admin key, and Tempo rejects an admin authorization that carries any of them. `client.ts` connects to the Tempo Accounts devnet ([set up the devnet key](/docs/accounts/create#connect-to-the-devnet)). `access-keys.ts` is the example in [Authorize an access key](/docs/accounts/access-keys#authorize-an-access-key).

```ts [client.ts]
// [!include ~/snippets/accounts-devnet.ts:client]
```

```ts [admin-key.ts]
import { account } from './access-keys'
import { client } from './client'

const kmsKeyAddress = process.env.KMS_KEY_ADDRESS as `0x${string}`

await client.accessKey.authorizeSync({
  account,
  accessKey: { address: kmsKeyAddress, type: 'secp256k1' },
  admin: true,
})

// true until the key is revoked
const isAdmin = await client.accessKey.isAdmin({ account, accessKey: kmsKeyAddress })
```

## Admin access key limits

- Changing an admin key's spending limit or scopes reverts with `InvalidKeyId`, because it has neither. To bound its holder, revoke it and authorize a new limited key.
- Revoking an admin key leaves the keys it authorized in place, so revoke each one separately.
