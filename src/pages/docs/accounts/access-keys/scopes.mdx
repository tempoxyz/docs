# Scopes

Scopes list the calls an access key can make, as contracts, functions, and recipients, and Tempo reverts any other call the key signs. Scope every backend, agent, and card key: a [spending limit](/docs/accounts/access-keys/spending-limits) caps the amount, but only scopes control where it goes.

<span id="scopes" />

## What a scope restricts

Each scope names a target contract and, optionally, one function on it and the recipients that function can pay:

| Field | Effect |
| --- | --- |
| `address` | The contract the key can call |
| `selector` | The function, as a signature such as `transfer(address,uint256)` or a 4-byte selector. Omit it to allow any function on the target. |
| `recipients` | The addresses the function can pay. Applies to `transfer`, `transferWithMemo`, and `approve`. |

Tempo checks every top-level call the key signs against its scopes and reverts a call that matches none with `CallNotAllowed`. A key with no `scopes` can call anything, and an empty list denies every call.

<span id="scope-an-access-key" />

## Scope an access key

Pass `scopes` when you [authorize the key](/docs/accounts/access-keys#authorize-an-access-key):

| Task | Scope |
| --- | --- |
| Payments to approved recipients | `transfer(address,uint256)` on the stablecoin, with `recipients` |
| Payments with a reference | `transferWithMemo(address,uint256,bytes32)` on the stablecoin |
| Earn deposits | `approve(address,uint256)` on the stablecoin and `deposit(uint256,address,uint256)` on the vault |

```ts [scopes.ts]
scopes: [
  { address: alphaUsd, recipients: [recipient], selector: 'transfer(address,uint256)' },
],
```

For scopes sized to a task, see [Pay out from a backend](/docs/accounts/guides/automations/pay-out-from-a-backend) and [Give an agent a wallet](/docs/accounts/guides/agents/give-an-agent-a-wallet).

## Change allowed calls

Signers that reach the threshold, or an [admin key](/docs/accounts/access-keys/admin-access-keys), change a live key's scopes on the [Account Keychain](/docs/protocol/transactions/AccountKeychain) without revoking it. `setAllowedCalls` creates or replaces the scope for each target you pass, and `removeAllowedCalls` removes one target:

```ts [set-allowed-calls.ts]
import { toFunctionSelector } from 'viem'
import { Abis, Addresses } from 'viem/tempo'

const newRecipient = env('TEMPO_NEW_RECIPIENT')

await client.writeContractSync({
  account,
  abi: Abis.accountKeychain,
  address: Addresses.accountKeychain,
  functionName: 'setAllowedCalls',
  args: [
    accessKey.accessKeyAddress,
    [{
      target: alphaUsd,
      selectorRules: [{ selector: toFunctionSelector('transfer(address,uint256)'), recipients: [recipient, newRecipient] }],
    }],
  ],
})
```

An empty `selectorRules` list allows any function on the target. Read the current scopes with `getAllowedCalls(account, keyId)`, which returns `isScoped` and the scope list.

## Scope limits

- Scopes check top-level calls only. A contract the key may call can make any internal calls, so allow only contracts you trust.
- An access key can't create a contract at the top level. A factory the scopes allow still can.
- `recipients` constrains only `transfer`, `transferWithMemo`, and `approve`.
- `setAllowedCalls` rejects an empty batch, a zero target, and duplicate targets, selectors, or recipients with `InvalidCallScope`.
- Admin keys have no scopes. `setAllowedCalls` and `removeAllowedCalls` on one revert with `InvalidKeyId`.
- A missing, revoked, or expired key reads as scoped with no allowed calls.

Specification: [Account Keychain call scopes](/docs/protocol/transactions/AccountKeychain#call-scope-enforcement).
