# Revocation

Revoking an access key shuts it off for good: once the revocation lands, Tempo rejects every transaction the key signs.

Revocation ends an [access key](/docs/accounts/access-keys) on demand, without waiting for its [expiry](/docs/accounts/access-keys/expiry). Revoke a key as soon as its device is lost, its secret leaks, or its holder no longer needs it.

<span id="key-revocation-by-situation" />

## Revoke an access key

Enough of the account's signers to meet its threshold, or an [admin key](/docs/accounts/access-keys/admin-access-keys), approve the revocation. A limited access key can't revoke any key, including itself.

In Viem, call [`accessKey.revoke`](https://viem.sh/tempo/actions/accessKey.revoke) with the account and the key's address.

When you authorize a key, save its address next to the device or service that holds it, so you know which address to revoke. Show a key as removed only after the revocation confirms.

## What revocation leaves in place

Revocation doesn't undo what the key did while it was active:

- Its transactions stay final. A payment racing the revocation goes through only if it lands first; once the revocation lands, Tempo rejects the rest.
- Its token approvals stay. A spender it approved can still pull tokens up to the allowance, so set each allowance to zero from the account.
- If it was an admin key, the keys it authorized stay authorized. Revoke each one.

## Revoke when signers change

Changing a configurable account's signers, which works only on the Tempo Accounts devnet, doesn't touch its access keys, so revoke them yourself: after a recovery, and before a hand-off.

After you [replace a lost or compromised signer](/docs/accounts/key-management/remove-signers#remove-a-lost-or-compromised-signer), revoke every key that signer's holder could use, including any an attacker authorized. You won't have those addresses saved, so list every key the account has authorized from its `KeyAuthorized` events. The devnet RPC searches at most 100,000 blocks per request, so read the events in pages:

```ts [find-keys.ts]
import { Abis, Addresses } from 'viem/tempo'
import { account } from './access-keys'
import { client } from './client'

const latestBlock = await client.getBlockNumber()
const pageSize = 100_000n

const events = []
// Start from 0, or from the block of the account's first transaction if you saved it
for (let fromBlock = 0n; fromBlock <= latestBlock; fromBlock += pageSize) {
  const toBlock = fromBlock + pageSize - 1n
  const page = await client.getContractEvents({ // [!code hl]
    abi: Abis.accountKeychain,
    address: Addresses.accountKeychain,
    args: { account: account.address },
    eventName: 'KeyAuthorized', // [!code hl]
    fromBlock,
    toBlock: toBlock < latestBlock ? toBlock : latestBlock,
    strict: true,
  })
  events.push(...page)
}

const keys = await Promise.all(
  events.map(({ args }) => client.accessKey.getMetadata({ account, accessKey: args.publicKey })),
)
// compare with the keys you saved
const unrevoked = keys.filter((key) => !key.isRevoked) // [!code hl]
```

Before you [hand an account to a customer](/docs/accounts/guides/users/hand-off), revoke your app's access keys, then swap out your app's signers. Once your signers are gone, your app can't approve anything, including a revocation.

## Revocation limits

- A revoked key's address can never be authorized again for this account. To restore access, authorize a new key.
- Revoking a key the account hasn't authorized reverts with [`KeyNotFound`](/docs/protocol/transactions/AccountKeychain#error-keynotfound). That includes a key whose authorization hasn't landed yet. If you bound a [witness](https://viem.sh/tempo/guides/access-keys/witnesses), a 32-byte value signed into the authorization, cancel it with `client.accessKey.burnWitnessSync({ account, witness })`. Tempo then rejects any authorization signed with that witness.
- An expired key needs no revocation: Tempo already rejects its transactions.

Specification: [Account Keychain key revocation](/docs/protocol/transactions/AccountKeychain#key-revocation).
