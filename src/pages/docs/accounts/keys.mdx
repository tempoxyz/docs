# Account model

Every Tempo EVM account is either a single-key account or a configurable account, and they differ in who approves transactions.

A single-key account is approved by one key, as on Ethereum. A configurable account is approved by weighted owners (the Accounts guides call them signers): a transaction runs once the approving owners' weights reach the account's threshold. Either type can also authorize access keys, which sign alone within limits. [How it works](/docs/accounts/how-it-works) walks through an example.

## Single-key and configurable accounts

| | [Single-key account](/docs/development/single-key-accounts) | [Configurable account](/docs/development/configurable-accounts) |
| --- | --- | --- |
| Approved by | Its one key, the root key | Owners whose weights reach the threshold |
| Address comes from | One public key: secp256k1, P-256, or WebAuthn (passkey) | The first configuration of owners, weights, threshold, and salt, or the original key if upgraded |
| Changing keys | A new key means a new address. [Upgrade to a configurable account](/docs/development/single-key-accounts#upgrade-to-a-configurable-account) to change keys and keep the address. | `updateConfig` replaces the owners and threshold. The address stays. |
| Running contract code (EIP-7702 delegation) | Allowed, but a delegated account can't upgrade | Not allowed |

Single-key accounts work on mainnet, testnet, and the Tempo Accounts devnet. Configurable accounts ([TIP-1107](https://tips.sh/1107)) and the upgrade ([TIP-1113](https://tips.sh/1113)) are draft specifications and run only on the devnet, not on mainnet or testnet. To create one there, follow [Create an account](/docs/accounts/create).

## Access keys for both account types

An access key is an extra key that signs for the account on its own, within the limits you set: a spending limit per TIP-20 token that can reset each period, an optional expiry, and scopes that restrict which contracts it calls and whom it pays. The [Account Keychain](/docs/development/account-keychain), a contract built into Tempo (a precompile), stores every account's access keys and enforces those limits on each transaction they sign.

The account itself authorizes and revokes access keys: its root key, or owners whose weights reach the threshold. An [admin access key](/docs/development/account-keychain#admin-access-keys) can too. It has no limits, so store it as carefully as a root or owner key. Access keys, admin or not, never count toward a threshold. To set one up, follow [Access keys](/docs/accounts/access-keys).

## Tempo transaction signature types

| Signature | Prefix | Used by |
| --- | --- | --- |
| secp256k1 | None (65 bytes) | A root key, owner, access key, or fee payer |
| P-256 | `0x01` | A root key, owner, or access key |
| WebAuthn | `0x02` | A root key, owner, or access key |
| Keychain | `0x04` | An access key, wrapping its own signature with the account's address |
| Multisig | `0x05` | A configurable account's owners, bundling their signatures with the account's configuration |

Viem's `Account` helpers encode every format. Byte layouts are in the [transaction specification](/docs/protocol/transactions/spec-tempo-transaction#signature-types) and, for `0x05`, [TIP-1114](https://tips.sh/1114).
