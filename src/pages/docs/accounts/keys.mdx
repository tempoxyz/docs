# Account Model

Every Tempo EVM account is either a single-key account or a configurable account.

## Overview

The two account types differ in who approves transactions. One key approves a single-key account's transactions, as on Ethereum. Weighted owners approve a configurable account's transactions. The Accounts guides call them signers. A transaction runs once the approving owners' weights reach the account's threshold. Either type can also authorize access keys, which sign alone within limits.

## Single-Key and Configurable Accounts

| | [Single-key account](/docs/development/single-key-accounts) | [Configurable account](/docs/development/configurable-accounts) |
| --- | --- | --- |
| Approved by | Its one key, the root key | Owners whose weights reach the threshold |
| Address comes from | One public key: secp256k1, P-256, or WebAuthn (passkey) | The first configuration of owners, weights, threshold, and salt, or the original key if upgraded |
| Changing keys | A new key means a new address. [Upgrade to a configurable account](/docs/development/single-key-accounts#upgrade-to-a-configurable-account) to change keys and keep the address. | `updateConfig` replaces the owners and threshold. The address stays. |
| Running contract code (EIP-7702 delegation) | Allowed, but a delegated account can't upgrade | Not allowed |

## Access Keys for Both Account Types

An [access key](/docs/accounts/access-keys) is an extra key that signs for the account on its own, within the limits you set:

- **Spending Limits:** A limit per TIP-20 token, which can reset each period.
- **Expiry:** An optional time after which the key stops working.
- **Scopes:** Restrictions on which contracts it calls and whom it pays.

The [Account Keychain](/docs/development/account-keychain), a contract built into Tempo (a precompile), stores every account's access keys. It enforces those limits on each transaction they sign.

The account itself authorizes and revokes access keys, through its root key or owners whose weights reach the threshold. An [admin access key](/docs/development/account-keychain#admin-access-keys) can too. It has no limits, so store it as carefully as a root or owner key. Access keys, admin or not, never count toward a threshold.

## Tempo Transaction Signature Types

| Signature | Prefix | Used by |
| --- | --- | --- |
| secp256k1 | None (65 bytes) | A root key, owner, access key, or fee payer |
| P-256 | `0x01` | A root key, owner, or access key |
| WebAuthn | `0x02` | A root key, owner, or access key |
| Keychain | `0x04` | An access key, wrapping its own signature with the account's address |
| Multisig | `0x05` | A configurable account's owners, bundling their signatures with the [account's configuration](/docs/development/configurable-accounts#multisig-signature-format) |

Viem's `Account` helpers encode every [format](/docs/protocol/transactions/spec-tempo-transaction#signature-types).

## Logins and API Keys

Only these keys sign transactions. Your app's login session controls access to your app. A Tempo API key authenticates requests to Tempo's hosted APIs. Neither signs for an account.
