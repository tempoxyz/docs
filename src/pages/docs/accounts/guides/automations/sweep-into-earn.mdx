# Sweep idle balances into Earn

A nightly job on your backend deposits a customer's idle stablecoins into an [Earn](/docs/earn) vault, signing with an access key the customer authorizes once. The key can deposit into that one vault, up to a daily limit, and nothing else: it can't send funds elsewhere or withdraw them.

A deposit takes two calls: `approve` lets the vault pull funds from the account, and `deposit` pulls them and issues vault shares in return. The key gets exactly those two calls. The examples run on Moderato testnet, whose stablecoins have no value, with pathUSD and a pathUSD vault from [Vaults](/docs/earn/vaults). Before you enable sweeps, run the vault checks in [Deposit](/docs/earn/integrate).

:::::steps

### Scope a key to the vault

Create a secp256k1 key in your KMS, as in [Keep the key in your KMS](/docs/accounts/guides/automations/pay-out-from-a-backend#keep-the-key-in-your-kms), then have the customer's signers authorize it from your app:

```ts [app/approve-sweeps.ts]
import { parseUnits } from 'viem'
import { Expiry } from 'viem/tempo'

const pathUsd = '0x20c0000000000000000000000000000000000000'

await client.accessKey.authorizeSync({
  accessKey: { accessKeyAddress: sweepKeyAddress, keyType: 'secp256k1' },
  account, // the customer's account, signed by its signers
  expiry: Expiry.days(90),
  limits: [{ token: pathUsd, limit: parseUnits('5000', 6), period: 86_400 }], // 5,000 pathUSD a day
  scopes: [
    { address: pathUsd, selector: 'approve(address,uint256)', recipients: [vault] },
    { address: vault, selector: 'deposit(uint256,address,uint256)' },
  ],
})
```

Show the customer the vault, the daily limit, and the expiry before they approve. The [scopes](/docs/accounts/access-keys/scopes) allow only these two calls, and the [spending limit](/docs/accounts/access-keys/spending-limits) counts approvals, so the vault can't pull more than 5,000 pathUSD a day. Fees the account pays count too, so leave headroom above your largest sweep.

### Sweep on a schedule

Each night, keep an operating float for the next day's payments and deposit the rest:

```ts [backend/sweep.ts]
import { tempoModerato } from 'viem/chains'
import { Actions, createClient, EarnShares } from 'viem/tempo'

const backend = createClient({ account: sweepKey, chain: tempoModerato, feeToken: pathUsd })

const balance = await backend.token.getBalance({ account: address, token: pathUsd })
const assetAmount = balance.amount - operatingFloat
if (assetAmount > 0n) {
  await backend.token.approveSync({ amount: assetAmount, spender: vault, token: pathUsd })
  const { result: quotedShares } = await Actions.earn.deposit.simulate(backend, {
    assetAmount,
    shareAmountMin: 1n,
    vault,
  })
  const { receipt, shareAmount } = await backend.earn.depositSync({
    assetAmount,
    shareAmountMin: EarnShares.minimumOutput(quotedShares, 50), // accept at most 0.5% fewer shares
    vault,
  })
  // record receipt.transactionHash and shareAmount for reconciliation
}
```

Approve first: the simulation that quotes the shares needs the approval in place. Tempo rejects any transaction that exceeds what's left of today's limit, calls outside the two scopes, or arrives after the expiry.

### Track the position

```ts [backend/position.ts]
const { shareBalance, value } = await backend.earn.getPosition({ account: address, vault })
const { remaining } = await backend.accessKey.getRemainingLimit({ account: address, accessKey: sweepKey, token: pathUsd })
```

Show the customer `value`, not `shareBalance`: shares don't map one-to-one to pathUSD, and `value` is what they're worth now, after fees, in pathUSD base units. `remaining` is what the key can still spend today. To show earnings over time, see [Balances and earnings](/docs/earn/balances). To withdraw, use the customer's signers or a separate key, as in [Withdraw](/docs/earn/withdraw).
