# Sweep idle balances into Earn

A nightly job on your backend deposits a customer's idle stablecoins into an [Earn](/docs/earn) vault, signing with an access key the customer authorizes once. The key can deposit into that one vault, up to a daily limit, and nothing else: it can't send funds elsewhere or withdraw them.

A deposit takes two calls: `approve` lets the vault pull funds from the account, and `deposit` pulls them and issues vault shares in return. The key gets exactly those two calls. Before you enable sweeps, run the vault checks in [Deposit](/docs/earn/integrate).

Earn vaults aren't on the Tempo Accounts devnet, so this page runs on Moderato testnet, whose stablecoins have no value and whose RPC needs no key. It uses pathUSD, a pathUSD vault from [Vaults](/docs/earn/vaults), and a single-key account as `account`, since Moderato doesn't run configurable accounts.

```ts [client.ts]
import { http } from 'viem'
import { tempoModerato } from 'viem/chains'
import { createClient } from 'viem/tempo'

export const client = createClient({ chain: tempoModerato, transport: http() }) // [!code hl]
```

### Scope a key to the vault

Create a secp256k1 key in your KMS, as in [Keep the key in your KMS](/docs/accounts/guides/automations/pay-out-from-a-backend#keep-the-key-in-your-kms), then have the customer authorize it from your app with their account's key:

```ts [app/approve-sweeps.ts]
import { parseUnits } from 'viem'
import { Expiry } from 'viem/tempo'
import { client } from '../client'

const pathUsd = '0x20c0000000000000000000000000000000000000'

await client.accessKey.authorizeSync({
  accessKey: { accessKeyAddress: sweepKeyAddress, keyType: 'secp256k1' },
  account, // the customer's account, signed by its key
  expiry: Expiry.days(90),
  // 5,000 pathUSD a day
  limits: [{ token: pathUsd, limit: parseUnits('5000', 6), period: 86_400 }], // [!code hl]
  scopes: [ // [!code hl]
    { address: pathUsd, selector: 'approve(address,uint256)', recipients: [vault] }, // [!code hl]
    { address: vault, selector: 'deposit(uint256,address,uint256)' }, // [!code hl]
  ], // [!code hl]
})
```

Show the customer the vault, the daily limit, and the expiry before they approve. The [scopes](/docs/accounts/access-keys/scopes) allow only these two calls, and the [spending limit](/docs/accounts/access-keys/spending-limits) counts approvals, so the vault can't pull more than 5,000 pathUSD a day. Fees the account pays count too, so leave headroom above your largest sweep.

### Sweep on a schedule

Each night, keep an operating float for the next day's payments and deposit the rest. Only the two writes pass `account: sweepKey`. Read with `client` alone: Tempo checks a read made as the key against the key's scopes too, so reading the balance as the key fails.

```ts [backend/sweep.ts]
import { Actions, EarnShares } from 'viem/tempo'
import { client } from '../client'

const pathUsd = '0x20c0000000000000000000000000000000000000'

const balance = await client.token.getBalance({ account: address, token: pathUsd })
const assetAmount = balance.amount - operatingFloat // [!code hl]
if (assetAmount > 0n) {
  await client.token.approveSync({ // [!code hl]
    // the key signs for the customer's account
    account: sweepKey, // [!code hl]
    amount: assetAmount, // [!code hl]
    feeToken: pathUsd, // [!code hl]
    spender: vault, // [!code hl]
    token: pathUsd, // [!code hl]
  }) // [!code hl]
  const { result: quotedShares } = await Actions.earn.deposit.simulate(client, {
    account: address,
    assetAmount,
    shareAmountMin: 1n,
    vault,
  })
  const { receipt, shareAmount } = await client.earn.depositSync({ // [!code hl]
    account: sweepKey, // [!code hl]
    assetAmount, // [!code hl]
    feeToken: pathUsd, // [!code hl]
    // accept at most 0.5% fewer shares
    shareAmountMin: EarnShares.minimumOutput(quotedShares, 50), // [!code hl]
    vault, // [!code hl]
  }) // [!code hl]
  // record receipt.transactionHash and shareAmount for reconciliation
}
```

Approve first: the simulation that quotes the shares needs the approval in place. `depositSync` repeats the approval in the deposit transaction, and since the limit counts only approval increases, the repeat uses none of it. Tempo rejects any transaction that exceeds what's left of today's limit, calls outside the two scopes, or arrives after the expiry.

### Track the position

```ts [backend/position.ts]
import { client } from '../client'

const pathUsd = '0x20c0000000000000000000000000000000000000'

const { shareBalance, value } = await client.earn.getPosition({ account: address, vault }) // [!code hl]
const { remaining } = await client.accessKey.getRemainingLimit({ account: address, accessKey: sweepKey, token: pathUsd }) // [!code hl]
```

Show the customer `value`, not `shareBalance`: shares don't map one-to-one to pathUSD, and `value` is what they're worth now, after fees, in pathUSD base units. `remaining` is what the key can still spend today. To show earnings over time, see [Balances and earnings](/docs/earn/balances). To withdraw, use the customer's own key or a separate key, as in [Withdraw](/docs/earn/withdraw).
