# Fund a card program

Your backend tops up a customer's card from their Tempo account without asking them each time.

In this guide, the customer's signers, such as a passkey, approve one [access key](/docs/accounts/access-keys) for your backend, once. Your backend keeps the key in its KMS and funds the card program as the customer spends. Tempo lets the key pay only the card program's funding address, up to a daily limit, so even a leaked key can't send money anywhere else or more than the limit in a day.

<span id="fund-a-card-with-a-daily-limit" />

The examples use a test stablecoin, and `client.ts` connects to the Tempo Accounts devnet ([set up the devnet key](/docs/accounts/create#connect-to-the-devnet)), the only network that runs configurable accounts. On mainnet and testnet, a card-funding key works the same from a single-key account, such as one whose key is the customer's passkey.

:::::steps

### Authorize a card-funding key

Get the customer's card funding address (`cardFundingAddress`) from your [card issuing partner](/docs/partners/cards). Create a secp256k1 key in your KMS and wrap it as a Viem account (`cardKey`), as in [Keep the key in your KMS](/docs/accounts/guides/automations/pay-out-from-a-backend#keep-the-key-in-your-kms). Then have the customer authorize its address (`cardKeyAddress`) in your app:

::::code-group

```ts [app/enable-card.ts]
import { parseUnits } from 'viem'
import { Expiry } from 'viem/tempo'
import { client } from '../client'

// A test stablecoin on the devnet
const stablecoin = '0x20c0000000000000000000000000000000000001'

await client.accessKey.authorizeSync({
  accessKey: { accessKeyAddress: cardKeyAddress, keyType: 'secp256k1' },
  account, // the customer's account, signed by its signers
  expiry: Expiry.days(30), // [!code hl]
  // 500 of the stablecoin a day
  limits: [{ token: stablecoin, limit: parseUnits('500', 6), period: 86_400 }], // [!code hl]
  scopes: [{ address: stablecoin, selector: 'transfer(address,uint256)', recipients: [cardFundingAddress] }], // [!code hl]
})
```


Set the limit to the card's daily spend limit plus a margin for the key's transaction fees, which count against it unless a [fee payer](/docs/accounts/fees/fee-sponsorship) covers them. Show the customer the card program, the limit, and the expiry before they approve.

### Fund the program

When the card program reports spend, or before it settles, send the amount to the funding address:

```ts [backend/fund-card.ts]
import { parseUnits } from 'viem'
import { client } from '../client'

// A test stablecoin on the devnet
const stablecoin = '0x20c0000000000000000000000000000000000001'

await client.token.transferSync({ // [!code hl]
  // the key signs for the customer's account
  account: cardKey, // [!code hl]
  amount: parseUnits('42.50', 6), // [!code hl]
  // the fee counts against the key's daily limit
  feeToken: stablecoin, // [!code hl]
  to: cardFundingAddress, // [!code hl]
  token: stablecoin, // [!code hl]
}) // [!code hl]
```

Tempo rejects a transfer to any other address, above what's left today, or after the expiry.

### Manage the limit and the key

The limit resets to its full amount every 24 hours (`period: 86_400`). Next to the card, show what's left and when it resets:

```ts [app/card-settings.ts]
import { client } from '../client'

// A test stablecoin on the devnet
const stablecoin = '0x20c0000000000000000000000000000000000001'

const { remaining, periodEnd } = await client.accessKey.getRemainingLimit({ // [!code hl]
  account, // [!code hl]
  accessKey: cardKeyAddress, // [!code hl]
  token: stablecoin, // [!code hl]
}) // [!code hl]
```

The customer's signers control the key:

- To change the limit, they call [`client.accessKey.updateLimitSync`](/docs/accounts/access-keys/spending-limits#change-a-spending-limit). What's left today becomes the new limit.
- To stop funding, they [revoke the key](/docs/accounts/access-keys/revocation#revoke-an-access-key). A revoked key never works again, so resuming takes a new key.
- To keep funding past 30 days, they [authorize a new key](/docs/accounts/access-keys/expiry#renew-an-expiring-key) before this one expires, since an expiry can't be extended.
