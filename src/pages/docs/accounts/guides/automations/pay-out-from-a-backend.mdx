# Pay out from a backend

Your backend can send payouts from a customer's Tempo account without prompting the customer each time. The customer's signers approve an [access key](/docs/accounts/access-keys) for your backend once, and Tempo lets that key pay only the [payees they list](/docs/accounts/access-keys/scopes), up to a [daily limit](/docs/accounts/access-keys/spending-limits), until it [expires](/docs/accounts/access-keys/expiry), so a leaked key can't drain the account.

The demo runs on Tempo devnet, a test network whose stablecoins have no value, with a device key in this browser as the customer's signer. The code runs on Moderato testnet with AlphaUSD, a test stablecoin, where `account` is the customer's single-key account, such as their passkey account. On devnet, a configurable account's signers authorize the key the same way.

### Authorize a scoped, limited key

Create one secp256k1 key per customer in your KMS. Its address, derived from the public key, is the key's ID on Tempo. Send that address to the customer's app, where the customer's signers authorize it:

```ts [app/approve-payouts.ts]
import { parseUnits } from 'viem'
import { Expiry } from 'viem/tempo'

const alphaUsd = '0x20c0000000000000000000000000000000000001'

await client.accessKey.authorizeSync({
  accessKey: { accessKeyAddress: payoutKeyAddress, keyType: 'secp256k1' },
  account, // the customer's account, approved with their passkey
  expiry: Expiry.days(90),
  limits: [{ token: alphaUsd, limit: parseUnits('1000', 6), period: 86_400 }], // 1,000 AlphaUSD a day
  scopes: [
    { address: alphaUsd, selector: 'transfer(address,uint256)', recipients: payees },
    { address: alphaUsd, selector: 'transferWithMemo(address,uint256,bytes32)', recipients: payees },
  ],
})
```

Authorizing is one transaction the customer approves, for example with their passkey. Show them the payees, daily limit, and expiry before they do.

Limits are in base units: AlphaUSD has 6 decimals, so `parseUnits('1000', 6)` is 1,000 AlphaUSD. Size the limit to your largest payout day plus fees, which count against it unless a [fee payer](/docs/accounts/fees/fee-sponsorship) sponsors them.

### Keep the key in your KMS

The private key never leaves the KMS, and Tempo stores only the key's address, payees, limit, and expiry. Wrap the key in a viem account that asks the KMS for each signature:

```ts [backend/payout-key.ts]
import { PublicKey, Signature } from 'ox'
import { Account } from 'viem/tempo'

const payoutKey = Account.from({
  access: address, // the customer's account address
  keyType: 'secp256k1',
  publicKey: PublicKey.fromHex(kmsPublicKey), // read once from your KMS
  async sign({ hash }) {
    return Signature.toHex(await kms.sign(kmsKeyId, hash)) // your KMS client returns { r, s, yParity }
  },
})
```

In your KMS, allow only the payout service to sign with the key, and log each signing request so you can match it to a payout.

### Send payouts

```ts [backend/send-payout.ts]
import { parseUnits, stringToHex } from 'viem'
import { tempoModerato } from 'viem/chains'
import { createClient } from 'viem/tempo'

const backend = createClient({ account: payoutKey, chain: tempoModerato, feeToken: alphaUsd })

await backend.token.transferSync({
  amount: parseUnits('250', 6),
  memo: stringToHex('payout-1042', { size: 32 }), // your payout ID, for reconciliation
  to: payee,
  token: alphaUsd,
})
```

The customer isn't prompted. Tempo rejects a payout to an address outside `payees`, one over what's left of today's limit, or any payout after the key expires. To stop payouts, have the signers [revoke the key](/docs/accounts/access-keys/revocation#revoke-an-access-key).

## Before you go live

- Payouts confirm one at a time by default, because an account's transactions share one nonce, a counter that orders them. To send them concurrently, use [expiring nonces or nonce keys](/docs/guide/payments/send-parallel-transactions).
- To add a payee, the signers or an [admin key](/docs/accounts/access-keys/admin-access-keys) update the key's [scopes](/docs/accounts/access-keys/scopes#change-allowed-calls).
- You can't extend an expiry, so [authorize a replacement key](/docs/accounts/access-keys/expiry#renew-an-expiring-key) before it passes.
