# Set up a company treasury wallet

Build a treasury that three approvers control, where any two approve a payment. Give the operations team its own daily budget, then rotate and remove approver keys at the same address and balance.

The examples use a `client` whose transport is a relay with `Relay.accounts`, as in [Read the current configuration](/docs/development/configurable-accounts#read-the-current-configuration). `client.accounts.getConfig` needs that relay; a bare node doesn't serve it. Configurable accounts and team budgets run on Tempo devnet.

## Create the treasury account

Make each approver a signer with weight 1, and set the threshold to 2. Use keys in separate teams' hardware wallets, KMSs, or HSMs, or the approvers' passkeys. See [Private keys](/docs/accounts/authentication/private-keys) for key sources.

```ts [treasury.ts]
import { Account } from 'viem/tempo'

const env = (name: string) => process.env[name] as `0x${string}`

const treasury = Account.fromConfig({
  address: 'infer',
  owners: [
    Account.fromSecp256k1(env('FINANCE_SIGNER_KEY')),
    Account.fromSecp256k1(env('OPERATIONS_SIGNER_KEY')),
    env('CONTROLLER_PASSKEY_ADDRESS'),
  ],
  threshold: 2,
})
```

Each payment then needs two approvals. Your app collects them, for example in your backend: see [Collect approvals from several approvers](/docs/accounts/policies/signing-thresholds#collect-approvals-from-several-approvers).

## Give a team a budget

Treasury approvers authorize a 2-of-3 team account once, as an access key with a daily budget. The team then pays from the treasury without asking them.

<GuideDemo guide="team-accounts" />

:::::steps

### Create the team account

Create a Tempo account with the three team members as signers and a threshold of 2, as for the treasury above.

### Authorize it from the treasury

Treasury approvers that reach its threshold approve the team account's address as an access key once. We recommend a daily limit per stablecoin, such as 50,000 USD, payments to approved recipients only, and a 90-day expiry followed by a new authorization.

### Pay as the team

One team member proposes a payment from the treasury, and a second approves it. Your app submits once the team reaches its threshold.

### Track the budget

[Read the remaining limit](/docs/accounts/access-keys/spending-limits#read-the-remaining-limit) as for any access key. The treasury [revokes](/docs/accounts/access-keys/revocation#revoke-an-access-key) the team account like any other access key when the team no longer needs it.

:::::

<span id="team-budget-rules" />

The budget follows these rules:

- It covers the whole team, not each member. Changing team signers keeps the authorization and the spending so far.
- Payments come from the treasury's address and balance, approved by the team's signers alone.
- Team members approve directly. The team's own access keys can't use the treasury's authorization.
- The team can't authorize keys, change treasury signers, or count toward the treasury's threshold.

## Rotate an approver's key

Give an approver a new key in one update, at the same weight. Access keys, including the team's budget, stay authorized.

<GuideDemo guide="rotate-keys" />

:::::steps

### Open the account by its address

```ts [rotate.ts]
const account = Account.fromConfig(address) // the treasury's saved address
const { owners, threshold } = await client.accounts.getConfig({ address: account.address })
```

### Swap the key at the same weight

```ts [rotate.ts]
import { isAddressEqual } from 'viem'

const nextOwners = owners.map((entry) =>
  isAddressEqual(entry.owner, oldKey) ? { owner: newKey, weight: entry.weight } : entry,
)
```

### Approve with the current signers

```ts [rotate.ts]
const { receipt } = await client.accounts.updateConfigSync({
  account,
  nextConfig: { owners: nextOwners, threshold },
  owner: operations, // the old key, unless it's compromised
})
await client.sendTransactionSync({ account, hash: receipt.transactionHash, owner: finance })
```

Once the update lands, the old key can't approve, and approvals collected before the update are void.

### Revoke the access keys you no longer trust

```ts [rotate.ts]
await client.accessKey.revokeSync({ accessKey, account })
```

:::::

For a compromised key, the other approvers approve the swap without it. To switch wallet providers, swap the old provider's key for the new one at the same weight.

## Remove a departing approver

Drop the approver and approve with the remaining ones. Their weights must still reach the threshold, or the update is rejected.

```ts [remove.ts]
import { isAddressEqual } from 'viem'

const { owners, threshold } = await client.accounts.getConfig({ address: account.address })
const nextOwners = owners.filter((entry) => !isAddressEqual(entry.owner, departing))

const { receipt } = await client.accounts.updateConfigSync({
  account,
  nextConfig: { owners: nextOwners, threshold },
  owner: finance,
})
await client.sendTransactionSync({ account, hash: receipt.transactionHash, owner: operations })
```

Then revoke each access key the departing approver could reach, and add their replacement as in [Add a backup signer](/docs/accounts/guides/self-custody#add-a-backup-signer).

## Treasury limits

- `InvalidConfig` means another signer update landed first. Read the signers again and rebuild the update.
- Signer changes don't revoke access keys. A revoked key can't be authorized again.
