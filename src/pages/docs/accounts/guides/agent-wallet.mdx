# Set up an agent wallet

Give an AI agent its own access key on an account, with a budget, an expiry, and only the calls its payments use. The account's signers stay with the customer or your approvers, and Tempo rejects anything outside the key's limits.

For an agent that pays for APIs from a terminal, start with [Tempo Wallet with agents](/docs/wallet/recipes#let-an-agent-pay-for-services).

## Authorize an agent's key

The example gives an agent 50 AlphaUSD a day for 30 days on Moderato testnet, for one-time [MPP](/docs/guide/machine-payments) payments.

:::::steps

### Define what the agent can do

Choose the token, a one-time or renewing budget, the expiry, and the contracts the agent calls. A custom [MPP client](/docs/guide/machine-payments/client) needs the calls its payment mode uses: `transferWithMemo` for one-time payments, and channel operations for payment sessions.

### Authorize a separate key for the agent

```ts [authorize-agent.ts]
import { parseUnits } from 'viem'
import { Account, Expiry, P256 } from 'viem/tempo'

const alphaUsd = '0x20c0000000000000000000000000000000000001'
const privateKey = P256.randomPrivateKey() // store it in the agent runtime's secret storage
const accessKey = Account.fromP256(privateKey, { access: account })

const keyAuthorization = await client.accessKey.signAuthorization({
  accessKey,
  account, // signed by the account's signers
  expiry: Expiry.days(30),
  limits: [{ token: alphaUsd, limit: parseUnits('50', 6), period: 86_400 }],
  scopes: [{ address: alphaUsd, selector: 'transferWithMemo(address,uint256,bytes32)' }],
})
```

The authorization travels with the agent's first payment. See [Authorize an access key](/docs/accounts/access-keys#authorize-an-access-key) for each option.

### Connect the key to the agent's client

```ts [agent.ts]
import { tempoModerato } from 'viem/chains'
import { createClient } from 'viem/tempo'

const agentClient = createClient({ account: accessKey, chain: tempoModerato, feeToken: alphaUsd })
```

### Show spending and end access

Show the agent's budget, expiry, allowed calls, and [remaining budget](/docs/accounts/access-keys/spending-limits#read-the-remaining-limit) in your account UI, with a [revoke](/docs/accounts/access-keys/revocation#revoke-an-access-key) action the account's signers approve. Show access as removed only after the revocation confirms.

## Agent budget limits

- The access key's budget caps what the agent spends from the account. Set a separate limit per request: Tempo Wallet CLI uses `--max-spend`.
- An agent's key can't authorize other keys, change signers, or count toward the threshold. Never give an agent an [admin access key](/docs/accounts/access-keys/admin-access-keys): it has no budget.
- Give each agent its own key, so you can revoke one without affecting the others.
