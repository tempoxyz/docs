# Offboard an approver

When an approver leaves, remove their signer from the treasury, revoke any access key they could sign with, and add a replacement so one lost key can't lock the treasury. The treasury keeps its address, balance, and payment history.

:::warning
**Not live yet.** Configurable accounts ([TIP-1107](https://tips.sh/1107)) run only on Tempo devnet, and behavior may change.
:::

The controller leaves, and finance and operations approve each change. The demo runs the same steps with keys the page generates.

### Remove their signer

Drop the departing approver from the saved signer list and keep the threshold:

```ts [offboard.ts]
import { isAddressEqual } from 'viem'

const remaining = owners.filter(({ owner }) => !isAddressEqual(owner, controller))

const { receipt } = await client.accounts.updateConfigSync({
  account: treasury,
  nextConfig: { owners: remaining, threshold },
  owner: finance, // 1 of 2: receipt.status is 'pending'
})
await client.sendTransactionSync({ account: treasury, hash: receipt.transactionHash, owner: operations })

const config = await client.accounts.getConfig({ address: treasury.address }) // Relay.accounts recorded it
// Save `config` with your treasury record: the next update starts from it.
```

Tempo rejects the update if the remaining weights can't reach the threshold. Here two approvers of weight 1 remain at a threshold of 2.

### Revoke their keys

Removing a signer doesn't revoke [access keys](/docs/accounts/access-keys). Any access key the departing approver could sign with, such as a backend key they managed, keeps paying within its limits until you revoke it:

```ts [offboard.ts]
import { Account } from 'viem/tempo'

// Open the treasury at its saved address: `address: 'infer'` would now derive a different one.
const current = Account.fromConfig({ address: treasury.address, ...config })

const { receipt: revoked } = await client.accessKey.revokeSync({ account: current, accessKey: serviceKey, owner: finance })
await client.sendTransactionSync({ account: current, hash: revoked.transactionHash, owner: operations })
```

`serviceKey` is the address you saved when you authorized the key. Revocation is permanent, so if the service still needs to pay, authorize a new key the departing approver never held. If you didn't save every key's address, [list the keys the treasury has authorized](/docs/accounts/access-keys/revocation#revoke-after-a-signer-change).

### Rebalance the threshold

With two approvers left at a threshold of 2, both must approve every payment, and losing either key locks the treasury. Add a replacement approver to return to 2 of 3:

```ts [offboard.ts]
const replacement = env('NEW_CONTROLLER_PASSKEY_ADDRESS')
const nextOwners = [...config.owners, { owner: replacement, weight: 1 }]

const { receipt: added } = await client.accounts.updateConfigSync({
  account: current,
  nextConfig: { owners: nextOwners, threshold: config.threshold },
  owner: finance,
})
await client.sendTransactionSync({ account: current, hash: added.transactionHash, owner: operations })

const rebalanced = await client.accounts.getConfig({ address: treasury.address })
// Save `rebalanced` with your treasury record.
```

If you already have the replacement's key, swap it in for the departing approver's in step 1's update and skip the 2-of-2 interval. Without a replacement, lowering the threshold to 1 keeps a lost key from locking the treasury but lets either approver pay alone. Have the new approver approve one transaction before you rely on their key.

## Rotate an approver's key instead

If the approver stays and only their key changes, such as a new hardware wallet, [replace the old key with the new one in one update](/docs/accounts/key-management/remove-signers#rotate-a-key-by-replacing-it-in-one-update) at the same weight.

## Offboarding limits

- Approvals collected before a signer update stop counting. Collect them again for any payment still waiting.
- `InvalidConfig` means the update didn't start from the treasury's current signers, usually because another update landed first. Load the latest saved configuration and rebuild the update.
