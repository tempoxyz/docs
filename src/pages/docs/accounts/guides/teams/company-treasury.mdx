# Set up a company treasury

A company treasury is one Tempo account that three approvers share, where any two must approve each payment. Tempo checks the approvals itself, so neither one stolen key nor your own backend can pay without a second approver.

:::warning
**Not live yet.** Configurable accounts ([TIP-1107](https://tips.sh/1107)) run only on Tempo devnet, and behavior may change.
:::

<span id="treasury-model" />

Each approver holds a signer, a key that approves the account's transactions, with a weight of 1. A transaction runs only when its approvers' weights add up to the threshold, here 2. The same threshold covers signer changes, so no single approver can add or remove a signer.

:::::steps

<span id="create-the-treasury-account" />

### Create the treasury

Keep each approver's key somewhere different, such as a hardware wallet, a separate KMS per team, or the approver's passkey, so one breach can't reach two of them. [Private keys](/docs/accounts/authentication/private-keys) compares the options.

```ts [treasury.ts]
import { Account } from 'viem/tempo'

const env = (name: string) => process.env[name] as `0x${string}`

const finance = Account.fromSecp256k1(env('FINANCE_SIGNER_KEY'))
const operations = Account.fromSecp256k1(env('OPERATIONS_SIGNER_KEY'))
const controller = env('CONTROLLER_PASSKEY_ADDRESS') // approves on their own device

const owners = [
  { owner: finance.address, weight: 1 },
  { owner: operations.address, weight: 1 },
  { owner: controller, weight: 1 },
]
const threshold = 2

const treasury = Account.fromConfig({ address: 'infer', owners, threshold })
// Save treasury.address and treasury.config with your treasury record.
```

`address: 'infer'` computes the treasury's address from its first signers and threshold, so you have it before the treasury sends anything. [Fund the treasury](/docs/accounts/create#fund-an-account-on-devnet) by sending stablecoins to that address; it pays its transaction fees from the same balance unless a [fee payer](/docs/accounts/fees/fee-sponsorship) sponsors them. The address stays the same when signers change, so save it rather than computing it again.

### Collect approvals

Each approver signs the same payment, usually on their own device. The first starts it and gets its hash, and the second approves that hash. This example runs both approvals in one process:

```ts [pay.ts]
import { http, parseUnits } from 'viem'
import { tempoDevnet } from 'viem/chains'
import { createClient, Relay, Store, withRelay } from 'viem/tempo'

const client = createClient({
  chain: tempoDevnet,
  transport: withRelay(http(), { plugins: [Relay.accounts({ store: Store.memory() })] }),
})
const alphaUsd = '0x20c0000000000000000000000000000000000001'

// Finance starts the payment: 1 of 2 approvals.
const { receipt } = await client.token.transferSync({
  account: treasury,
  amount: parseUnits('1200', 6), // 1,200 AlphaUSD in base units (6 decimals)
  owner: finance,
  to: vendor, // the recipient's address
  token: alphaUsd,
})
// receipt.status is 'pending' until approvals reach the threshold

// Operations approves the same hash: 2 of 2, so the payment runs.
await client.sendTransactionSync({ account: treasury, hash: receipt.transactionHash, owner: operations })
```

`Relay.accounts` holds each approval until the weights reach the threshold, then submits. `Store.memory()` works in one process. For approvers on different devices, give every approver's client the same persistent store, such as one in your backend.

Your app shows the second approver what they're approving, such as the recipient and amount, and passes them the hash. Stop at two: Tempo rejects signatures beyond the threshold. To collect approvals in a backend or verify them in a contract, see [Signing thresholds](/docs/accounts/policies/signing-thresholds#collect-and-verify-approvals).

## Treasury limits and changes

A treasury holds 1 to 48 signers, and a transaction carries at most 8 approvals, so set a threshold that eight approvers can reach.

To let a team pay within a daily limit without two treasury approvals per payment, [give it a budget](/docs/accounts/guides/teams/team-budget). When an approver leaves or replaces their key, follow [Offboard an approver](/docs/accounts/guides/teams/offboard-an-approver). A signer change voids approvals still waiting, so collect those again.
