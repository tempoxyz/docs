# Set up a company treasury

A company treasury is one Tempo account that three approvers share, where any two must approve each payment. Tempo checks the approvals itself, so neither one stolen key nor your own backend can pay without a second approver.

:::warning
**Not live yet.** Configurable accounts ([TIP-1107](https://tips.sh/1107)) run only on the Tempo Accounts devnet, and behavior may change.
:::

<span id="treasury-model" />

Each approver holds a signer, a key that approves the account's transactions, with a weight of 1. A transaction runs only when its approvers' weights add up to the threshold, here 2. The same threshold covers signer changes, so no single approver can add or remove a signer.

`client.ts` connects to the Tempo Accounts devnet ([set up the devnet key](/docs/accounts/create#connect-to-the-devnet)).

### Create the treasury

Keep each approver's key somewhere different, such as a hardware wallet, a separate KMS per team, or the approver's passkey, so one breach can't reach two of them. [Private keys](/docs/accounts/authentication/private-keys) compares the options. Here finance and operations sign with private keys, and the controller signs with a passkey on their own device, so your app knows only the controller's address.

```ts [treasury.ts]
import { Account } from 'viem/tempo'
import { client } from './client'

const env = (name: string) => process.env[name] as `0x${string}`

const finance = Account.fromSecp256k1(env('FINANCE_SIGNER_KEY'))
const operations = Account.fromSecp256k1(env('OPERATIONS_SIGNER_KEY'))
const controller = env('CONTROLLER_PASSKEY_ADDRESS') // the key stays on the controller's device

const treasury = Account.fromConfig({
  address: 'infer',
  owners: [
    { owner: finance.address, weight: 1 },
    { owner: operations.address, weight: 1 },
    { owner: controller, weight: 1 },
  ],
  threshold: 2,
})

// Save with your treasury record.
const saved = { address: treasury.address, config: treasury.config }

await client.faucet.fundSync({ account: saved.address }) // devnet test stablecoins
```

`address: 'infer'` computes the address from the first signers and threshold, so creating the treasury sends nothing; Tempo records the treasury with its first transaction. The address can receive stablecoins before then: on the devnet, the [faucet](/docs/accounts/create#fund-an-account-on-devnet) sends it test stablecoins. The treasury pays transaction fees from its own balance unless a [fee payer](/docs/accounts/fees/fee-sponsorship) sponsors them.

Tempo stores only a hash of the configuration (signers, weights, threshold, salt, and version): enough to check approvals, but not to tell your app who the signers are. Save the address and configuration with your treasury record. The address stays the same when signers change, and every approval is built from the saved configuration.

<span id="collect-approvals" />

### Approve a payment

To pay, rebuild the treasury from its saved record and attach the keys of the approvers signing this payment. The other signers stay as addresses:

```ts [treasury.ts]
import { isAddressEqual, parseUnits } from 'viem'

const alphaUsd = '0x20c0000000000000000000000000000000000001' // a devnet test stablecoin

/** Rebuilds the treasury from its saved record, with the approvers' keys attached. */
function openTreasury(approvers: readonly Account.RootAccount[]) {
  const { address, config } = saved
  const owners = config.owners.map(({ owner, weight }) => ({
    owner: approvers.find((key) => isAddressEqual(key.address, owner)) ?? owner, // other signers stay addresses
    weight,
  }))
  // Never updated (version 0): the address still comes from the first signers.
  if (config.version === 0n)
    return Account.fromConfig({ address: 'infer', owners, salt: config.salt, threshold: config.threshold })
  return Account.fromConfig({ ...config, address, owners })
}

// Finance and operations approve: 1 + 1 reaches the threshold of 2.
await client.token.transferSync({
  account: openTreasury([finance, operations]),
  amount: parseUnits('1200', 6), // 1,200 AlphaUSD in base units (6 decimals)
  to: vendor, // the recipient's address
  token: alphaUsd,
})
```

viem signs with the attached keys, highest weight first, until they reach the threshold. With only finance's key attached, it throws `Local owners do not meet the threshold.` and sends nothing. Call `openTreasury` for every action, not once at startup. A [signer change](/docs/accounts/key-management/add-signers) raises the configuration's version and returns the new `config`. Save it, because Tempo rejects approvals built from an older record with `multisig configuration commitment mismatch`.

This example holds two approvers' keys in one process, so that process could pay alone. In production, each approver checks the recipient and amount and signs on their own device. To collect approvals from separate devices, see [Signing thresholds](/docs/accounts/policies/signing-thresholds#approvers-on-separate-devices). To check the treasury's approvals in your own contract, see [Verify approvals in a contract](/docs/accounts/policies/signing-thresholds#verify-approvals).

## Treasury limits and changes

A treasury holds 1 to 48 signers, and a transaction carries at most 8 approvals, so set a threshold that eight approvers can reach.

To let a team pay within a daily limit without two treasury approvals per payment, [give it a budget](/docs/accounts/guides/teams/team-budget). When an approver leaves or replaces their key, follow [Offboard an approver](/docs/accounts/guides/teams/offboard-an-approver). A signer change voids approvals collected for a payment that hasn't been sent, so collect them again.
