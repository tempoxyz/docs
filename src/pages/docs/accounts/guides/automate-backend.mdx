# Automate a backend

Sweep a customer's idle balance into an [Earn](/docs/earn) vault each night. The account's signers approve one access key for your backend, scoped to `approve` and `deposit` on the vault with a daily limit, and your backend sweeps without prompting anyone.

## Sweep idle balances into a vault

The demo authorizes a backend key on Tempo devnet, moves funds with it, then revokes it. The examples use Moderato testnet, the `client` from [OIDC logins](/docs/accounts/authentication/oidc#connect-to-a-salt-service), and a vault from [Vaults](/docs/earn/vaults) that accepts the account's stablecoin.

:::::steps

### Create the key in your backend

```ts [backend/sweep-key.ts]
import { Account, P256 } from 'viem/tempo'

const privateKey = P256.randomPrivateKey()
await secrets.put(`sweeps/${address}`, privateKey) // your secret manager

const sweepKey = Account.fromP256(privateKey, { access: address }) // the customer's account address
```

Send `sweepKey.accessKeyAddress` to the customer's app. The private key never leaves your backend.

### Have the customer's signers approve it once

```ts [app/approve-sweeps.ts]
import { parseUnits } from 'viem'
import { Expiry } from 'viem/tempo'

const pathUsd = '0x20c0000000000000000000000000000000000000'

await client.accessKey.authorizeSync({
  accessKey: { accessKeyAddress, keyType: 'p256' },
  account,
  expiry: Expiry.days(90),
  limits: [{ token: pathUsd, limit: parseUnits('5000', 6), period: 86_400 }],
  scopes: [
    { address: pathUsd, selector: 'approve(address,uint256)' },
    { address: vault, selector: 'deposit(uint256,address,uint256)' },
  ],
})
```

This runs in the customer's app with their signed-in `account`. Show the daily limit, the vault, and the expiry before they approve. The key can't transfer funds anywhere else.

### Move funds without prompts

```ts [backend/sweep.ts]
import { Account, Actions, EarnShares } from 'viem/tempo'

const sweepKey = Account.fromP256(await secrets.get(`sweeps/${address}`), { access: address })

const balance = await client.token.getBalance({ account: address, token: pathUsd })
const assetAmount = balance.amount - operatingFloat // keep enough for the day's payments
if (assetAmount > 0n) {
  const { result: quotedShares } = await Actions.earn.deposit.simulate(client, {
    account: sweepKey,
    assetAmount,
    shareAmountMin: 1n,
    vault,
  })
  await client.earn.depositSync({
    account: sweepKey,
    assetAmount,
    shareAmountMin: EarnShares.minimumOutput(quotedShares, 50),
    vault,
  })
}
```

Tempo rejects a sweep over the daily limit, a call outside the two scopes, or any call after expiry, even from a compromised backend. See [Deposit](/docs/earn/integrate) for the deposit flow and its checks.

### Show the key and let the customer revoke it

```ts [app/sweep-settings.ts]
const remaining = await client.accessKey.getRemainingLimit({ accessKey: accessKeyAddress, account, token: pathUsd })

await client.accessKey.revokeSync({ accessKey: accessKeyAddress, account })
```

Show `remaining`, the vault, and the expiry next to a revoke button.

## Recommended limits for backend automations

| Automation | Spending limit | Allowed calls | Expiry |
| --- | --- | --- | --- |
| Earn sweeps | The idle balance you sweep, renewing daily | `approve` and `deposit` on your Earn vault | 90 days |
| Payouts | Your largest payout day, renewing daily | `transfer` to the customer's approved payees | 90 days |
| Card funding | The card's daily spend limit | `transfer` to your card program's funding address | 30 days |
| Bill pay | The largest bill, renewing monthly | `transfer` to each biller | 1 year |

For card funding, see [Set up a spending account](/docs/accounts/guides/spending-account). Access key rules and limits: [Access keys](/docs/accounts/access-keys).

<span id="troubleshoot-backend-payments" />

An account's transactions share one sequential nonce by default, so they land in order. Send concurrent backend payments with expiring nonces or separate nonce keys. See [Parallel payments](/docs/guide/payments/send-parallel-transactions).
