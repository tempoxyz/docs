# Add a recovery signer

A recovery signer is a second key that can approve transactions for a user's account, so losing their phone or first key doesn't lock them out. With one signer, a lost key is a lost account: nobody, including Tempo, can recover it. Add a recovery signer, then require two factors so whoever holds it can't take over the account alone. The address and balance stay the same.

:::warning
**Not live yet.** Configurable accounts ([TIP-1107](https://tips.sh/1107)) run only on Tempo devnet, and behavior may change.
:::

This guide starts from one signer at weight 1 and a threshold of 1, the total weight an approval needs. That signer, `currentKey`, is the key the account was created with, such as a key your app or wallet provider holds for the user.

Your app also keeps `saved`, the record it stored when it created the account: `{ address: account.address, config: account.config }`. The configuration lists the signers, their weights, the threshold, and a version number. Tempo stores only a hash of it, so your saved copy is the source of truth, and your app rebuilds the account from it before each action.

### Create the new signer

Pick a key the user doesn't lose along with the first one, such as a [recovery provider's](/docs/accounts/policies/signing-thresholds#recovery-provider) key or a backup key in a hardware wallet or KMS. The update needs only its address, `newSigner` in the next step.

### Approve the update

`openAccount` rebuilds the account from `saved` and attaches the keys you pass it as approvers. Every other signer stays a plain address, which is all the configuration needs. `currentKey` approves alone because its weight of 1 reaches the threshold of 1. The update appends `newSigner` to the saved signers.

```ts [add-signer.ts]
import { http, isAddressEqual } from 'viem'
import { tempoDevnet } from 'viem/chains'
import { Account, createClient } from 'viem/tempo'

const client = createClient({ chain: tempoDevnet, transport: http() })

/** The account that `saved` describes, holding the approvers' keys. */
function openAccount(approvers: Account.RootAccount[]) {
  const { address, config } = saved
  const owners = config.owners.map(({ owner, weight }) => ({
    owner: approvers.find((key) => isAddressEqual(key.address, owner)) ?? owner,
    weight,
  }))
  return config.version === 0n
    ? Account.fromConfig({ address: 'infer', owners, salt: config.salt, threshold: config.threshold })
    : Account.fromConfig({ ...config, address, owners })
}

const { config } = await client.accounts.updateConfigSync({
  account: openAccount([currentKey]),
  nextConfig: {
    owners: [...saved.config.owners, { owner: newSigner, weight: 1 }],
    threshold: saved.config.threshold,
  },
})
saved.config = config // the next openAccount call rebuilds from this
```

Save the returned `config` in place of the old one right away. Each signer update raises the version, which changes the hash Tempo stores, so a transaction from an account rebuilt from the old copy fails. `openAccount` reads `saved` on every call, so the next step builds from the new configuration. The address comes from the account's first configuration: at version 0, `address: 'infer'` derives it from the signers, and after an update `openAccount` passes the saved address instead.

### Confirm the account survives losing one signer

Check that the other signers still reach the threshold, whichever one is lost.

```ts [add-signer.ts]
const total = config.owners.reduce((sum, { weight }) => sum + weight, 0)
const recoverable = config.owners.every(({ weight }) => total - weight >= config.threshold)
```

Tempo can't tell whether a signer still holds its key, so have the new signer approve once before you rely on it.

### Require two factors

Either signer can now approve anything alone, including adding a device or removing the other signer, so whoever holds the recovery signer could take over the account. To require two factors, use the [customer accounts setup](/docs/accounts/policies/signing-thresholds#recommended-signer-setups): in one update, add a passkey at weight 2 and raise the threshold to 2. This step reuses `client` and `openAccount` from `add-signer.ts`.

```ts [multi-factor.ts]
import { Account, WebAuthnP256 } from 'viem/tempo'

const passkey = Account.fromWebAuthnP256(await WebAuthnP256.createCredential({ label: 'My account' }))

const { config: twoFactor } = await client.accounts.updateConfigSync({
  account: openAccount([currentKey]), // approves alone at the current threshold of 1
  nextConfig: {
    owners: [...saved.config.owners, { owner: passkey.address, weight: 2 }],
    threshold: 2,
  },
})
saved.config = twoFactor
```

Now a new device or a signer change needs the passkey on the user's device, or the first key and recovery signer together. Give those two keys [different holders](/docs/accounts/policies/signing-thresholds#what-a-threshold-protects-against), because one party holding both can approve alone. Signer changes don't touch access keys, so the user's existing device key keeps paying within its limits.

## Recovery signer limits

- Only current signers count toward the threshold, not the signer being added. When one key can't reach it alone, pass more approving keys to `openAccount`. If the keys you pass still fall short, viem throws `Local owners do not meet the threshold.` and sends nothing. To collect approvals from separate devices, see [Signing thresholds](/docs/accounts/policies/signing-thresholds#approvers-on-separate-devices).
- `multisig configuration commitment mismatch` means the account was rebuilt from an older configuration than the one Tempo stores, usually because another update landed first or the app didn't store the returned `config`. Load the latest saved configuration and rebuild the update.

When the user loses a signer, follow [Recover a user's account](/docs/accounts/guides/users/recover-an-account).
