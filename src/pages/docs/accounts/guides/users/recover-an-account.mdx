# Recover a user's account

When a user loses the phone that holds their passkey, the account's other signers (the keys that approve its transactions) swap in a new passkey, and the new passkey revokes the phone's device key. The account keeps its address and balance.

:::warning
**Not live yet.** Configurable accounts ([TIP-1107](https://tips.sh/1107)) run only on Tempo devnet, and behavior may change.
:::

This guide continues from [Add a recovery signer](/docs/accounts/guides/users/add-a-recovery-signer#require-two-factors), with the same devnet `client` and account: a passkey at weight 2, the user's first key and a recovery signer at weight 1 each, and a threshold of 2, the total weight an approval needs. Without the passkey, the other two reach 2 together. Tempo can't override an account's signers, so [check this when you add signers](/docs/accounts/guides/users/add-a-recovery-signer#confirm-the-account-survives-losing-one-signer), not after one is lost.

In the demo, a device key in this browser stands in for the passkey, and the demo treats it as lost.

:::::steps

### Create the replacement signer

The user creates a new passkey on their new device. It isn't a signer until the next step adds it.

```ts [recover.ts]
import { Account, WebAuthnP256 } from 'viem/tempo'

const passkey = Account.fromWebAuthnP256(await WebAuthnP256.createCredential({ label: 'My account' }))
```

<span id="sign-in-with-the-remaining-signers" />

### Approve with the remaining signers

Open the account from the address and configuration your app saved after its last update. Don't use `address: 'infer'`: once signers change, it derives a different address. Swap the lost passkey for the new one at the same weight. The first key sends the update and the recovery signer approves the same transaction; together they reach the threshold, so it lands.

```ts [recover.ts]
import { isAddressEqual } from 'viem'

const firstKey = Account.fromSecp256k1(firstPrivateKey)
const recovery = Account.fromSecp256k1(recoveryPrivateKey) // or your recovery provider's signer
const account = Account.fromConfig({ address, ...savedConfig })

const nextOwners = savedConfig.owners.map((entry) =>
  isAddressEqual(entry.owner, lostPasskeyAddress) ? { owner: passkey.address, weight: entry.weight } : entry,
)

const { receipt } = await client.accounts.updateConfigSync({
  account,
  nextConfig: { owners: nextOwners, threshold: savedConfig.threshold },
  owner: firstKey, // 1 of 2: receipt.status is 'pending'
})
await client.sendTransactionSync({ account, hash: receipt.transactionHash, owner: recovery })

const config = await client.accounts.getConfig({ address }) // Relay.accounts recorded it
// Save `config` in place of `savedConfig`.
```

Once the update lands, the lost passkey can't approve anything.

### Revoke the lost device's keys

Changing signers doesn't revoke access keys, so the device key on the lost phone can still pay within its limits. Reopen the account from the new configuration, then revoke the key with the new passkey, which reaches the threshold alone.

```ts [recover.ts]
const current = Account.fromConfig({ address, ...config }) // the configuration after the update

await client.accessKey.revokeSync({ accessKey: lostDeviceKey, account: current, owner: passkey })
```

If you didn't save the lost key's address, [list the keys the account has authorized](/docs/accounts/access-keys/revocation#revoke-when-signers-change). A revoked key can't be authorized again, so authorize a new [device key](/docs/accounts/authentication/device-keys) for the new phone.
