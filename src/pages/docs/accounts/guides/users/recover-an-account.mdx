# Recover a user's account

Swap in a new passkey when a user loses their phone, keeping the account's address and balance.

In this guide, a user loses the phone that holds their passkey, and the account's other two signers (keys that approve its transactions), the user's first key and a recovery signer, together swap in a new passkey from the user's new device. The new passkey then revokes the lost phone's device key. The account keeps its address and balance, and the guide runs on the Tempo Accounts devnet.

:::warning
**Configurable accounts aren't live yet.** Accounts with several signers and a threshold ([TIP-1107](https://tips.sh/1107)) work only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), not on mainnet or testnet, and may still change. Replacing a lost signer needs one.
:::

This guide continues from [Add a recovery signer](/docs/accounts/guides/users/add-a-recovery-signer#require-two-factors), with the same account: a passkey at weight 2, the user's first key and a recovery signer at weight 1 each, and a threshold of 2, the total weight an approval needs. Without the passkey, the other two reach 2 together. Tempo can't override an account's signers, so [check this when you add signers](/docs/accounts/guides/users/add-a-recovery-signer#confirm-the-account-survives-losing-one-signer), not after one is lost.

Tempo stores only a hash of the account's configuration (signers, weights, threshold, and version), so your app rebuilds the account from the address and configuration it saved after the last update: `saved.address` and `saved.config` below.

In the demo, a device key in this browser stands in for the passkey, and the demo treats it as lost.

:::::steps

### Create the replacement signer

The user creates a new passkey on their new device. It isn't a signer until the next step adds it.

```ts [recover.ts]
import { Account, WebAuthnP256 } from 'viem/tempo'

const passkey = Account.fromWebAuthnP256(await WebAuthnP256.createCredential({ label: 'My account' })) // [!code hl]
```

<span id="sign-in-with-the-remaining-signers" />

### Approve with the remaining signers

Rebuild the account from `saved`, attaching the keys that approve: the first key, held by your app or wallet provider, and the recovery signer. Signers without an attached key, such as the lost passkey, whose address is `lostPasskey`, stay addresses that can't sign. `openAccount` passes the saved address, not `address: 'infer'`, which derives a different address once signers change. The update swaps the lost passkey for the new one at the same weight, and viem signs it with both attached keys: their weights of 1 each reach the threshold of 2.

`client.ts` connects to the Tempo Accounts devnet ([set up the devnet key](/docs/accounts/create#connect-to-the-devnet)).

::::code-group

```ts [recover.ts]
import { isAddressEqual } from 'viem'
import { client } from './client'

/** The account that `saved` describes, holding the approvers' keys. */
function openAccount(approvers: Account.RootAccount[]) {
  const { address, config } = saved
  const owners = config.owners.map(({ owner, weight }) => ({
    owner: approvers.find((key) => isAddressEqual(key.address, owner)) ?? owner,
    weight,
  }))
  return Account.fromConfig({ ...config, address, owners })
}

const firstKey = Account.fromSecp256k1(firstPrivateKey) // held by your app or wallet provider
const recovery = Account.fromSecp256k1(recoveryPrivateKey) // or your recovery provider's signer

const { config } = await client.accounts.updateConfigSync({ // [!code hl]
  account: openAccount([firstKey, recovery]), // [!code hl]
  nextConfig: { // [!code hl]
    owners: saved.config.owners.map(({ owner, weight }) => ({ // [!code hl]
      owner: isAddressEqual(owner, lostPasskey) ? passkey.address : owner, // [!code hl]
      weight, // [!code hl]
    })), // [!code hl]
    threshold: saved.config.threshold, // [!code hl]
  }, // [!code hl]
}) // [!code hl]
// persist it: the version increments, and the next step builds from it
saved.config = config // [!code hl]
```

::::

If the attached keys can't reach the threshold, viem throws `Local owners do not meet the threshold.` and sends nothing. To collect approvals from separate devices, see [Signing thresholds](/docs/accounts/policies/signing-thresholds#approvers-on-separate-devices). Once the update lands, the lost passkey can't approve anything.

### Revoke the lost device's keys

The lost phone's device key is an [access key](/docs/accounts/access-keys): it pays from the account within its limits without the signers' approval. Changing signers doesn't revoke it, so revoke it now. `lostDeviceKey` is the address your app saved when it authorized the key. `openAccount` rebuilds the account from the updated `saved.config`; an account built from the old configuration no longer matches the hash Tempo stores and fails with `multisig configuration commitment mismatch`. On the new device, the new passkey approves alone, because its weight of 2 reaches the threshold.

```ts [recover.ts]
await client.accessKey.revokeSync({ // [!code hl]
  // rebuilt from the new `saved.config`
  account: openAccount([passkey]), // [!code hl]
  accessKey: lostDeviceKey, // [!code hl]
}) // [!code hl]
```

If you didn't save the lost key's address, [list the keys the account has authorized](/docs/accounts/access-keys/revocation#revoke-when-signers-change). A revoked key can't be authorized again, so authorize a new [device key](/docs/accounts/authentication/device-keys) for the new phone.
