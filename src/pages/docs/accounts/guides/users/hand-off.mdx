# Hand off to a self-custodial wallet

Give a user full control of their account through a signer in their own wallet.

Your app removes its own signers and access keys from a user's account and replaces them with one signer the user holds in their own wallet, such as Tempo Wallet. The account keeps its address and balance, and your app keeps no key.

:::warning
**Configurable accounts aren't live yet.** Accounts with several signers and a threshold ([TIP-1107](https://tips.sh/1107)) work only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), not on mainnet or testnet, and may still change. This guide uses one.
:::

<span id="why-a-signer-handoff-instead-of-a-private-key-export" />

Your app holds two kinds of keys on the account: signers, which approve payments and account changes, and access keys, which pay within limits. A handoff removes both: your app's signer revokes the access keys, then approves its own replacement by the user's signer. Unlike exporting a private key, a handoff leaves your app no copy, and it works for passkeys and device keys, which can't be exported.

The demo plays your app. It holds the account's only signer and an access key, then hands the account to a device key in this browser, standing in for the user's passkey.

:::::steps

### Get the user's signer address

The user creates a passkey in a self-custodial wallet, such as [Tempo Wallet](https://wallet.tempo.xyz), and sends you its address, `userSigner` below. The key stays on their device, and your app needs only the address. Have them confirm it in their wallet before you continue: Tempo can't check that the user holds the key behind an address, and a wrong address locks the account.

<span id="handoff-limits" />

### Revoke your app's keys

Changing signers leaves access keys active, so revoke each one your app holds first, while your app's signer can still approve. [Revoked](/docs/accounts/access-keys/revocation) keys can't be authorized on this account again.

Your app's signer approves each revocation. Rebuild the account from the address and configuration you saved for this user, since Tempo stores only a hash of the configuration. Attach your app's signer as a key Viem can sign with, and leave the other signers as addresses.

`client.ts` connects to the Tempo Accounts devnet ([set up the devnet key](/docs/accounts/create#connect-to-the-devnet)).

::::code-group

```ts [hand-off.ts]
import { isAddressEqual } from 'viem'
import { Account } from 'viem/tempo'
import { client } from './client'

const appSigner = Account.fromSecp256k1(process.env.APP_SIGNER_KEY as `0x${string}`)

// Your app's signer approves; the other signers stay addresses.
const { address, config } = await loadAccount(userId) // your app's storage
const owners = config.owners.map(({ owner, weight }) => ({
  owner: isAddressEqual(owner, appSigner.address) ? appSigner : owner, // [!code hl]
  weight,
}))
const account =
  config.version === 0n // never updated: the config derives the address
    ? Account.fromConfig({ address: 'infer', owners, salt: config.salt, threshold: config.threshold })
    : Account.fromConfig({ ...config, address, owners })

// the access key addresses you saved
for (const accessKey of appAccessKeys) { // [!code hl]
  await client.accessKey.revokeSync({ account, accessKey }) // [!code hl]
} // [!code hl]
```

Viem signs with `appSigner`. If its weight alone can't reach the threshold, Viem throws `Local owners do not meet the threshold.` and sends nothing. To collect approvals from separate devices, see [Signing thresholds](/docs/accounts/policies/signing-thresholds#approvers-on-separate-devices). Revocations leave the configuration unchanged, so the same `account` approves the swap.

<span id="swap-the-signers-in-one-update" />

### Swap the signers

In one update, replace your app's signers, including any key your wallet provider holds for the user, with the user's signer. Your app's signer approves its own removal.

```ts [hand-off.ts]
const { config: handedOff } = await client.accounts.updateConfigSync({ // [!code hl]
  account, // [!code hl]
  nextConfig: { // [!code hl]
    owners: [{ owner: userSigner, weight: 1 }], // [!code hl]
    threshold: 1, // [!code hl]
  }, // [!code hl]
}) // [!code hl]
await saveAccount(userId, { address, config: handedOff }) // [!code hl]
```

`handedOff` is the new configuration, one version higher. An account built from the old configuration now fails, and the user's wallet needs `handedOff` to approve.

If the user loses their only signer, nobody, including Tempo, can recover the account. To leave them a backup, send the [customer accounts setup](/docs/accounts/policies/signing-thresholds#recommended-signer-setups) in this update instead: the user's passkey approves alone, and two backup signers they choose approve only together.

### Send the user to their wallet

The user's signer now controls the account at `address`, and the balance is already there. Send the user `address` and `handedOff`, because their wallet can't read the configuration back from Tempo. To request payments from them later, [connect your app to their wallet](/docs/accounts/guides/users/self-custodial-wallets#connect-tempo-wallet).
