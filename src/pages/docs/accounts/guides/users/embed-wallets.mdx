# Embed wallets with a provider

Run embedded wallets with a provider such as Privy or Turnkey, while each user keeps a signer only they hold. The provider's key is one signer among several, and Tempo enforces the account's threshold and access-key limits on whatever the provider signs.

<span id="choose-the-controls-your-application-needs" />

Three parties share the work. Your application signs users in, saves each user's account address, and decides when to request a payment. Your wallet provider holds its signing key and applies its own policies before it signs. Tempo checks every signature against the account's signers and the limits on its access keys, the scoped keys a device or app uses for everyday payments.

:::::steps

<span id="make-the-providers-key-one-signer" />

### Make the provider's key one signer

Create the account with three signers: the user's passkey at weight 2, your provider's key at weight 1, and a recovery provider's key at weight 1, with threshold 2. A passkey is a key the user's device keeps and unlocks with Face ID, Touch ID, or Windows Hello. The user approves alone with it; the two providers approve only together. This is the [embedded wallets setup](/docs/accounts/policies/signing-thresholds#recommended-signer-setups).

```ts [account.ts]
import { Account, WebAuthnP256 } from 'viem/tempo'

const passkey = Account.fromWebAuthnP256(await WebAuthnP256.createCredential({ label: 'My account' }))

// Keep these: you pass them to every later signer update.
const owners = [
  { owner: passkey, weight: 2 },
  { owner: providerKeyAddress, weight: 1 }, // the address of the key your provider manages
  { owner: recoveryAddress, weight: 1 }, // the address your recovery provider gives you
]
const threshold = 2

const account = Account.fromConfig({ address: 'infer', owners, threshold })
```

The address comes from these first signers and stays the same when signers change later, so save `account.address` and `account.config` (the signer addresses, weights, and threshold) with the user's record. Accounts with several signers ([TIP-1107](https://tips.sh/1107)) run only on Tempo devnet, a test network for features in development.

### Connect Privy or Turnkey

To run embedded wallets yourself, use your provider's Tempo integration to sign with the provider's key.

- **Privy:** the [Tempo integration](https://docs.privy.io/wallets/using-wallets/tempo/send-a-transaction) signs Tempo transactions from embedded wallets, with batched calls, fee-token selection, fee sponsorship, and validity windows. Start from the [Privy Tempo example](https://github.com/privy-io/examples/tree/main/examples/privy-next-tempo) for wallet creation, sign-in, and payments in a browser app. Keep Privy and your RPC client on the same network.
- **Turnkey:** the [Tempo integration](https://docs.turnkey.com/features/networks/tempo) covers address derivation, transaction construction, and signing policies. It uses `ADDRESS_TYPE_ETHEREUM` for Tempo addresses and exposes Tempo transaction fields to its policy engine through the `tempo.tx` namespace. Start from the [Turnkey Tempo example](https://github.com/tkhq/sdk/tree/main/examples/chain-integrations/with-tempo) for single calls, batches, and fee sponsorship, and the [Embedded Wallet Kit](https://docs.turnkey.com/sdks/react/getting-started) for wallet UI.

:::::

When a user leaves, swap the provider's key for a signer the user holds: see [Hand off to a self-custodial wallet](/docs/accounts/guides/users/hand-off).

## Connect a self-custodial wallet instead

If users already hold a self-custodial wallet, such as Tempo Wallet, connect it with the [Accounts SDK](https://accounts.tempo.xyz/docs). The wallet holds the keys and signs; your application uses the address the user selects. This example uses Moderato testnet.

```bash [Terminal]
pnpm add --save-exact accounts@0.18.4 viem
```

<span id="connect-tempo-wallet-from-your-application" />

```ts [connect.ts]
import { Provider } from 'accounts'
import { tempoModerato } from 'viem/chains'

const provider = Provider.create({ chains: [tempoModerato], testnet: true })
const [address] = await provider.request({ method: 'eth_requestAccounts' })
if (!address) throw new Error('No account was selected')
```

On `accountsChanged`, update the selected address or clear it when the wallet disconnects. On `chainChanged`, refresh network-dependent state before enabling transactions. Keep this connection separate from your application's signed-in session. The [browser wallet setup](/docs/guide/payments/send-a-payment/examples#browser-wallet-setup) creates wallet and public clients from this provider, and [wallet partners](/docs/partners/wallets) lists other integrations.
