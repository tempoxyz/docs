# Migrate existing wallets

Each of your users' existing accounts is a single-key account (EOA), like a standard Ethereum account: one private key approves everything, so losing that key loses the account. Upgrade each account in place to add backup signers. The address, balances, and access keys stay the same, and the upgrade is permanent.

:::warning
**Not live yet.** Account upgrade ([TIP-1113](https://tips.sh/1113)) runs only on Tempo devnet, and behavior may change.
:::

After the upgrade, the account has a list of signers, each with a weight, and a threshold: the total weight an approval needs. The original key keeps approving only if you list it. [Account upgrade](/docs/accounts/key-management/account-upgrade) explains the change and runs one in a live demo.

:::::steps

### Choose the new signers

List the original key and at least one backup signer the user can reach without it, such as a passkey or your recovery provider's key. With both at weight 1 and threshold 1, either one approves alone and can replace the other if it's lost.

```ts [upgrade.ts]
import { Account, AccountConfig } from 'viem/tempo'

const original = Account.fromSecp256k1(userPrivateKey) // the key your app manages for this user

// Sorts the signers by address, as Tempo requires
const { owners, threshold } = AccountConfig.from({
  owners: [
    { owner: original.address, weight: 1 },
    { owner: backupAddress, weight: 1 }, // the user's passkey or your recovery provider's key
  ],
  threshold: 1,
})
```

Access keys carry over with their limits, so [revoke](/docs/accounts/access-keys/revocation) any you don't want before you upgrade.

### Upgrade each account in place

Send the upgrade for each account as in [Account upgrade](/docs/accounts/key-management/account-upgrade#send-the-upgrade): the user's original key signs one transaction whose only call is `upgradeAccount(threshold, owners)`, on a `client` connected to Tempo devnet. Each upgrade pays a transaction fee in a stablecoin, and a [fee payer](/docs/accounts/fees/fee-sponsorship) can sponsor it for accounts with no balance.

### Save the configuration

Save each account's new configuration with the user's record, as the Account upgrade code does: every later approval includes it. An upgraded account starts at version 1, with a salt Tempo derives from its address. Sign through `Account.fromConfig` from now on: a direct signature from the original key fails with `RootKeyRetired`.

From then on, manage signers like any other account, as in [Add a recovery signer](/docs/accounts/guides/users/add-a-recovery-signer).
