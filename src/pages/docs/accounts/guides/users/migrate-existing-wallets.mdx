# Migrate existing wallets

Upgrade your users' existing single-key accounts in place to add backup signers.

Each existing account is a single-key account (EOA), like a standard Ethereum account: one private key approves everything, so losing that key loses the account. The upgrade keeps the address, balances, and access keys, and it's permanent.

:::warning
**Account upgrades aren't live yet.** Turning a single-key account into a configurable account at the same address ([TIP-1113](https://tips.sh/1113)) works only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), not on mainnet or testnet, and may still change.
:::

After the upgrade, the account has a list of signers, each with a weight, and a threshold: the total weight an approval needs. The original key keeps approving only if you list it. [Account upgrade](/docs/accounts/key-management/account-upgrade) explains the change and runs one in your browser.

:::::steps

### Choose the new signers

List the original key and at least one backup signer the user can reach without it, such as a passkey on the user's device or your recovery provider's key. Your app holds the original key. The backup's private key stays with its holder, the user's device or your recovery provider, so your app needs only the backup's address. With both at weight 1 and threshold 1, either one approves alone and can replace the other if it's lost.

```ts [upgrade.ts]
import { Account, AccountConfig } from 'viem/tempo'

const original = Account.fromSecp256k1(userPrivateKey) // the key your app holds for this user

// Sorts the signers by address, as Tempo requires
const { owners, threshold } = AccountConfig.from({ // [!code hl]
  owners: [ // [!code hl]
    { owner: original.address, weight: 1 }, // [!code hl]
    // the user's passkey or your recovery provider's key
    { owner: backupAddress, weight: 1 }, // [!code hl]
  ], // [!code hl]
  threshold: 1, // [!code hl]
}) // [!code hl]
```

Access keys, the limited keys that sign payments for the account, carry over with their limits, so [revoke](/docs/accounts/access-keys/revocation) any you don't want before you upgrade.

### Upgrade each account in place

Send the upgrade for each account as in [Account upgrade](/docs/accounts/key-management/account-upgrade#send-the-upgrade): the user's original key signs one transaction whose only call is `upgradeAccount(threshold, owners)`. Set `feeToken` on that call, or on the client, to the stablecoin that pays the fee. Without it, viem sends a standard Ethereum transaction and the upgrade reverts with [`PrimitiveRootRequired`](https://github.com/tempoxyz/tempo/blob/3530079/crates/precompiles/src/native_multisig/mod.rs#L154). A [fee payer](/docs/accounts/fees/fee-sponsorship) can sponsor the fee for accounts with no balance. On mainnet or testnet, the same transaction succeeds and charges its fee but changes nothing, so a successful receipt there doesn't mean the account upgraded.

### Save the configuration

Tempo stores only a hash of each account's configuration, so the copy your app saves is what it signs with from now on. Once the upgrade succeeds, save the address and configuration with the user's record. An upgraded account starts at version 1, and its salt, a fixed 32-byte value that is part of the configuration, comes from its address.

```ts [upgrade.ts]
import { concat, keccak256, toHex } from 'viem'

// your app's storage
await saveAccount(userId, { // [!code hl]
  // unchanged by the upgrade
  address: original.address, // [!code hl]
  config: { // [!code hl]
    owners, // [!code hl]
    salt: keccak256(concat([toHex('tempo:multisig:upgrade'), original.address])), // [!code hl]
    threshold, // [!code hl]
    version: 1n, // [!code hl]
  }, // [!code hl]
}) // [!code hl]
```

### Pay through the saved configuration

Wherever your app signs with `original` directly, pass an account rebuilt from the saved record instead: a direct signature from the original key now fails with [`RootKeyRetired`](https://github.com/tempoxyz/tempo/blob/3530079/crates/revm/src/native_multisig/mod.rs#L390) (`primitive root key retired`). In the rebuilt account, pass `original` itself in its signer entry so it can sign, and keep the other signers as addresses. viem signs with the keys you pass until their weights reach the threshold. `client.ts` connects to the Tempo Accounts devnet ([set up the devnet key](/docs/accounts/create#connect-to-the-devnet)).

```ts [client.ts]
// [!include ~/snippets/accounts-devnet.ts:client]
```

```ts [pay.ts]
import { isAddressEqual, parseUnits } from 'viem'
import { Account } from 'viem/tempo'
import { client } from './client'

// A test stablecoin on the devnet
const token = '0x20c0000000000000000000000000000000000001'
const original = Account.fromSecp256k1(userPrivateKey) // the key your app holds for this user
const { address, config } = await loadAccount(userId) // the record saved above

const account = Account.fromConfig({ // [!code hl]
  ...config, // [!code hl]
  address, // [!code hl]
  owners: config.owners.map(({ owner, weight }) => ({ // [!code hl]
    // the key that approves
    owner: isAddressEqual(owner, original.address) ? original : owner, // [!code hl]
    weight, // [!code hl]
  })), // [!code hl]
}) // [!code hl]

await client.token.transferSync({ account, amount: parseUnits('1', 6), to: recipient, token }) // [!code hl]
```

From then on, manage signers like any other configurable account, as in [Add a recovery signer](/docs/accounts/guides/users/add-a-recovery-signer). After each signer change, save the `config` that `updateConfigSync` returns and rebuild the account from it. An account built from an older configuration no longer matches the hash Tempo stores, and its transactions fail with `multisig configuration commitment mismatch`.
