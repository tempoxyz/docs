# Signer rotation

Signer rotation swaps one signer for a new key at the same weight, in one update that the current signers approve. Any combination of signers that could approve before can approve after, with the new key in the old one's place.

<span id="replace-a-signer" />

## Rotate a signer at the same weight

A rotation rewrites one entry in the account's signer list and keeps the threshold. Tempo checks the update like any other transaction from the account: approving weights must reach the current threshold. On a scheduled rotation, the old key can be one of the approvers.

Read the current signers, swap the entry, and approve with enough signers to reach the threshold:

```ts [rotate-signer.ts]
import { isAddressEqual } from 'viem'
import { Account } from 'viem/tempo'

const account = Account.fromConfig(address) // the account's saved address
const config = await client.accounts.getConfig({ address: account.address })
if (!config) throw new Error('The relay has no configuration for this account.')

const { receipt } = await client.accounts.updateConfigSync({
  account,
  nextConfig: {
    owners: config.owners.map((entry) =>
      isAddressEqual(entry.owner, oldSigner) ? { owner: newSigner, weight: entry.weight } : entry,
    ),
    threshold: config.threshold,
  },
  owner: approver, // a current signer; on a scheduled rotation, the old key can approve
})

// A second signer approves the same update when the first can't reach the threshold alone.
await client.sendTransactionSync({ account, hash: receipt.transactionHash, owner: secondSigner })
```

`getConfig` reads the signers from a relay that runs `Relay.accounts`, so the client's transport must be that relay. It returns `null` when the relay has no configuration for the account.

Swapping in one update means the account never has the new key and the old key active together, and never has neither. The same update covers a provider switch: swap the old provider key for the new one at the same weight. [Rotate an approver's key](/docs/accounts/guides/company-treasury#rotate-an-approvers-key) walks through it.

## Remove a departing signer

Removing a signer is the same update with its entry dropped. Approve with the signers that stay:

```ts [remove-signer.ts]
const { receipt } = await client.accounts.updateConfigSync({
  account,
  nextConfig: {
    owners: config.owners.filter((entry) => !isAddressEqual(entry.owner, departing)),
    threshold: config.threshold,
  },
  owner: approver, // a signer that stays
})
```

If the remaining weights fall below the threshold, lower `threshold` in the same update, or Tempo rejects it. [Remove a departing approver](/docs/accounts/guides/company-treasury#remove-a-departing-approver) walks through offboarding.

## Rotate a compromised signer

Treat a compromised signer as an attacker who can approve at its weight. Swap it out or remove it with the other signers only, so the update doesn't depend on a key you no longer trust. Then [revoke every access key](/docs/accounts/access-keys/revocation) it could reach: a signer update doesn't touch access keys, and a key the attacker authorized keeps paying within its limits until you revoke it.

If the compromised signer can reach the threshold alone, it can also rotate the other signers out first. Keep every signer below the threshold alone, so no single key controls the account.

<span id="revoke-what-the-old-signer-authorized" />

## Revoke what the old signer authorized

Removing or swapping a signer doesn't revoke access keys. After the update lands, revoke each access key the old signer could reach, including any key an attacker authorized. [Access key revocation](/docs/accounts/access-keys/revocation) covers how to find and revoke them.

## Signer rotation limits

- The approving signers must reach the current threshold. Removing a signer must leave weights that still reach it, or Tempo rejects the update.
- An account keeps at least one signer.
- `InvalidConfig` means another signer update landed first. Read the signers again and rebuild the update.
- After a signer change, `address: 'infer'` derives a different address. Open the account with `Account.fromConfig(address)`.
- An account holds 1–48 signers, with total weight at most 255.

Specifications: [configuration updates](https://tips.sh/1109), [configurable accounts](https://tips.sh/1107).
