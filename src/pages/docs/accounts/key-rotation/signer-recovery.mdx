# Signer recovery

Signer recovery replaces a lost signer using only the signers that remain, and it works only if their weights still reach the threshold. Tempo has no recovery service or override: an account that can't reach the threshold without the lost key can't be recovered.

## Recover with the remaining signers

Recovery is a [signer rotation](/docs/accounts/key-rotation/signer-rotation) in which the lost key doesn't approve. The remaining signers approve one update that swaps the lost signer for a new one, and Tempo checks their weights against the current threshold like any other transaction.

For example, a customer with a passkey at weight 2, and a backup key and a recovery provider's key at weight 1 each, at threshold 2, loses their phone. They create a new passkey on a new device, and the two keys approve the swap together:

```ts [recover.ts]
import { Account } from 'viem/tempo'

const account = Account.fromConfig(address) // the customer's saved address
const backup = Account.fromSecp256k1(process.env.BACKUP_KEY as `0x${string}`)
const recovery = Account.fromSecp256k1(process.env.RECOVERY_KEY as `0x${string}`)

const { receipt } = await client.accounts.updateConfigSync({
  account,
  nextConfig: {
    owners: [
      { owner: newPasskey.address, weight: 2 },
      { owner: backup.address, weight: 1 },
      { owner: recovery.address, weight: 1 },
    ],
    threshold: 2,
  },
  owner: backup,
})

await client.sendTransactionSync({ account, hash: receipt.transactionHash, owner: recovery })
```

Once the update lands, the lost passkey can't approve. Then [revoke the access keys](/docs/accounts/access-keys/revocation) the lost device held, since a device key on a lost phone keeps paying within its limits until you do. [Recover from a lost passkey](/docs/accounts/guides/self-custody#recover-from-a-lost-passkey) walks through the full flow.

A lost backup or recovery key works the same way: the passkey replaces it alone.

## Add a recovery signer before you need it

A recovery signer exists so the account survives losing another signer. Give it enough weight that the remaining signers reach the threshold without any one signer, and no more: it can also approve payments at that weight.

- **Below the threshold:** the signer approves only together with others. Use this for backup and recovery keys, so no single one controls the account.
- **At or above the threshold:** the signer approves anything alone, including removing every other signer. Use this only for a key you would trust with the whole account.

Adding weight doesn't raise the threshold, so a new signer can make approvals easier to reach. Raise the threshold in the same update if the account should still need the same approvers. Check the setup against the rule in [Plan for recovery](/docs/accounts/key-rotation#plan-for-recovery), and see [Add a backup signer](/docs/accounts/guides/self-custody#add-a-backup-signer) for the update.

## Recover funds sent on another chain

The account's address is the same on every EVM chain, so someone can send funds to it on a chain where Tempo doesn't run. On supported chains, the account's initial secp256k1 signers, reaching the original threshold, can deploy a recovery wallet at that address and retrieve the funds, even after you remove those signers on Tempo.

Passkeys and device keys don't count. Accounts created with only passkeys and device keys, and accounts [upgraded in place](/docs/accounts/key-rotation/account-upgrade), can't recover funds this way. [Recover funds sent on another chain](/docs/accounts/guides/self-custody#recover-funds-sent-on-another-chain) covers the steps.

## Signer recovery limits

- The remaining signers must reach the threshold. Plan for this when you create the account: see [Plan for recovery](/docs/accounts/key-rotation#plan-for-recovery).
- Tempo can't tell whether a signer still holds its key. Have each new signer approve once before you rely on it.
- Cross-chain recovery uses only the initial secp256k1 signers at the original threshold.
