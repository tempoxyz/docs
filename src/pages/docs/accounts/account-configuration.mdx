# Account Configuration

Changes a configurable account's signers, weights, and threshold without changing its address.

<span id="how-it-works" />

## Overview

An account's configuration is its signers, their weights, and its threshold. A signer is a key that approves the account's transactions. Because the address stays, the balance and history survive a lost phone or a departing approver.

<ConfigurableAccountsT14 />

A [configuration update](/docs/accounts/account-configuration/configuration-updates) replaces the account's whole signer list and its [threshold](/docs/accounts/policies/signing-thresholds) in one transaction. Signers whose weights reach the current threshold approve it, the same way they approve a payment. Only the current signers can approve a change. Tempo has no override, so [plan for recovery](#plan-for-recovery) before you need it.

A single-key account (EOA) has no signer list to change. [Upgrade it](/docs/accounts/account-configuration/account-upgrade) to a configurable account first.

## Approvers by Situation

The situations differ in who approves:

| Situation | The update | Who approves |
| --- | --- | --- |
| [Add a backup or recovery signer](/docs/accounts/account-configuration/configuration-updates#add-a-signer) | Adds the new signer | The current signers |
| [Rotate a key](/docs/accounts/account-configuration/configuration-updates#rotate-a-key-by-replacing-it-in-one-update) | Swaps the new key in at the old one's weight | The current signers, including the old key |
| [Replace a lost or compromised signer](/docs/accounts/account-configuration/configuration-updates#remove-a-lost-or-compromised-signer) | Swaps a new signer in for it | The other signers, without it |
| [Offboard an approver](/docs/accounts/custodians/team-multisig) | Removes their signer, and lowers the threshold if needed | The remaining approvers |
| [Hand off to a self-custodial wallet](/docs/accounts/apps/self-custodial-wallets) | Replaces your app's signers with one the user holds | Your app's signers |

<span id="revoke-a-key" />
<span id="revoke-access-keys" />

A configuration update doesn't touch access keys or token approvals. A device key on a lost phone keeps paying within its limits until you [revoke it](/docs/accounts/access-keys/revocation#revoke-after-a-signer-change).

## Watch Changes

Each [configuration update](/docs/development/configurable-accounts#configuration-updates) emits `MultisigConfigUpdated` with the account, its new version, threshold, and signer list. The public indexer doesn't cover the Tempo Accounts devnet. Read the event with Viem's `getContractEvents` from a devnet client. The devnet RPC searches at most 100,000 blocks per request.

```ts [watch-signers.ts]
import { Abis, Addresses } from 'viem/tempo'
import { account } from './account'
import { client } from './client'

const latestBlock = await client.getBlockNumber()

const updates = await client.getContractEvents({ // [!code hl]
  abi: Abis.nativeMultisig,
  address: Addresses.nativeMultisig,
  eventName: 'MultisigConfigUpdated', // [!code hl]
  args: { account: account.address },
  fromBlock: latestBlock - 99_999n,
  toBlock: latestBlock,
  strict: true,
})
// each update's args: { account, salt, version, threshold, owners }
```

## Plan for Recovery

Only the other signers can replace a lost one. When you create the account, choose weights that reach the threshold without any one signer. The test is total weight minus the largest signer's weight. When that's at least the threshold, the account survives losing any one signer.

For example, give a passkey weight 2, and a backup key and a recovery provider's key weight 1 each. Set the threshold to 2. It passes, because 4 minus 2 leaves 2. The two keys together replace a lost passkey. The passkey alone replaces either key. Other [recommended signer setups](/docs/accounts/policies/signing-thresholds#recommended-signer-setups) also pass. On an existing account, [add a recovery signer](/docs/accounts/account-configuration/configuration-updates#add-a-recovery-signer).

A recovery signer can approve payments at its weight too, so give it no more weight than recovery needs.

<span id="recover-funds-sent-on-another-chain" />

### Funds on Other Chains

The account has the same address on other EVM chains. A sender can pay it on the wrong chain by mistake. Those funds can't be retrieved today.

The [specification for configurable account addresses](/docs/development/configurable-accounts#configurable-account-address) defines a recovery factory contract for that chain. With it, the account's original secp256k1 signers could deploy a recovery wallet at the address. That wallet retrieves the funds. Those are standard Ethereum keys, such as KMS or hardware wallet keys. That works if their weights reach the original threshold, even after you remove them on Tempo. No chain has the recovery factory yet.

Passkeys and device keys don't count. Accounts [upgraded in place](/docs/accounts/account-configuration/account-upgrade) don't use the factory. On other chains, their original key still controls the address. To keep the option open, create the account with secp256k1 signers whose weights reach the threshold on their own.
