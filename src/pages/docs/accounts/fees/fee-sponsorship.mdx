# Fee sponsorship

Fee sponsorship lets you pay your customers' network fees, so their accounts don't need any balance for fees. A fee payer, which Tempo hosts or you run, adds its signature to the customer's transaction and pays the fee from its own balance. That signature covers only the fee: the fee payer can't change what the account signed or move its funds.

<span id="sponsor-fees-with-a-fee-payer" />

## How fee sponsorship works

1. The account signs its calls and leaves the fee token blank, so the fee payer can pick it.
2. The fee payer decides whether to sponsor the transaction, picks the fee token, and adds its signature.
3. Tempo verifies both signatures and charges the fee to the fee payer. If either signature fails or the fee payer can't cover the fee, Tempo rejects the transaction.

<span id="what-a-fee-payer-can-and-cant-do" />

The worst a fee payer can do is refuse or delay sponsorship, and the account can then pay its own fee if it holds a fee token.

## Request sponsorship

Route the client through a fee payer with `withRelay`, and set `feePayer: true` on each transaction you want sponsored:

```ts [sponsored-transfer.ts]
import { http, parseUnits } from 'viem'
import { tempoModerato } from 'viem/chains'
import { createClient, withRelay } from 'viem/tempo'

const client = createClient({
  chain: tempoModerato,
  transport: withRelay(http(), http('https://sponsor.moderato.tempo.xyz')),
})

await client.token.transferSync({
  account,
  amount: parseUnits('25', 6),
  feePayer: true, // request sponsorship
  to: recipient,
  token: alphaUsd,
})
```

`sponsor.moderato.tempo.xyz` is Tempo's public fee payer for Moderato testnet and needs no API key. In production, use the hosted [Fee Payer API](/docs/api/fee-payer) with a Tempo API key, or run your own. Try the flow in the [Sponsor fees](/docs/guide/payments/sponsor-user-fees) demo.

## Run your own fee payer

Run a fee payer on your backend with viem's `Relay` and its `Relay.feePayer` plugin. `validate` decides which transactions to sponsor:

```ts [fee-payer.ts]
import type { Hex } from 'viem'
import { privateKeyToAccount } from 'viem/accounts'
import { tempoModerato } from 'viem/chains'
import { createClient, Relay } from 'viem/tempo'

const relay = Relay.create({
  client: createClient({ chain: tempoModerato }),
  plugins: [
    Relay.feePayer({
      account: privateKeyToAccount(process.env.FEE_PAYER_KEY as Hex),
      validate: async (request) => request.from !== undefined && (await isCustomer(request.from)),
    }),
  ],
})

export default { fetch: relay.fetch }
```

Only `true` sponsors the transaction. Any other result refuses it, and the transaction falls back to the account paying its own fee. Without `validate`, the fee payer sponsors every request it receives, so add authentication and rate limits before you fund it.

Fund the fee payer's address with stablecoins, keep its private key on the server, and point clients' `withRelay` at your server's URL instead of the testnet endpoint. If your backend sends the transactions itself, skip the server: pass the same `plugins` to `withRelay(http(), { plugins })` on the backend's client.

## Fee sponsorship limits

- The fee payer pays in the transaction's fee token, or in its [default fee token](/docs/accounts/fees/fee-tokens#set-a-default-fee-token) when that's blank. On your own fee payer, set `feeToken` in `Relay.feePayer` to the [supported fee token](/docs/accounts/fees/fee-tokens#supported-fee-tokens) you fund it with.
- A sponsored transaction that's included and then fails still costs the fee payer its fee.

Specification: [fee payer](/docs/protocol/fees/spec-fee#fee-payer).
