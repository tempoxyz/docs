# Fee sponsorship

Fee sponsorship lets you pay your customers' network fees, so their accounts don't need any balance for fees. A fee payer, which you run or Tempo hosts, adds its signature to the customer's transaction and pays the fee from its own balance. That signature covers only the fee: the fee payer can't change what the account signed or move its funds.

<span id="sponsor-an-accounts-fees" />
<span id="sponsor-fees-with-a-fee-payer" />

## How fee sponsorship works

1. The account signs its calls and leaves the fee token blank, so the fee payer can pick it.
2. The fee payer decides whether to sponsor the transaction, picks the fee token, and adds its signature.
3. Tempo verifies both signatures and charges the fee to the fee payer. If either signature fails or the fee payer can't cover the fee, Tempo rejects the transaction.

<span id="what-a-fee-payer-can-and-cant-do" />

The worst a fee payer can do is refuse or delay sponsorship, and the account can then pay its own fee if it holds a fee token.

## Run your own fee payer

Your own fee payer is an account whose key stays on your backend, funded with stablecoins. Pass it as `feePayer` on each transaction you sponsor. `client.ts` connects to the Tempo Accounts devnet ([set up the devnet key](/docs/accounts/create#connect-to-the-devnet)).

```ts [client.ts]
// [!include ~/snippets/accounts-devnet.ts:client]
```

In `sponsored-transfer.ts`, `account` is the paying account with the keys that approve the payment attached, such as the account from [Create an account](/docs/accounts/create#create-an-account-from-a-signing-key) or an [access key](/docs/accounts/access-keys) your backend holds for it, and `recipient` is the payee's address:

```ts [sponsored-transfer.ts]
import { parseUnits } from 'viem'
import { Account } from 'viem/tempo'
import { client } from './client'

const alphaUsd = '0x20c0000000000000000000000000000000000001' // AlphaUSD, a devnet test stablecoin

// Keep the fee payer's private key on your server.
const feePayer = Account.fromSecp256k1(process.env.FEE_PAYER_KEY as `0x${string}`)
await client.faucet.fundSync({ account: feePayer.address }) // devnet test stablecoins for its fees

await client.token.transferSync({
  account, // needs AlphaUSD for the payment, none for the fee
  amount: parseUnits('25', 6),
  feePayer, // signs only for the fee, and pays it
  feeToken: alphaUsd, // the fee payer's choice: the token being transferred
  to: recipient,
  token: alphaUsd,
})
```

Your backend decides what to sponsor: the fee payer pays for every transaction your code passes it to, so authenticate and rate-limit the requests that trigger one.

## Use Tempo's hosted fee payer

When the customer's device signs the transaction, a hosted fee payer can add the second signature. Route the client through it with `withRelay`, and set `feePayer: true` on each transaction you want sponsored. Tempo's public fee payer runs on Moderato testnet, not on the Tempo Accounts devnet, so this example sends from a single-key account (EOA) on Moderato, whose RPC needs no key:

```ts [hosted-sponsored-transfer.ts]
import { http, parseUnits } from 'viem'
import { tempoModerato } from 'viem/chains'
import { createClient, withRelay } from 'viem/tempo'

const alphaUsd = '0x20c0000000000000000000000000000000000001' // AlphaUSD, a testnet stablecoin

const client = createClient({
  chain: tempoModerato,
  transport: withRelay(http(), http('https://sponsor.moderato.tempo.xyz')),
})

await client.token.transferSync({
  account, // a single-key account on Moderato
  amount: parseUnits('25', 6),
  feePayer: true, // request sponsorship
  to: recipient,
  token: alphaUsd,
})
```

`sponsor.moderato.tempo.xyz` is Tempo's public fee payer for Moderato testnet and needs no API key. In production, use the hosted [Fee Payer API](/docs/api/fee-payer) with a Tempo API key. Try the flow in the [Sponsor fees](/docs/guide/payments/sponsor-user-fees) demo.

## Fee sponsorship limits

- The fee payer pays in the transaction's `feeToken`, or in its own [default fee token](/docs/accounts/fees/fee-tokens#set-a-default-fee-token) when that's blank. Fund it with that [supported fee token](/docs/accounts/fees/fee-tokens#supported-fee-tokens).
- On the Tempo Accounts devnet, set `feeToken` to the token a sponsored transfer moves. With another fee token, or none, the transfer can run out of gas.
- A sponsored transaction that's included and then fails still costs the fee payer its fee.

Specification: [fee payer](/docs/protocol/fees/spec-fee#fee-payer).
