# Fee sponsorship

A fee payer pays another account's network fees, so the account needs no fee balance, such as a new customer sending their first payment right after sign-in. The fee payer's signature authorizes only the fee: it holds no signer or access key and can't move the account's funds.

## How fee sponsorship works

The account signs its calls with the fee token left blank. The fee payer checks the transaction against its own policy, chooses the fee token, and adds its signature. Tempo verifies both signatures and takes the fee from the fee payer's balance. If either signature is invalid or the fee payer's balance falls short, the transaction is invalid.

To request sponsorship, point the client's relay at a fee payer and mark each sponsored transaction with `feePayer: true`:

```ts [client.ts]
import { http, parseUnits } from 'viem'
import { tempoModerato } from 'viem/chains'
import { createClient, withRelay } from 'viem/tempo'

export const client = createClient({
  chain: tempoModerato,
  transport: withRelay(http(), http('https://sponsor.moderato.tempo.xyz')),
})

await client.token.transferSync({
  account,
  amount: parseUnits('25', 6),
  feePayer: true, // request sponsorship
  to: recipient,
  token: alphaUsd,
})
```

The endpoint above is the public fee payer on Moderato testnet and needs no API key. In production, use the hosted [Fee Payer API](/docs/api/fee-payer) with a Tempo API key, or run your own. [Sponsor fees](/docs/guide/payments/sponsor-user-fees) walks through the full flow with a live demo.

## Run your own fee payer

Anyone can run a fee payer: you, your wallet provider, or another operator. Host one with viem's `Relay` and its `Relay.feePayer` plugin, funded with the stablecoins it pays fees in. Its `validate` callback receives each transaction request and decides whether to sponsor it:

```ts [fee-payer.ts]
import { http, type Hex } from 'viem'
import { privateKeyToAccount } from 'viem/accounts'
import { tempoModerato } from 'viem/chains'
import { createClient, Relay, withRelay } from 'viem/tempo'

const plugins = [
  Relay.feePayer({
    account: privateKeyToAccount(process.env.FEE_PAYER_KEY as Hex),
    validate: async (request) => request.from !== undefined && (await isCustomer(request.from)),
  }),
]

export const client = createClient({
  chain: tempoModerato,
  transport: withRelay(http(), { plugins }),
})
```

Only `true` sponsors the transaction. `false`, or a named reason such as `'spend_limit_exceeded'`, refuses it, and the relay returns the transaction for the account to pay itself. Without `validate`, the fee payer sponsors every request it receives, so add authentication and rate limits before you fund it.

To serve the fee payer to other clients, pass the same plugins to `Relay.create({ client, plugins })` and serve `relay.fetch`. When the relay also runs `Relay.accounts`, list `Relay.accounts` first.

## What a fee payer can and can't do

The fee payer's signature covers one specific transaction and authorizes only its fee:

| A fee payer can | A fee payer can't |
| --- | --- |
| Pay the fee from its own balance | Approve a transaction or count toward the account's threshold |
| Choose the fee token for transactions it sponsors | Change the calls the account signed |
| Refuse or delay sponsorship | Move the account's funds |

Because the fee payer holds no signer or access key, a fee payer that stops working can delay transactions but can't take funds. The account can still pay its own fees when it holds a fee token.

## Fee sponsorship limits

- The fee payer pays from its own balance in the fee token it chooses, so keep it funded in a token with [Fee AMM](/docs/protocol/fees/spec-fee-amm) liquidity.
- A sponsored transaction that's included and then reverts still costs the fee payer its fee.
- The fee payer's default fee token applies to every transaction it sponsors, unless it sets `feeToken`. See [Fee tokens](/docs/accounts/fees/fee-tokens).
