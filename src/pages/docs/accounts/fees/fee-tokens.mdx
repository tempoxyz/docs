# Fee tokens

A fee token is the USD stablecoin a transaction pays its network fee in.

A Tempo account needs no separate gas token for fees. Set the account's default fee token once, and override it on any transaction that should pay in another stablecoin. On mainnet, use [OUSD](/docs/guide/ousd) for most accounts.

<span id="fee-token-limits" />

## Supported fee tokens

Before a transaction runs, Tempo checks its fee token:

- It's a [TIP-20 token](/docs/protocol/tip20/overview), Tempo's token standard, whose currency is USD.
- The account paying the fee holds enough of it to cover the maximum fee: the gas limit times the gas price.
- If the block's validator wants its fees in a different stablecoin, the [Fee AMM](/docs/protocol/fees/spec-fee-amm), Tempo's built-in exchange pools, has enough liquidity to convert it.

If any check fails, the transaction is invalid and isn't included. Tempo doesn't try another token.

<span id="set-an-accounts-default-fee-token" />

## Set a default fee token

The default covers every transaction the account pays the fee for, including ones it sponsors for other accounts as a [fee payer](/docs/accounts/fees/fee-sponsorship). Without one, Tempo follows the [fee token precedence](/docs/accounts/fees#fee-token-precedence), which can fall back to pathUSD, a stablecoin the account might not hold.

In the code, `account` is a funded configurable account from [Create an account](/docs/accounts/create#create-an-account-from-a-signing-key). Configurable accounts run only on the Tempo Accounts devnet, so `client.ts` connects to it ([set up the devnet key](/docs/accounts/create#connect-to-the-devnet)), and the examples pay fees in the devnet faucet's test stablecoins. A single-key account on mainnet or testnet sets and overrides its fee token the same way, with that network's stablecoins, such as [OUSD](/docs/guide/ousd) on mainnet.

::::code-group

```ts [set-fee-token.ts]
import { client } from './client'

// A test stablecoin on the devnet
const otherStablecoin = '0x20c0000000000000000000000000000000000002'

const { receipt } = await client.fee.setUserTokenSync({ // [!code hl]
  account, // [!code hl]
  token: otherStablecoin, // [!code hl]
  // pays this transaction's own fee in the same stablecoin // [!code hl]
  feeToken: otherStablecoin, // [!code hl]
}) // [!code hl]
```

```ts [client.ts]
// [!include ~/snippets/accounts-devnet.ts:client]
```

::::

This calls `setUserToken` on the FeeManager, Tempo's built-in fee contract. Pass `feeToken` as well: before the default exists, this transaction's own fee can otherwise fall back to pathUSD. Read the current default with `client.fee.getUserToken({ account: account.address })`, which returns `null` until one is set. [`fee.setUserToken`](https://viem.sh/tempo/actions/fee.setUserToken) lists the action's other options.

The default outranks the token being transferred. With OUSD as the default, a transfer of another stablecoin still pays its fee in OUSD, and is invalid if the account's OUSD can't cover it.

## Override the fee token per transaction

Pass `feeToken` to pay one transaction's fee in a different stablecoin. It outranks the default and every other rule, for that transaction only. Here the account sends one stablecoin to `recipient`, the payee's address, and pays the fee in another stablecoin:

```ts [transfer.ts]
import { parseUnits } from 'viem'
import { client } from './client'

// Two test stablecoins on the devnet
const stablecoin = '0x20c0000000000000000000000000000000000001'
const otherStablecoin = '0x20c0000000000000000000000000000000000002'

await client.token.transferSync({
  account,
  amount: parseUnits('25', 6),
  // this transaction's fee token
  feeToken: stablecoin, // [!code hl]
  to: recipient,
  token: otherStablecoin,
})
```

On a transaction sent through a fee payer server, the account leaves the fee token blank and the server picks it. When your backend sponsors the transaction itself, set `feeToken` to the token being transferred; see [Fee sponsorship limits](/docs/accounts/fees/fee-sponsorship#fee-sponsorship-limits).

[Choose a fee token](/docs/guide/payments/pay-fees-in-any-stablecoin) has a browser demo of a per-transaction fee token, and shows both calls in Wagmi, Rust, Python, Go, and Cast.

Specification: [fee token preferences](/docs/protocol/fees/spec-fee#fee-token-preferences).
