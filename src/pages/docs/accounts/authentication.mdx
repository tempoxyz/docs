# Signing methods

A signing method is the kind of key that approves a Tempo account's transactions: a private key, a device key, or a passkey. Choose each key by who should hold it: a passkey or device key stays with the customer, while a key on your server or with a wallet provider lets that party sign too.

## Choose a signing method

| Method | Where the key lives | Use it for | Main limit |
| --- | --- | --- | --- |
| [Private keys](/docs/accounts/authentication/private-keys) | A wallet, a wallet provider, or your KMS or HSM | Treasury approvers, backup and recovery keys, servers, and scripts | Anyone who can make it sign, including through your KMS, has its full power |
| [Device keys](/docs/accounts/authentication/device-keys) | The customer's phone, computer, or browser, which can't export it | Payments within a spending limit, with no prompt | A browser key is gone if the customer clears site data |
| [Passkeys](/docs/accounts/authentication/passkeys) | Synced across the customer's devices, or on a security key | Customer approvals and signer changes, with Face ID or a fingerprint | Works only on the domain that created it |

## Combine signing methods

Each key joins the account as a signer or an access key. A signer approves with a weight, and a transaction runs once the approving signers' weights reach the account's [threshold](/docs/accounts/policies/signing-thresholds). An [access key](/docs/accounts/access-keys) pays alone within its limits and never counts toward the threshold. Add device keys and server payout keys as access keys: a signer has no spending limit.

Tempo has no override, so your app or a provider can approve only with the signers it holds. Set weights so no one but the customer reaches the threshold alone: [Recommended signer setups](/docs/accounts/policies/signing-thresholds#recommended-signer-setups) gives the weights for customer accounts, embedded wallets, and treasuries. Signers and thresholds run only on Tempo devnet.
