# Signing methods

A signing method is the kind of key that approves an account's transactions: a passkey, a device key, or a private key.

Choose each key by who should hold it. A passkey or device key stays with the customer. A private key on your server or with a wallet provider lets that party sign too. Every method works on mainnet and testnet today, as the one key of a [single-key account](/docs/accounts/how-it-works#address) or as an [access key](/docs/accounts/access-keys).

## How it works

Tempo verifies three kinds of signature onchain:

- **secp256k1.** Ethereum wallets use it.
- **P-256.** Device keys and P-256 private keys use it.
- **WebAuthn P-256.** Passkeys use it.

The kind of key decides where it can live and how the holder approves. Its role on the account decides what it can do.

<span id="combine-signing-methods" />

## Combining methods

Each key joins the account in one of two roles:

| Role | What it does |
| --- | --- |
| Signer | Approves with a weight. A transaction runs once the approving signers' weights reach the account's [threshold](/docs/accounts/policies/signing-thresholds). |
| [Access key](/docs/accounts/access-keys) | Pays alone within its limits. Never counts toward the threshold. |

Add device keys and server payout keys as access keys. A signer has no spending limit.

<ConfigurableAccountsT14 />

Several weighted signers on one account need a configurable account. Tempo has no override. Your app or a provider can approve only with the signers it holds. Set weights so no one but the customer reaches the threshold alone. [Recommended signer setups](/docs/accounts/policies/signing-thresholds#recommended-signer-setups) gives the weights for customer accounts, embedded wallets, and treasuries.
