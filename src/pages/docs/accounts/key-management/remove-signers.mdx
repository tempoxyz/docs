# Remove signers

Removing a signer ends its power to approve when an approver leaves or a key is lost or compromised. The signers that stay approve a new signer list without it, and the account keeps its address, balance, and token approvals. To rotate a key, the same update puts the new key in the old one's place. Signer updates run only on Tempo devnet.

## What removing a signer stops

Once the update lands, the removed signer can't approve anything, and approvals collected under the old signer list stop counting.

<span id="revoke-what-the-old-signer-authorized" />

[Access keys](/docs/accounts/access-keys) keep working. A device key or agent key the removed signer authorized keeps paying within its limits, so after the update, [revoke every key](/docs/accounts/access-keys/revocation#revoke-after-a-signer-change) its holder could reach, including any an attacker added.

## Remove a signer

Load the [saved configuration](/docs/accounts/key-management/add-signers#send-the-signer-update), drop the signer's entry, and approve with signers that stay:

```ts [remove-signer.ts]
import { isAddressEqual } from 'viem'
import { Account } from 'viem/tempo'

const { address, config } = await loadAccount(customerId) // your app's storage
// Before the first signer update, the configuration is version 0 and derives the address.
const account =
  config.version === 0n
    ? Account.fromConfig({ ...config, address: 'infer' })
    : Account.fromConfig({ address, ...config })

const { receipt } = await client.accounts.updateConfigSync({
  account,
  nextConfig: {
    owners: config.owners.filter((entry) => !isAddressEqual(entry.owner, departing)),
    threshold: config.threshold,
  },
  owner: approver, // a signer that stays
})

// receipt.status is 'pending' until approvals reach the threshold, so a second signer approves
// only when `approver` alone doesn't reach it.
if (receipt.status === 'pending')
  await client.sendTransactionSync({ account, hash: receipt.transactionHash, owner: secondSigner })

const updated = await client.accounts.getConfig({ address }) // Relay.accounts recorded it
await saveAccount(customerId, { address, config: updated }) // the next update starts from this
```

`client` is a devnet client with `Relay.accounts` on its transport, as in [Signing thresholds](/docs/accounts/policies/signing-thresholds#collect-approvals).

If the remaining weights fall short of the threshold, lower `threshold` in the same update. [Offboard an approver](/docs/accounts/guides/teams/offboard-an-approver) walks through removing one from a treasury.

## Rotate a key by replacing it in one update

Rotate when the holder stays but the key changes: a new hardware wallet, a new device, or a new wallet provider. Put the new key at the old one's weight and keep the threshold, so every group of signers that could approve before still can:

```ts [rotate-signer.ts]
const { receipt } = await client.accounts.updateConfigSync({
  account,
  nextConfig: {
    owners: config.owners.map((entry) =>
      isAddressEqual(entry.owner, oldSigner) ? { owner: newSigner, weight: entry.weight } : entry,
    ),
    threshold: config.threshold,
  },
  owner: approver, // on a scheduled rotation, the old key can approve
})
```

One update swaps the keys, so the account never has both keys active, or neither.

## Remove a lost or compromised signer

When a signer is lost or compromised, the other signers approve the update without it. Tempo has no recovery service or override, so this works only if their weights still reach the threshold. Check that when you create the account, using the rule in [Plan for recovery](/docs/accounts/key-management#plan-for-recovery).

For example, with a passkey at weight 2 plus a backup key and a recovery provider's key at weight 1 each, at threshold 2, the two keys together approve the [rotation](#rotate-a-key-by-replacing-it-in-one-update) that swaps in a new passkey after the customer loses their phone. [Recover a user's account](/docs/accounts/guides/users/recover-an-account) walks through it.

Treat a compromised signer as an attacker and leave it out of the approvers. If its weight reaches the threshold alone, it can remove your other signers first, so give that much weight only to a key you'd trust with the whole account.

## Limits on removing signers

- The approving signers must reach the current threshold, and the remaining weights must reach the new one, or Tempo rejects the update.
- An account keeps at least one signer.
- `InvalidConfig` means the configuration you sent doesn't match the one Tempo stores, for example because another signer update landed first. Load the latest saved configuration and rebuild the update.
- Until the first update, open the account with `address: 'infer'`; after a signer change, open it from its saved address with `Account.fromConfig({ address, ...config })`.

Specifications: [configuration updates](https://tips.sh/1109), [configurable accounts](https://tips.sh/1107).
