# Add signers

Adding a signer, a key that approves the account's transactions, backs up a key you could lose or lets another person approve. The current signers approve the addition in one signer update, and the address, balance, token approvals, and access keys stay the same. Signer updates run only on Tempo devnet.

<span id="what-adding-a-signer-does" />

## Choose the new signer's weight

The weight you give the new signer decides what it can approve alone. Every signer has a weight of at least 1, and the signers who approve a payment or a signer update need weights that reach the account's threshold:

- Below the threshold, the new signer approves only together with others, so no single backup or recovery signer controls the account.
- At or above the threshold, it approves anything alone, including removing every other signer. Give this weight only to a key you'd trust with the whole account.

The threshold stays the same unless you change it, so each new signer adds a way to reach it. To keep requiring the same approvers, raise the threshold in the same update. [Signing thresholds](/docs/accounts/policies/signing-thresholds#recommended-signer-setups) lists recommended setups.

## Add a recovery signer

A recovery signer lets the remaining signers replace a lost one. Give it enough weight that the account can [lose any one signer](/docs/accounts/key-management#plan-for-recovery) and still reach the threshold, and no more, because it can approve payments at that weight too. [Add a recovery signer](/docs/accounts/guides/users/add-a-recovery-signer) walks through it in a live demo.

## Send the signer update

A signer update replaces the account's whole signer list. Tempo stores only a hash of the configuration, a fingerprint it checks approvals against but can't read back, so your app saves the configuration itself: signers, threshold, salt, and version. Load it, append the new signer, and approve with the current signers:

```ts [add-signer.ts]
import { Account } from 'viem/tempo'

const { address, config } = await loadAccount(customerId) // your app's storage
// Before the first signer update, the configuration is version 0 and derives the address.
const account =
  config.version === 0n
    ? Account.fromConfig({ ...config, address: 'infer' })
    : Account.fromConfig({ address, ...config })

const { receipt } = await client.accounts.updateConfigSync({
  account,
  nextConfig: {
    owners: [...config.owners, { owner: newSigner, weight: 1 }],
    threshold: config.threshold,
  },
  owner: approver, // a current signer
})

// receipt.status is 'pending' until approvals reach the threshold, so a second signer approves
// only when `approver` alone doesn't reach it.
if (receipt.status === 'pending')
  await client.sendTransactionSync({ account, hash: receipt.transactionHash, owner: secondSigner })

const updated = await client.accounts.getConfig({ address }) // Relay.accounts recorded it
await saveAccount(customerId, { address, config: updated }) // the next update starts from this
```

`client` is a devnet client with `Relay.accounts` on its transport, as in [Signing thresholds](/docs/accounts/policies/signing-thresholds#collect-approvals). `newSigner` is the new key's address: a passkey, a device key, a key in a KMS or hardware wallet, or an address from a recovery provider. viem sorts the signers by address, as Tempo requires.

## Limits on adding signers

- An account holds 1 to 48 signers, with total weight at most 255. A transaction carries at most 8 approvals, so the 8 largest weights must reach the threshold.
- The approving signers must reach the current threshold without the new signer.
- `InvalidConfig` means the configuration you sent doesn't match the one Tempo stores, for example because another signer update landed first. Load the latest saved configuration and rebuild the update.
- Until the first update, open the account with `address: 'infer'`; after a signer change, open it from its saved address, as the code does.
- Tempo can't tell whether a signer still holds its key. Have each new signer approve once before you rely on it.

Specification: [configuration updates](https://tips.sh/1109).
