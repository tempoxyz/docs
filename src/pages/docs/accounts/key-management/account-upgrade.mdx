# Account upgrade

An account upgrade adds backup signers to a single-key account, like a standard Ethereum account (an EOA), without changing its address, so a lost key no longer means a lost account. The upgrade is permanent.

:::warning
**Not live yet.** Account upgrade ([TIP-1113](https://tips.sh/1113)) runs only on Tempo devnet, and behavior may change.
:::

## What an upgrade changes

The upgrade gives the account a list of signers, each with a weight, and a threshold: the total weight an approval needs. From then on, signers whose weights reach the threshold approve for the account. The original key approves only if you list it, at its weight. The address, balances, token approvals, nonce, contract storage, and access keys with their limits stay the same.

The original key isn't fully retired: contracts that verify signatures themselves, such as Permit2, may still accept it, and it still controls the address on other EVM chains.

## Choose signers and threshold

List the original key and at least one backup signer, such as a passkey or a recovery key. With both at weight 1 and threshold 1, either key can pay alone and replace the other if it's lost. To require two approvals per payment, use threshold 2 with three signers at weight 1. Whatever you choose, the signers left after losing any one must still reach the threshold ([Plan for recovery](/docs/accounts/key-management#plan-for-recovery)).

Access keys carry over with their limits, so [revoke](/docs/accounts/access-keys/revocation) any you don't want before you upgrade.

## Send the upgrade

The original key signs one transaction whose only call is `upgradeAccount(threshold, owners)` on Tempo's built-in multisig contract. viem 2.57.5 has no upgrade action, so call the contract with `writeContractSync`:

```ts [upgrade.ts]
import { concat, keccak256, parseAbi, toHex } from 'viem'
import { Account, AccountConfig, Addresses } from 'viem/tempo'

const original = Account.fromSecp256k1(process.env.ACCOUNT_KEY as `0x${string}`)

// Sorts the signers by address, as Tempo requires
const { owners, threshold } = AccountConfig.from({
  owners: [
    { owner: original.address, weight: 1 },
    { owner: backupAddress, weight: 1 }, // a passkey or recovery key
  ],
  threshold: 1,
})

await client.writeContractSync({
  account: original,
  address: Addresses.nativeMultisig,
  abi: parseAbi([
    'function upgradeAccount(uint8 threshold, (address owner, uint8 weight)[] owners) returns (bytes32)',
  ]),
  functionName: 'upgradeAccount',
  args: [threshold, owners],
})

// The same address at configuration version 1. Pass `original` itself so it can sign.
const account = Account.fromConfig({
  address: original.address,
  owners: [
    { owner: original, weight: 1 },
    { owner: backupAddress, weight: 1 },
  ],
  salt: keccak256(concat([toHex('tempo:multisig:upgrade'), original.address])), // Tempo derives it from the address
  threshold,
  version: 1n,
})

await saveAccount(customerId, { address: account.address, config: account.config })
```

`client` is a viem client on Tempo devnet, and `saveAccount` stands for your app's storage. [Adding](/docs/accounts/key-management/add-signers) or [removing](/docs/accounts/key-management/remove-signers) signers later starts from the saved configuration. To upgrade every user's account, follow [Migrate existing wallets](/docs/accounts/guides/users/migrate-existing-wallets).

## Account upgrade limits

- Only the original key can sign the upgrade. Access keys can't, but a [fee payer](/docs/accounts/fees/fee-sponsorship) can sponsor it.
- The upgrade must be the transaction's only call, with no `keyAuthorization` and no EIP-7702 authorization list.
- Accounts with contract code, an EIP-7702 delegation, or existing signers can't upgrade.
- Afterward, a direct signature from the original key fails with `RootKeyRetired`. Sign through `Account.fromConfig` instead.
- Upgraded accounts can't [recover funds sent to their address on another chain](/docs/accounts/key-management#recover-funds-sent-on-another-chain).
