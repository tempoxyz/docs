# Create an account

Creating a Tempo account takes no API call and no transaction: your app computes the account's address from its first signer, the key that approves its transactions. Pick a first signer below to create one.

:::warning
**Configurable accounts aren't live yet.** Accounts with several signers and a threshold ([TIP-1107](https://tips.sh/1107)) work only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), not on mainnet or testnet, and may still change. Every account this page creates is a configurable account, even with one signer.
:::

## How account creation works

1. You choose the first signer: a passkey, a device key, or a private key. It approves alone: its weight is 1, and so is the account's threshold, the total weight an approval needs.
2. Your app computes the address from that signer. The address can receive stablecoins right away and stays the same when you change signers or add [access keys](/docs/accounts/access-keys).
3. The account's first transaction, such as a payment, registers it on the [Tempo Accounts devnet](#connect-to-the-devnet). That transaction pays a network fee in a stablecoin, so fund the address first or [sponsor the fee](/docs/accounts/fees/fee-sponsorship).

## Create an account in code

```ts [account.ts]
import { generatePrivateKey } from 'viem/accounts'
import { Account } from 'viem/tempo'

const privateKey = generatePrivateKey() // Keep this secret: it approves the account's transactions.
const signer = Account.fromSecp256k1(privateKey) // [!code hl]
export const account = Account.fromConfig({ address: 'infer', owners: [signer] }) // [!code hl]

// Save account.address and account.config with your user record.
```

`address: 'infer'` tells [`Account.fromConfig`](https://viem.sh/tempo/accounts/account.fromConfig) to compute the address from the signer, which viem calls an owner. You need the saved `account.config` to [add signers](/docs/accounts/key-management/add-signers) later.

For a passkey or device key, use that signer instead: [signing methods](/docs/accounts/authentication) shows each one. To create a second account from the same key, pass a different 32-byte `salt`. On mainnet or testnet, use the signer on its own: it's a [single-key account](/docs/development/single-key-accounts) (EOA), like a standard Ethereum account, whose address comes from its key. If you already have one, [upgrade it in place](/docs/accounts/key-management/account-upgrade) on the devnet to keep its address.

## Connect to the devnet

The Accounts examples connect to the Tempo Accounts devnet, a test network that runs configurable accounts. Its RPC, the endpoint your app sends requests and transactions to, needs a key: [contact Tempo](https://tempo.xyz/contact) for one and set it as the `TEMPO_DEVNET_RPC_KEY` environment variable. The key is a test credential for the devnet, so keep it out of code you commit and out of production apps. In a browser app, read it from your bundler's environment variables instead of `process.env`.

To fund the address, ask the devnet faucet, which sends test stablecoins, including pathUSD:

```ts [fund.ts]
import { account } from './account'
import { client } from './client'

await client.faucet.fundSync({ account: account.address }) // [!code hl]
```
