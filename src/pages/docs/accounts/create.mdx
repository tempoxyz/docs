# Create an account

An account's address comes from its first signer. Nothing to deploy: the address is ready immediately, and the first approved transaction registers the account.

<AccountSandbox />

Every step runs on Tempo devnet. Logins use a local auth service and [salt service](/docs/accounts/authentication/oidc#login-services) on `localhost:5173`.

<span id="try-a-passkey-account" />

## How account creation works

- The first signer (a passkey, login, or key) starts at weight 1 and threshold 1.
- Later signer, weight, and threshold changes keep the same address and balance.
- The address can receive stablecoins before its first transaction.
- The registering transaction is usually a payment that also authorizes the device's [access key](/docs/accounts/access-keys). [Sponsor the fee](/docs/guide/payments/sponsor-user-fees) so a new account needs no balance.

## Choose the first signer

| Account | First signer | Then add |
| --- | --- | --- |
| Embedded wallet | The customer's login in your app: [OIDC](/docs/accounts/authentication/oidc), such as Google, or [Privy](/docs/accounts/authentication/oidc#privy-logins) | A passkey the customer holds, so they can [take the account with them](/docs/accounts/guides/self-custody#hand-off-to-a-self-custodial-wallet) |
| Customer | A login or a passkey | A second signer as backup |
| Company SSO | An SSO login | A passkey or a recovery provider, threshold 2 |
| Treasury | One approver's key | The other approvers, then raise the threshold |
| Backend service | A key in your signing infrastructure | Nothing, or a recovery key |

## Create an account in code

::::code-group

```ts [Login]
import { Account, WebCryptoP256 } from 'viem/tempo'
import { client } from './client'

declare function signIn(options: { nonce: string }): Promise<string>

const keyPair = await WebCryptoP256.createKeyPair()
const { credential } = await client.oidc.prove({ getToken: signIn, publicKey: keyPair.publicKey })
const account = Account.fromConfig({ address: 'infer', owners: [Account.fromZk(credential)] })
```

```ts [Passkey]
import { Account, WebAuthnP256 } from 'viem/tempo'

const passkey = Account.fromWebAuthnP256(await WebAuthnP256.createCredential({ label: 'Acme' }))
const account = Account.fromConfig({ address: 'infer', owners: [passkey] })
```

```ts [Private key]
import { generatePrivateKey } from 'viem/accounts'
import { Account } from 'viem/tempo'

const key = Account.fromSecp256k1(generatePrivateKey())
const account = Account.fromConfig({ address: 'infer', owners: [key] })
```

```bash [CLI]
cast wallet new
```

## Upgrade an existing account

A single-key account moves to signers and a threshold in one transaction, at the same address, balances, token approvals, and access keys. Only the original secp256k1 key or passkey signs the upgrade. The demo and examples run on Tempo devnet.

<UpgradeAccountDemo />

:::::steps

### Choose the signers and threshold

```ts [upgrade.ts]
import { Account, AccountConfig } from 'viem/tempo'

const original = Account.fromSecp256k1(process.env.ACCOUNT_KEY as `0x${string}`)
const { owners, threshold } = AccountConfig.from({
  owners: [
    { owner: original.address, weight: 1 },
    { owner: passkeyAddress, weight: 1 }, // the customer's new passkey
  ],
  threshold: 1,
})
```

`AccountConfig.from` sorts the signers by address, as Tempo requires. Before you upgrade, revoke the access keys you don't want while the original key can do it alone.

### Send the upgrade on its own

```ts [upgrade.ts]
import { parseAbi } from 'viem'

await client.writeContractSync({
  account: original,
  address: '0xAACC000000000000000000000000000000000000',
  abi: parseAbi([
    'function upgradeAccount(uint8 threshold, (address owner, uint8 weight)[] owners) returns (bytes32)',
  ]),
  functionName: 'upgradeAccount',
  args: [threshold, owners],
})
```

The upgrade is permanent and must be the transaction's only call, with no `keyAuthorization` or authorization list.

### Save the account's new configuration

```ts [upgrade.ts]
import { concat, keccak256, toHex } from 'viem'

const account = Account.fromConfig({
  address: original.address,
  owners,
  salt: keccak256(concat([toHex('tempo:multisig:upgrade'), original.address])),
  threshold,
  version: 1,
})
```

Tempo stores only a hash of this configuration, and every approval needs it. The original key now approves only as a listed signer: pass `owner: original`.

:::::

<span id="what-the-upgrade-changes" />

| Error | Cause |
| --- | --- |
| `UpgradeMustBeOnlyCall` | The upgrade wasn't the transaction's only call |
| `PrimitiveRootRequired` | An access key signed instead of the original secp256k1 key or passkey |
| `AccountHasCode` | The account has contract code or an EIP-7702 delegation, so it can't upgrade |
| `AccountAlreadyConfigurable` | The account already has signers. Change them as in [Add a backup signer](/docs/accounts/guides/self-custody#add-a-backup-signer). |
| `InvalidConfig` | The signers aren't sorted by address, or the threshold is out of reach |
| `RootKeyRetired` | The original key signed alone after the upgrade |

Contracts that check signatures themselves, such as Permit2, may still accept the original key, and on other chains it still controls the address. Upgraded accounts can't use [cross-chain recovery](/docs/accounts/guides/self-custody#recover-funds-sent-on-another-chain).
