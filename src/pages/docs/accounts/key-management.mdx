# Key management

Key management lets you add, remove, or replace an account's signers without changing its address.

A Tempo account's signers are the keys that approve its transactions. A configurable account changes them at the same address, so its balance and history survive a lost phone or a departing approver. Only the current signers can approve a change, and Tempo has no override, so [plan for recovery](#plan-for-recovery) before you need it.

:::warning
**Configurable accounts aren't live yet.** Accounts with several signers and a threshold ([TIP-1107](https://tips.sh/1107)) work only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet), not on mainnet or testnet, and may still change. Adding, removing, and replacing signers all need one.
:::

## Every change is one signer update

A signer update replaces the account's whole signer list and its [threshold](/docs/accounts/policies/signing-thresholds), the total weight an approval needs, in one transaction. Signers whose weights reach the current threshold approve it, the same way they approve a payment. Once it lands, a removed signer can't approve anything, and approvals collected before the update stop counting.

What differs between situations is who approves:

| Situation | The update | Who approves |
| --- | --- | --- |
| [Add a backup or recovery signer](/docs/accounts/key-management/signer-updates#add-a-signer) | Adds the new signer | The current signers |
| [Rotate a key](/docs/accounts/key-management/signer-updates#rotate-a-key-by-replacing-it-in-one-update) | Swaps the new key in at the old one's weight | The current signers, including the old key |
| [Replace a lost or compromised signer](/docs/accounts/key-management/signer-updates#remove-a-lost-or-compromised-signer) | Swaps a new signer in for it | The other signers, without it |
| [Offboard an approver](/docs/accounts/custodians/company-treasury) | Removes their signer, and lowers the threshold if needed | The remaining approvers |
| [Hand off to a self-custodial wallet](/docs/accounts/apps/self-custodial-wallets) | Replaces your app's signers with one the user holds | Your app's signers |

A signer update doesn't touch access keys or token approvals, so a device key on a lost phone keeps paying within its limits until you [revoke it](/docs/accounts/access-keys/revocation#revoke-after-a-signer-change).

A single-key account (EOA), like a standard Ethereum account, has no signer list to change, so [upgrade it](/docs/accounts/key-management/account-upgrade) to a configurable account first.

## Watch signer changes

Each signer update emits `MultisigConfigUpdated` with the account, its new version, threshold, and signer list. The public indexer doesn't cover the Tempo Accounts devnet, so read the event with Viem's `getContractEvents` from a devnet client. The devnet RPC searches at most 100,000 blocks per request.

```ts [watch-signers.ts]
import { Abis, Addresses } from 'viem/tempo'
import { account } from './account'
import { client } from './client'

const latestBlock = await client.getBlockNumber()

const updates = await client.getContractEvents({ // [!code hl]
  abi: Abis.nativeMultisig,
  address: Addresses.nativeMultisig,
  eventName: 'MultisigConfigUpdated', // [!code hl]
  args: { account: account.address },
  fromBlock: latestBlock - 99_999n,
  toBlock: latestBlock,
  strict: true,
})
// each update's args: { account, salt, version, threshold, owners }
```

## Plan for recovery

After a signer is lost, only the others can replace it. So when you create the account, choose weights that reach the threshold without any one signer: total weight minus the largest signer's weight must be at least the threshold.

For example, a passkey at weight 2, plus a backup key and a recovery provider's key at weight 1 each, at threshold 2, passes: 4 minus 2 leaves 2. The two keys together replace a lost passkey, and the passkey alone replaces either key. [Recommended signer setups](/docs/accounts/policies/signing-thresholds#recommended-signer-setups) lists others that pass, and [Add a recovery signer](/docs/accounts/key-management/signer-updates#add-a-recovery-signer) adds one to an existing account.

A recovery signer can approve payments at its weight too, so give it no more weight than recovery needs. Tempo can't tell whether a signer still holds its key, so have each new signer approve once before you rely on it.

### Recover funds sent on another chain

The account has the same address on other EVM chains, so a sender can pay it on the wrong chain by mistake. The specification for configurable account addresses defines a way back: a recovery factory contract on that chain. It would let the secp256k1 signers (standard Ethereum keys, such as KMS or hardware wallet keys) you created the account with deploy a recovery wallet at the address and retrieve the funds, if their weights reach the original threshold, even after you remove them on Tempo. No chain has the recovery factory yet, so funds sent to the address on another chain can't be retrieved today.

Passkeys and device keys don't count. Accounts [upgraded in place](/docs/accounts/key-management/account-upgrade) don't use the factory: on other chains, the original key still controls the address. To keep the option open, create the account with secp256k1 signers whose weights reach the threshold on their own.

Specifications: [configurable accounts](https://tips.sh/1107), [configuration updates](https://tips.sh/1109), [configurable account addresses](https://tips.sh/1110).
