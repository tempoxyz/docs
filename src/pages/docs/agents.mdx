# Machine payments

Pay for an API as part of the HTTP request, or charge for your own service. The Machine Payments Protocol (MPP) lets a server request payment and a client retry with payment authorization.

[Pay for an API →](#pay-for-an-api) · [Accept API payments →](#accept-api-payments)

## Pay for an API

Install `mppx` and `viem`, then [configure the payer account](/docs/guide/machine-payments/client#define-the-mpp-payer-account). For the CLI, [connect Tempo Wallet](/docs/cli/wallet#download-the-tempo-wallet-cli). Set `PAID_API_URL` in the CLI or `paidUrl` in TypeScript to the service's endpoint. The [MPP client setup](/docs/network/examples#machine-payment-clients) supplies `Mppx`, `tempo`, and a mainnet Wagmi configuration. These clients pay with real funds unless both client and service use testnet.




::::

The example calls a GET endpoint. Use the method and request body from the service's documentation for other requests. Preview payment terms with `tempo request --dry-run "$PAID_API_URL"` before paying.

## Accept API payments

Configure `mppx` with your payment token, recipient address, and server secret using the [server quickstart](/docs/guide/machine-payments/server). Then protect a route with a fixed price per request:

::::code-group

```ts [Next.js]
export const GET = mppx.charge({ amount: '0.10' })(
  () => Response.json({ data: 'Your paid resource' }),
)
```

```ts [Hono]
app.get('/resource',
  mppx.charge({ amount: '0.10' }),
  (c) => c.json({ data: 'Your paid resource' }),
)
```

::::

Each tab uses the framework-specific `mppx` instance from the server quickstart. `amount` is in the configured token's decimal units. Follow [One-time payments](/docs/guide/machine-payments/one-time-payments) for a complete service.

The server returns a `402 Payment Required` challenge. The client authorizes payment and retries; the server verifies it before returning the resource and receipt. Inspect an endpoint's HTTP challenge without paying:

```bash [API (HTTP)]
curl -i "$PAID_API_URL"
```

The [`WWW-Authenticate` challenge](/docs/guide/machine-payments#mpp-payment-flow) describes the payment terms. A plain cURL request does not sign or pay the challenge. The [payment flow demo](/docs/guide/machine-payments#mpp-payment-flow) shows the complete exchange.

## Payment sessions

Use a session when charges accumulate during service usage. The client funds a payment channel and signs vouchers as it consumes the service, without sending an onchain transaction for every request. With the [Next.js session configuration](/docs/guide/machine-payments/pay-as-you-go), charge per resource:

```ts [Next.js]
export const GET = mppx.session({ amount: '0.01', unitType: 'photo' })(
  () => Response.json({ url: 'https://your-service.example/photo.jpg' }),
)
```

- [Pay-as-you-go payments](/docs/guide/machine-payments/pay-as-you-go) for metered API usage.
- [Streamed payments](/docs/guide/machine-payments/streamed-payments) for charges during a streaming response.
