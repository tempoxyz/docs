# Supported networks and assets

Read the route directory before offering a network or asset in your application. A network being supported does not mean every token, direction, or funding method is available.

## Read the route directory

Click **Try** to read the live directory. Filter by source or destination network and token to narrow the results. This request lists supported routes; it does not create a transfer or request a signature.

<OpenApi.Playground operationId="listRoutes" hideQueryParams anchors={false} />

Public requests use the API's shared rate limit. For authenticated access, see [Routes API access](/docs/routes/transfers#set-up-routes-api-access).

Use the returned source and destination chain/token pairs, funding methods, and amount modes to build the choices in your application. Match tokens by network and contract address, not by symbol alone.

## Check the selected payment

Once the user chooses a pair and amount, [request a quote](/docs/routes/quotes). Availability depends on those inputs and the funding method. Refresh the quote when the user changes them.

Use [transfers](/docs/routes/transfers) when your app can request source-wallet signatures, or [deposit addresses](/docs/routes/deposits) when the sender pays independently.

For current request and response fields, see the [route directory reference](/docs/api/routes/routes). To integrate a bridge directly, see [bridge providers](/docs/ecosystem/bridges).
