# Accept deposits

Give customers a reusable address to fund from an external wallet. Each address routes funds to your chosen Tempo recipient, either from one source network and token or from every supported source in its chain family.

For payments already on Tempo, use [Receive payments](/docs/guide/payments/accept-a-payment). [Virtual addresses](/docs/guide/payments/virtual-addresses) attribute those payments to a shared Tempo balance; they are different from Routes deposit addresses.

<span id="set-up-routes-api-access" />

## Prepare a deposit route

Before the first step, have:

- A backend key with `routes:read` and `routes:write` from [Set up API access](/docs/routes/api-setup). Keep the key on the backend; show customers only the returned funding instructions.
- A route with deposit-address support from [Supported routes](/docs/routes/networks).
- A Tempo recipient, and a refund address for each source chain family.

Each step below has a request builder that generates cURL and TypeScript. To see the flow first, [try a route](/docs/routes/test) and choose **Deposit address**. The [cURL example](/docs/routes/examples/deposits) runs every step from a terminal.

<span id="create-and-monitor-a-deposit-address" />

## Accept a deposit

:::::steps

### Quote the deposit

<OpenApi.Playground operationId="quoteRoutesDepositAddress" anchors={false} />

Include the `recipient` and `refundAddress` you create the address with. Some routes, including those from Ethereum, Polygon, BNB Smart Chain, and Tron, return `quote_not_available` without them.

Show the destination amount and fees as described in [Quotes and fees](/docs/routes/quotes), and refresh expired terms. A quote prices the supplied amount; it does not establish receipt of funds.

<span id="create-a-reusable-address" />

### Create a deposit address

Send the [idempotency key](/docs/routes/api-setup#set-idempotency-keys) you stored for this customer's address.

<OpenApi.Playground operationId="createRoutesDepositAddressV2" anchors={false} />

Set `sourceChain` and `sourceToken` together to accept one source, or omit both to accept every supported source. Save the returned `id` and each `addresses[].address` with your customer record. The response carries no quote terms, so quote the deposit again before showing funding instructions when terms are stale.

<span id="show-the-funding-instructions" />

### Show funding instructions

Display each returned address with the networks and tokens in its `sources`. Check that its status is `active` before inviting deposits. Do not present it as an address for arbitrary assets or networks.

<span id="track-each-deposit" />

### Track deposits

Set `depositAddress` to the returned source-chain address, not its `rda_…` object ID.

<OpenApi.Playground operationId="listRoutesDeposits" anchors={false} />

The response lists deposits in `data`. Follow `nextCursor` for subsequent pages. Read each deposit with `GET /v1/routes/deposits/{id}`.

:::::

## Reconcile delivery and refunds

Save the customer, deposit-address ID, and individual deposit IDs together. The same address can receive multiple deposits, so reconcile each deposit's delivered amount and destination transaction references separately. An active address can receive funds; only a completed deposit confirms delivery to Tempo.

Continue with [Track delivery](/docs/routes/delivery) before crediting a balance or treating a refund as complete. See the [Deposit addresses API reference](/docs/api/routes/deposit-addresses) for the full lifecycle.
