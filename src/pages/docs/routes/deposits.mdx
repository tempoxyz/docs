# Accept deposits

Give customers reusable addresses to fund from an external wallet. Routes delivers each deposit to your chosen Tempo recipient.

For payments already on Tempo, use [Receive payments](/docs/guide/payments/accept-a-payment). [Virtual addresses](/docs/guide/payments/virtual-addresses) attribute those payments to a shared Tempo balance; they are different from Routes deposit addresses.

## Choose a deposit address type

Each deposit address object holds one reusable address per chain family. The source fields decide what it accepts:

| Type | Create with | Accepts | Use when |
| --- | --- | --- | --- |
| Single-source | `sourceChain` and `sourceToken` | One network and token, such as USDC on Base | You show one asset. |
| Universal | Neither field | Supported sources in each family you give a refund address | The customer picks the network. |

Single-source IDs start with `rda_` and universal IDs with `uda_`. Universal addresses cover EVM, Solana, and Tron; Stellar is single-source only.

## Prepare a deposit route

Before the first step, have:

- A backend key with `routes:read` and `routes:write` from [Set up API access](/docs/routes/api-setup). Keep the key on the backend; show customers only the returned funding instructions.
- A route from [Supported routes](/docs/routes/networks) with `capabilities.depositAddress`, or `capabilities.universalDepositAddress` for a universal address.
- A Tempo recipient, and a refund address for each chain family you accept, such as `evm` or `solana`.

Each step below has a request builder that generates cURL and TypeScript. To see the flow first, [try a route](/docs/routes/test) and choose **Deposit address**. The [cURL example](/docs/routes/examples/deposits) runs every step from a terminal.

## Accept a deposit

:::::steps

### Quote the deposit

<OpenApi.Playground operationId="quoteRoutesDepositAddress" anchors={false} />

A quote prices one source. For a universal address, quote the source the customer picks.

Include the `recipient` and `refundAddress` you create the address with. Some routes, including those from Ethereum, Polygon, BNB Smart Chain, and Tron, return `quote_not_available` without them.

Show the destination amount and fees as described in [Quotes and fees](/docs/routes/quotes), and refresh expired terms. A quote prices the supplied amount; it does not establish receipt of funds.

<span id="create-a-reusable-address" />

### Create a deposit address

Send the [idempotency key](/docs/routes/api-setup#set-idempotency-keys) you stored for this customer's address.

<OpenApi.Playground operationId="createRoutesDepositAddressV2" anchors={false} />

Set `refundAddresses` per chain family; a universal address only gets addresses for those families. Set `amount` to a typical deposit in base units. Below the route minimum, creation returns `amount_too_low`.

Save the returned `id`. The response has no quote terms, so [quote](#quote-the-deposit) before showing instructions. Retrying with the same idempotency key and body returns the original response.

<span id="show-the-funding-instructions" />

### Show funding instructions

Show each entry in `addresses` with its `sources`, once its `status` is `active`. Routes doesn't credit or automatically refund funds from an unlisted network or token.

<span id="track-each-deposit" />

### Track deposits

Set `depositAddressId` to the returned `id`. It matches deposits on every address in the object.

<OpenApi.Playground operationId="listRoutesDeposits" anchors={false} />

The response lists deposits in `data`. Follow `nextCursor` for subsequent pages. Read each deposit with `GET /v1/routes/deposits/{id}`. Each deposit's `depositAddressId` is the `rda_…` address that received it.

:::::

## Reconcile delivery and refunds

Save the customer, the deposit address `id`, and individual deposit IDs together. The same address can receive multiple deposits, so reconcile each deposit's delivered amount and destination transaction references separately. An active address can receive funds; only a completed deposit confirms delivery to Tempo.

If a sent deposit doesn't appear, reconcile the object:

<OpenApi.Playground operationId="reconcileRoutesDepositAddressV2" anchors={false} />

Continue with [Track delivery](/docs/routes/delivery) before crediting a balance or treating a refund as complete. See the [Deposit addresses API reference](/docs/api/routes/deposit-addresses) for the full lifecycle.
