# Set up API access

Create a Routes API key, request transfer access, and keep the key on your backend. Every Routes guide after this page assumes this setup.

## Routes API key scopes

| Scope | Allows | How a key gets it |
| --- | --- | --- |
| `routes:read` | Quotes, and transfer and deposit status reads | Selected by default on a new key. |
| `routes:write` | Creating transfers and deposit addresses, and registering source transactions | Tempo adds it when it approves your [access request](#request-routes-access). |
| `data:read` | Reading the [route directory](/docs/routes/networks) with your key, which applies your organization's access policy | Selected by default on a new key. |

Routes runs on mainnet, so use a production key. Sandbox keys can't create live routes.

The route directory also accepts requests without a key at the [public rate limit](/docs/api/rate-limits). The Routes API key authenticates your application; it doesn't sign blockchain transactions.

## Request Routes access

Tempo reviews each request and adds `routes:write` to the keys you choose. Any member of your organization can send one from Tempo Console. Each project has at most one pending request.

:::::steps

### Create a production key

[Create an API key](/docs/api/console/api-keys#create-an-api-key) in the project that will call Routes. Creating a key needs the admin or owner role. The new-key form shows `routes:write` as **Requires Tempo approval**, so the key starts with `routes:read` and `data:read`.

You can request access before the project has a key. Tempo can grant access to keys you create later.

### Open the request form

In [Tempo Console](https://console.tempo.xyz/?to=/:org/routes), select **Routes** and choose the project. On the **Routes access** card, select **Request access**. The card shows **Exit sandbox** instead when you're in sandbox.

### Describe what you need

The **Request Routes access** form asks for:

- **Keys.** The production keys that should create transfers. Keys with `routes:read` start selected.
- **Routes.** The source and destination pairs your application needs. Leave the list empty if you're not sure, and Tempo follows up.
- **Expected monthly volume.** An estimate, such as `$50k across 2,000 transfers`.
- **1:1 delivery.** Whether recipients receive the full amount sent. See [Offer 1:1 delivery](/docs/routes/quotes#offer-11-delivery).
- **Notes.** Your use case, launch date, or questions.

Select **Send request**.

### Check the request status

The **Create transfers** row on the **Routes access** card shows where the request stands:

| Status | Card shows | What to do |
| --- | --- | --- |
| Pending | **Request sent** with the date | Wait for review. Select **Cancel request** to withdraw it; a sent request can't be edited. |
| Declined | **Your last request was declined**, with Tempo's reason when given | Address the reason, then send a new request. |
| Approved | **Ready.** The card hides once the project has keys with `routes:read` and `routes:write`. | Start building. |

:::::

Approval saves your organization's route policy, which sets the routes your keys can use and any 1:1 delivery terms. Tempo then adds `routes:write` to the keys you chose. Read the [route directory](/docs/routes/networks) with your key to see the routes your policy allows.

To add routes later, open **Routes** › **Available routes** and select **Request a route**. It opens the same form. The [Routes access requests endpoints](/docs/api/routes-access-requests) behind this form authenticate with your Console session, not an API key.

## Resolve Routes access errors

The Routes API returns HTTP `403` with one of these codes when a key or organization lacks access:

| Code | Cause | Fix |
| --- | --- | --- |
| `api_key_forbidden` | The key lacks a scope named in the message, or it's a sandbox key. | Use a production key with that scope. For `routes:write`, [request access](#request-routes-access). |
| `routes_not_allowed` | Your organization's policy doesn't include this route or funding method. | Select **Request a route** in Tempo Console. |
| `routes_subsidy_not_enabled` | The request sent `subsidize: true` without approved 1:1 terms. | Ask for 1:1 delivery in your access request, or quote without `subsidize`. |
| `routes_subsidy_not_allowed` | This route isn't eligible for the requested subsidy. | Quote without `subsidize`. |
| `billing_required`, `billing_past_due` | 1:1 delivery that your organization pays for needs active billing. | [Add a payment method](/docs/api/console/usage-and-billing#add-a-payment-method) in Billing. |
| `routes_suspended` | New routes are paused for your organization and environment. | [Contact Tempo](https://tempo.xyz/contact). |

## Configure the client

Set `TEMPO_API_KEY` in your environment. TypeScript uses Node.js with built-in `fetch`; Python uses `requests` (`python -m pip install requests`); cURL examples require `curl` and `jq`.

::::code-group

```ts [TypeScript (fetch)]
const api = 'https://api.tempo.xyz/v1'
const headers = {
  'tempo-api-key': process.env.TEMPO_API_KEY!,
  'Content-Type': 'application/json',
}
```

```python [Python (requests)]
import os
import requests

api = "https://api.tempo.xyz/v1"
headers = {
    "tempo-api-key": os.environ["TEMPO_API_KEY"],
    "Content-Type": "application/json",
}
```

```bash [cURL (API)]
# Set TEMPO_API_KEY in your terminal's environment before running requests.
curl --fail-with-body 'https://api.tempo.xyz/v1/routes' \
  --header "tempo-api-key: $TEMPO_API_KEY"
```

::::

Each request builder in the flow guides generates cURL and TypeScript for its endpoint with these headers.

## Set idempotency keys

Create requests require an `idempotency-key` header. Assign one key per operation, such as one payment or one customer's deposit address, and store it with that record before sending the request:

::::code-group

```ts [TypeScript (fetch)]
const requestKey = crypto.randomUUID() // Persist with your payment record.
```

```python [Python (requests)]
import uuid

requestKey = str(uuid.uuid4())  # Persist with your payment record.
```

```bash [cURL (API)]
# Choose and retain one key per operation, including across retries.
ROUTE_REQUEST_KEY="my-payment-001"
```

::::

Reuse the key when you retry the same request with unchanged inputs. Matching requests replay the successful response for 24 hours; a request with changed inputs conflicts. Use a new key for a new operation.

Continue with [Supported routes](/docs/routes/networks) to choose a pair, then [Quotes and fees](/docs/routes/quotes).
