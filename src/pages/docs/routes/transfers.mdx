# Make a transfer

Move stablecoins when your application can authorize the source transaction through a wallet or its own signer. Routes prepares the source calls; your application signs them and tracks delivery.

<span id="set-up-routes-api-access" />

## Prepare a transfer route

Before the first step, have:

- A backend key with `routes:read` and `routes:write` from [Set up API access](/docs/routes/api-setup).
- A route with transfer support from [Supported routes](/docs/routes/networks). This guide fixes the source amount with `exactSource`, so check that the route lists that mode.
- A signer for the sender account on the source network, such as a connected wallet or your own signing service. The Routes API key does not authorize that account.

Each step below has a request builder that generates cURL and TypeScript. To see the flow first, [try a route](/docs/routes/test). The [cURL example](/docs/routes/examples/transfers) runs every step from a terminal.

## Transfer funds

:::::steps

### Get a quote

<span id="quote-the-transfer" />

<OpenApi.Playground operationId="quoteRoutesTransfer" anchors={false} />

A quote prices the request; it does not reserve or create a transfer.

<span id="review-fees" />

Show the source amount, destination amount, minimum destination amount, and fees as described in [Quotes and fees](/docs/routes/quotes). Refresh the quote when `quote.expiresAt` passes.

### Create the transfer

Send the [idempotency key](/docs/routes/api-setup#set-idempotency-keys) you stored for this payment.

<OpenApi.Playground operationId="createRoutesTransfer" anchors={false} />

Save the returned transfer `id` and retain its unsigned `action`. Review the returned terms before requesting a signature. Transfer reads do not return the executable action.

<span id="sign-and-submit-the-source-calls" />

### Sign and submit

Use the source account's signer to submit the returned calls in order. Calls can include approvals and may require separate transactions. Handle the returned `action.type` using the [EVM or Tron action format](/docs/api/routes/transfers).

For an `evm:calls` action, pass each call's `to`, `data`, and `value` to your source-chain wallet client. Wait for successful execution before the next call, and retain all hashes as `transactionHashes`. If submission stops partway through, inspect the transactions already sent before resuming.

On Tempo, [Tempo Wallet](/docs/accounts/guides/users/self-custodial-wallets#connect-tempo-wallet) submits every call as one atomic transaction, so the sender signs once. [Try a route](/docs/routes/test) to compare both paths.

### Register the source transactions

Enter the transfer `id` from creation and the actual `transactionHashes` produced by your signer. Use `transactionHash` instead when there is only one source transaction.

<OpenApi.Playground operationId="registerRoutesTransferSourceTransaction" anchors={false} />

The API verifies and associates the hashes with the transfer.

<span id="track-destination-delivery" />

### Confirm the transfer

<OpenApi.Playground operationId="getRoutesTransfer" anchors={false} />

Keep the payment pending until `status` is `completed`. Reconcile the delivered amount and destination transaction references.
