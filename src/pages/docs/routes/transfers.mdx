# Make a transfer

Use a transfer when your application can authorize transactions from the source account, through its own signing infrastructure, a wallet provider, or a connected wallet. The same flow supports transfers into or out of Tempo, subject to the [supported networks and assets](/docs/routes/networks).

Routes prepares the source-chain calls for the account's signer to sign and submit.

## Set up Routes API access

Create a project and API key in [Tempo Console](/docs/api/console). For this flow, use `routes:read` for quotes and status reads and `routes:write` to create transfers and register source transactions. Authenticated route-directory reads also require `data:read`. Keep the key on your backend; see [API authentication](/docs/api/authentication).

Routes endpoints use the `https://api.tempo.xyz/v1` base URL. Send your key in the `tempo-api-key` header.

## Submit and track a transfer

:::::steps

### Quote the transfer

Call `GET /v1/routes/transfers/quote` with the source and destination chains, tokens, sender, recipient, and amount. Choose whether to specify the source amount or requested destination amount, as described in [Quotes and fees](/docs/routes/quotes#choose-which-amount-to-fix).

Review the returned source amount, destination amount, minimum destination amount, fees, and `quote.expiresAt`. A quote does not create or reserve a transfer.

### Create the transfer

Call `POST /v1/routes/transfers` with the selected parameters and an `idempotency-key`. Save the returned transfer `id` and unsigned `action`, and review the returned terms before requesting a signature. Transfer reads do not return the executable action.

### Sign and submit the source calls

Use the source account's signer to sign and submit the returned calls in order. An action can include approval calls as well as the call that starts the route, and may require separate transactions. Handle the returned `action.type` for the source chain.

### Register the source transactions

Call `POST /v1/routes/transfers/{id}/source-transactions` with `transactionHash` for one transaction or `transactionHashes` for multiple transactions produced by the prepared calls. The API verifies and associates them with the transfer.

### Track destination delivery

Read `GET /v1/routes/transfers/{id}` until the transfer reaches `completed`. Save the source and destination transaction references with your payment record. For refunds or other outcomes, follow [Track delivery](/docs/routes/delivery).

:::::

See the [Transfers API reference](/docs/api/routes/transfers) for request schemas, action formats, and response fields.
