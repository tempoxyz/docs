# QuickNode on Tempo

QuickNode provides managed HTTP and WebSocket RPC endpoints for Tempo mainnet. Use an endpoint to read payment activity and broadcast transactions prepared by your wallet. Its [Tempo API overview](https://www.quicknode.com/docs/tempo/api-overview) lists archive access and supported RPC APIs; confirm the exact network and method before integrating.

## What QuickNode supplies for Tempo

| Capability | Integration use |
| --- | --- |
| JSON-RPC reads | Query supported block, log, state, transaction, and receipt methods. |
| Transaction submission | Broadcast a signed transaction; account control and signing remain with your application or wallet. |
| WebSocket access | Subscribe to supported chain events through a persistent connection. |
| Historical inspection | Use the documented archive, Debug, and Trace methods for the historical state or execution data you need. |

Archive availability, historical-state reads, and a particular debug or trace call are separate requirements. Check the method's documentation and behavior with your endpoint. QuickNode also lists Streams and Webhooks for Tempo; evaluate those products separately from raw RPC access.

## Configure the endpoint and client

:::::steps

### Create a Tempo endpoint

Follow the [QuickNode Tempo quickstart](https://www.quicknode.com/docs/tempo/quickstart). Create an account, select Tempo in the endpoint setup, choose the intended network, and retrieve the provider URL. Treat authenticated endpoint URLs as credentials.

### Verify the network identity

Match the endpoint to [Tempo's current network details](/docs/quickstart/connection-details). Mainnet uses chain ID `4217`; current Moderato testnet uses `42431`.

QuickNode's API overview currently lists a testnet chain ID of `42429`, which differs from current Moderato. Confirm a Moderato endpoint with QuickNode before using it for that network; do not assume an endpoint labeled testnet has the required chain ID.

Replace `<QUICKNODE_TEMPO_HTTP_URL>` with your HTTP endpoint and run this read-only network check:

```bash [Terminal]
curl --fail --silent --show-error '<QUICKNODE_TEMPO_HTTP_URL>' \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'
```

Expect `result: "0x1079"` for mainnet or `result: "0xa5bf"` for current Moderato. Stop if the result differs from the intended network. A matching chain ID confirms network identity, not support for every historical or diagnostic method.

### Connect the signing and payment flow

Use [Tempo SDK setup](/docs/sdk) for the application's client and [Send payments](/docs/guide/payments/send-a-payment) for signing and submission. Match the token contract, fee configuration, and account to the endpoint's network.

:::::

## Choose HTTP or WebSocket access

QuickNode's [endpoint documentation](https://www.quicknode.com/docs/tempo/endpoints) describes both transports. HTTP fits request-and-response reads and submissions; WebSockets support persistent event subscriptions.

WebSocket responses have size limits. For large responses, QuickNode recommends HTTP POST requests. Bound historical log ranges and retain progress so interrupted reads can resume. Method credit costs and rate limits depend on the selected plan and request type; account for both in traffic estimates.

## Preserve payment and historical-data correctness

An RPC provider does not create customer wallets or decide whether a business payment is approved. Keep signing permissions and application approvals separate from endpoint access.

Use the [receiving guide](/docs/guide/payments/accept-a-payment) to verify the delivered token, recipient, amount, network, and successful transfer. A transaction can succeed while a receive policy holds funds instead of crediting the intended recipient.

For event ingestion, keep a historical checkpoint and a unique event key comprising the network, transaction hash, and transfer log index. Recover missed activity after disconnects. Inspect an unresolved submission before resending it; a timeout does not prove payment failure.

## QuickNode questions

### Do I need to run my own Tempo node?

No. A managed QuickNode endpoint supplies network access. Your application still operates signing, payment verification, and recovery from interrupted requests.

### Can I use WebSockets?

Yes. QuickNode documents Tempo WebSocket endpoints. Confirm the subscription method and response-size limits required by your application.

### Does QuickNode provide historical Tempo data?

Its API overview lists mainnet archive access and Debug and Trace APIs. Confirm the exact method and historical range rather than assuming every diagnostic request is supported.

### Can I use the documented testnet entry for current Moderato?

Verify the endpoint first. The overview's listed testnet chain ID differs from Tempo's current Moderato chain ID. Use current Tempo network details and provider confirmation before sending test transactions.
