# Elliptic on Tempo

Use Elliptic to assess Tempo wallet exposure, monitor stablecoin payments, and trace fund flows during investigations. Elliptic documents these capabilities for Tempo, including historical and current data for case review. Confirm product access and the API inputs for your account before integrating.

## Elliptic capabilities for Tempo

Elliptic's [Tempo integration announcement](https://www.elliptic.co/newsroom/elliptic-integrates-with-tempo-the-payments-first-blockchain/) describes:

- Wallet screening for exposure to sanctions and illicit activity.
- Stablecoin transaction monitoring on Tempo.
- Cross-chain fund tracing between Tempo and other supported blockchains.
- Historical and current data for investigations and case management.

Use the capability that matches the decision you need to make. An address check before payment, monitoring activity over time, and investigating a transfer require different inputs and operating processes. Confirm the relevant product, endpoint, and supported asset identifiers with Elliptic.

## Prepare Elliptic API access

Elliptic's [authentication guide](https://developers.elliptic.co/docs/authentication-1) requires an API key and secret for authenticated requests. Its signing process uses the request timestamp, method, path, and body. Follow the maintained guide or SDK rather than adapting a request signature from another provider. The instructions for generating keys require an Elliptic login.

The [single-analysis reference](https://developers.elliptic.co/reference/analysissync) requires a subject, analysis type, and `customer_reference`. Confirm the current subject schema and the network and asset identifiers for the Tempo activity you intend to analyze. The reference documents errors for unauthenticated or unauthorized requests, missing subjects, and rate limits; handle those outcomes separately from a completed analysis.

## Select the analysis direction

For transaction analyses, the documented directions answer different questions:

| Analysis type | Exposure it examines |
| --- | --- |
| `source_of_funds` | Entities that contributed funds to the transaction's source address. |
| `destination_of_funds` | Entities that received funds from the transaction's destination address. |

Choose the direction that fits your deposit, withdrawal, or investigation workflow. Do not interpret one direction's result as a complete assessment of both sides of a payment.

## Connect an analysis to your payment workflow

:::::steps

### Identify the subject and customer reference

Prepare the address or transaction you need analyzed and the internal customer reference. Confirm that Elliptic supports that subject on the selected network.

### Request and review the analysis

Use authenticated requests and the current endpoint schema. Map the returned findings to your review thresholds, escalation process, and rules for stale or unavailable results.

### Preserve the decision record

Keep the analysis time, findings, internal payment reference, and decision together. Route cases requiring investigation to the tools and staff responsible for that workflow.

:::::

Elliptic supplies risk information. Your organization decides whether to process a payment and remains responsible for its customer checks and applicable obligations. An analysis does not automatically update Tempo's [token permissions or receive policies](/docs/resources/guides/compliance-controls).

## Elliptic integration questions

### Does Elliptic support Tempo?

Yes. Elliptic documents Tempo address screening, stablecoin transaction monitoring, cross-chain tracing, and historical and current data for investigations. Confirm the product and endpoint required by your integration.

### What do I need for API authentication?

You need an Elliptic API key and secret and must authenticate requests using the provider's current signing guidance or SDK. Keep credential handling within the environment authorized for your integration.

### Does a missing subject mean the payment passed screening?

No. The analysis reference documents a separate error when the requested subject is not found on the selected blockchain. Resolve the subject, coverage, or request issue before treating it as an assessed payment.
