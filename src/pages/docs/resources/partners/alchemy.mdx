# Alchemy on Tempo

Alchemy provides hosted HTTP and WebSocket RPC endpoints for Tempo mainnet and Moderato testnet. Use them to read chain data and submit transactions signed by your application or wallet without operating a node. Start with [Alchemy's Tempo network page](https://www.alchemy.com/rpc/tempo) and the [Tempo network details](/docs/quickstart/connection-details).

## What Alchemy supplies for Tempo

| Capability | How it fits a payment integration |
| --- | --- |
| Chain reads | Read blocks, contract state, transactions, and receipts through supported JSON-RPC methods. |
| Transaction submission | Broadcast a signed transaction to the matching Tempo network. Signing authority remains with your wallet or application. |
| WebSocket subscriptions | Observe supported chain activity, then recover missed records after an interruption. |

Alchemy lists RPC, WebSockets, and Debug API support on its Tempo mainnet page. Check the specific method and account access before depending on a debugging operation. Other Alchemy products have separate chain-support requirements; a Tempo RPC endpoint does not establish Token API, Transfers API, Gas Manager, or webhook availability.

## Configure an Alchemy connection

:::::steps

### Create an application and obtain access

Use the [Alchemy dashboard](https://dashboard.alchemy.com/) to obtain an API key. Keep authenticated endpoint URLs out of public logs and source control. Apply the access controls appropriate to the application that uses the endpoint.

### Match the endpoint to the Tempo network

Choose the mainnet or Moderato endpoint and configure the client for the same network. Tempo mainnet uses chain ID `4217`; Moderato uses `42431`. Mainnet and testnet have separate assets and transaction histories.

Replace `<ALCHEMY_TEMPO_HTTP_URL>` with the HTTP endpoint from your dashboard and run this read-only network check:

```bash [Terminal]
curl --fail --silent --show-error '<ALCHEMY_TEMPO_HTTP_URL>' \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'
```

The response's `result` must be `0x1079` for mainnet or `0xa5bf` for Moderato. Stop and correct the endpoint or client configuration if it differs. This verifies network identity; it does not verify every RPC method or product entitlement.

### Validate reads before submitting a payment

Alchemy's [Tempo quickstart](https://www.alchemy.com/docs/reference/tempo-api-quickstart) demonstrates Viem chain reads. Use the current [Tempo SDK setup](/docs/sdk) and [network details](/docs/quickstart/connection-details) for Tempo-specific configuration, then follow [Send payments](/docs/guide/payments/send-a-payment) for signing and submission.

:::::

## Read stablecoin balances and verify delivery

Read spendable balances from the relevant TIP-20 token contract. Tempo's `eth_getBalance` response is an EVM compatibility value, not a customer's spendable stablecoin balance. Alchemy's generic native-balance example should not be used as the balance of a Tempo payment asset. See [EVM differences](/docs/quickstart/evm-compatibility#handling-eth-native-token-balance-checks).

A submitted transaction or successful receipt alone does not establish payment delivery. Verify the network, token contract, intended recipient, amount, and delivered transfer events using [Receive payments](/docs/guide/payments/accept-a-payment). Preserve the transaction identifier before investigating a timeout or retrying a payment.

## Plan for request limits and missed events

Alchemy's [throughput documentation](https://www.alchemy.com/docs/reference/throughput) describes account-level compute-unit limits and `429` responses. Set bounded retries and backoff for reads. For a transaction submission, investigate the existing signed transaction before creating another payment attempt.

A WebSocket subscription is a notification path, not your only payment record. Retain a checkpoint and read historical activity after reconnecting. Store the network, transaction hash, and transfer log index so repeated events cannot credit a payment twice.

## Alchemy questions

### Does Alchemy support Tempo mainnet and Moderato?

Yes. Its Tempo network page lists mainnet endpoints and a separate Moderato network. Select the correct endpoint and match it to Tempo's current network details.

### Can I connect with Viem?

Yes. Alchemy publishes a Viem quickstart for chain reads. Use Tempo's SDK and payment guides when the integration needs Tempo transaction features, fee-token selection, or sponsorship.

### Does RPC support include every Alchemy API?

No. Check the Tempo product-support matrix and the exact method you need. Reading a standard transaction receipt through RPC is distinct from access to a separate indexed-data product.
