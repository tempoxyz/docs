# Blockaid on Tempo

Use Blockaid to simulate a proposed Tempo payment and assess security findings before requesting a signature. Its official TypeScript client lists Tempo identifiers for individual transaction scans. Confirm account access and support for the transaction format your application submits.

## Blockaid's documented Tempo coverage

Blockaid's [Tempo announcement](https://blockaid.io/blog/blockaid-expands-protection-to-the-tempo-network), published December 9, 2025, describes transaction simulation and validation for wallets and exchanges in its partner network. It discusses additional monitoring, fraud-prevention, and cosigner capabilities as potential adoption paths. That announcement does not establish that every Blockaid product or public endpoint is available for every Tempo application.

The [individual transaction scan method](https://github.com/blockaid-official/blockaid-client-node/blob/main/src/resources/evm/transaction.ts), `client.evm.transaction.scan`, sends requests to `POST /v0/evm/transaction/scan`. Its imported [supported-chain type](https://github.com/blockaid-official/blockaid-client-node/blob/main/src/resources/evm/evm.ts) explicitly includes `tempo` and `tempo-testnet`. These identifiers are present in the published `@blockaid/client` version `1.8.0` reviewed for this page.

The bulk transaction API has a separate, narrower supported-chain type that does not list Tempo. Do not infer bulk scanning or native Tempo batch and sponsorship support from the individual scan's network list. Confirm the relevant transaction format and the testnet environment before using that flow.

## Distinguish simulation from validation

[Blockaid's official client](https://github.com/blockaid-official/blockaid-client-node) exposes transaction scanning with simulation and validation outputs:

| Output | Decision it supports |
| --- | --- |
| Simulation | Preview the transaction's expected effects, such as changes to assets or approvals. |
| Validation | Assess transaction security risk and present findings to the user or apply an application policy. |

These outputs support a signing decision. They do not establish that the recipient has passed sanctions screening, that a customer has completed identity checks, or that a proposed transaction will execute successfully under later network conditions.

The transaction scan defaults to validation output. Set `options: ['simulation', 'validation']` when the application needs both a transaction preview and security findings.

## Prepare a confirmed Blockaid integration

:::::steps

### Confirm access and transaction format

Obtain Blockaid API access for individual transaction scanning. Select the documented Tempo chain identifier and confirm which testnet it refers to if using `tempo-testnet`. Check support for the exact transaction format, including any native batch or sponsored payment flow you intend to submit.

### Use the maintained request schema

Use the [official TypeScript client](https://github.com/blockaid-official/blockaid-client-node) or current API documentation for authentication and request fields. The individual scan requires `account_address`, `chain`, transaction `data`, and `metadata`. Follow its current schema and explicitly request the outputs your application needs.

### Define the signing response

Decide how the application handles a warning, a security finding, an unsupported request, or a scan error. Present the relevant effects and findings before requesting a signature. Keep the assessment and the transaction it evaluated together.

Inspect `validation.result_type`, not just HTTP success or `validation.status`. The documented response can have `status: 'Success'` with `result_type: 'Error'`; that is an assessment error, not a benign finding.

:::::

## Keep security checks and payment controls distinct

A scan supplies expected effects and risk information. Your application controls whether to display a warning, request review, or stop its signing flow. It does not guarantee that a transaction is safe or compliant.

Keep wallet security checks distinct from [payment screening](/docs/resources/guides/payment-screening) and Tempo's [token and receive controls](/docs/resources/guides/compliance-controls). A simulation does not update an onchain policy or replace the institution's counterparty review.

## Blockaid integration questions

### Does Blockaid support Tempo?

Yes. Its individual transaction scan's supported-chain type lists `tempo` and `tempo-testnet`. Confirm account access, the selected environment, and support for the exact transaction format before integrating.

### Can I use any Blockaid EVM scanning endpoint on Tempo?

Use the documented individual transaction scan. Its Tempo identifiers do not establish support for the bulk endpoint, monitoring products, or every native Tempo transaction format.

### Are simulation and address screening interchangeable?

No. Simulation examines a proposed transaction's effects. Address screening assesses counterparty exposure. Use the checks required by your application's signing and payment decisions.
