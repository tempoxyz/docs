# Chainalysis on Tempo

Use Chainalysis Address Screening for address risk checks, KYT for transaction monitoring, and Reactor for investigations on Tempo. Chainalysis documents support for these three products, automatic TIP-20 token coverage, and decoding transfer memos when present. Confirm access to the products your workflow requires.

## Choose the Chainalysis product for the decision

The [Tempo support announcement](https://www.chainalysis.com/blog/tempo-automatic-token-coverage-march-2026/) identifies separate products for screening, monitoring, and investigations:

| Product | Documented Tempo workflow |
| --- | --- |
| Address Screening | Assess the risk associated with an address. |
| KYT | Monitor activity and generate alerts for review. |
| Reactor | Trace and visualize fund flows during investigations. |

For pre-payment checks, [Address Screening](https://www.chainalysis.com/product/address-screening/) assesses direct and indirect exposure and supports configurable category severities and exposure thresholds. It offers an interface and API access. Select settings that map to your payment policy and define which results require escalation.

## Use TIP-20 coverage and payment context

Chainalysis documents automatic coverage of TIP-20 tokens deployed on Tempo. It also captures and decodes TIP-20 transfer memos when included, making that context available in monitoring and investigation workflows.

A memo can help connect a transfer to an internal payment reference. Keep personal information and case details offchain, and follow the [transfer memo guide](/docs/guide/payments/transfer-memos) when creating the reference. A decoded memo does not establish the identity of a counterparty or prove that an invoice has been paid.

## Prepare product access and refresh behavior

Confirm your account entitlements, API credentials, and current product-specific documentation with Chainalysis. Access to one product does not establish access to another.

Address Screening's [product FAQ](https://www.chainalysis.com/product/address-screening/) distinguishes interface monitoring from API rescreening: interface users can receive alerts when a risk score changes, while an API integration must make another call to refresh the result. Set a refresh policy appropriate to your payment flow instead of treating a one-time API result as ongoing monitoring.

## Put screening and alerts into operation

:::::steps

### Set the decision and risk settings

Choose the screening categories, exposure thresholds, and findings that require review. Identify who can approve a payment or close an alert.

### Integrate the selected product

Use Address Screening for the address check, KYT for monitoring, or Reactor for investigation. Use that product's current documentation for inputs and supported environments.

### Retain the result and payment reference

Keep the assessment time, findings, decision, and internal payment reference together. Define how your application handles stale results, unavailable services, and errors.

:::::

Chainalysis supplies risk information for your decision process. Its results do not replace customer checks or automatically configure Tempo's [token and receive controls](/docs/resources/guides/compliance-controls). Connect any onchain permission changes to an authorized application workflow.

## Chainalysis integration questions

### Which Chainalysis products support Tempo?

Chainalysis names Address Screening, KYT, and Reactor in its Tempo support announcement. Confirm access and current implementation requirements for the product you intend to use.

### Does Chainalysis support TIP-20 tokens and memos?

Yes. Chainalysis documents automatic TIP-20 token coverage and decoding of transfer memos when present. Include only an appropriate reference in a public memo.

### Will an API screen keep an address monitored automatically?

Do not assume that. Address Screening's API requires another call for an updated result. Its interface offers risk-score change alerts; KYT is a separate transaction-monitoring product.
