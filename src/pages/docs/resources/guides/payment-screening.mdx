# Payment screening tools

Choose a screening tool by identifying the decision it must support: assessing an address before payment, monitoring activity afterward, or checking a proposed transaction before signing. These are different jobs, and one provider’s support for Tempo does not establish every product’s scope.

<span id="choose-check" />

## Place the check in your payment flow

Use address screening when you need risk information about a sender or recipient. Use transaction monitoring when activity over time should produce alerts or cases. Use transaction simulation and validation when a wallet needs to understand the proposed action and its security risks before signing.

Map each check to a decision your application or operations team can take. A provider result should lead to a defined outcome, such as continuing, waiting for review, or declining the payment under your own policy.

<span id="compare-products" />

## Compare screening products

Start with the products that match that decision. Confirm their Tempo coverage, API availability, and the information returned before comparing commercial terms.

- **TRM.** Documents Tempo wallet screening, transaction monitoring, tracing, and entity attribution. Confirm access to the required product. [Explore TRM](https://www.trmlabs.com/blockchain-coverage/tempo).
- **Chainalysis.** Documents Tempo support in Address Screening, KYT, and Reactor for screening, monitoring, and investigation workflows. [Explore Chainalysis](https://www.chainalysis.com/blog/tempo-automatic-token-coverage-march-2026/).
- **Elliptic.** Documents Tempo address screening, stablecoin transaction monitoring, and cross-chain investigation capabilities. [Explore Elliptic](https://www.elliptic.co/newsroom/elliptic-integrates-with-tempo-the-payments-first-blockchain/).
- **Blockaid.** Evaluate transaction simulation and validation before signing. Check the supported chain list for the particular scanning endpoint. [Explore Blockaid](https://github.com/blockaid-official/blockaid-client-node/blob/main/src/resources/evm/transaction.ts).

<span id="inputs-and-access" />

## Confirm screening inputs, access, and refresh behavior

Prepare the subject you need assessed: an address, transaction, or proposed wallet action. Establish how the selected API identifies networks and assets. Avoid copying request fields from a different provider or assuming a public sanctions endpoint is equivalent to a commercial screening product.

Confirm product access before planning an integration. TRM’s detailed API documentation follows account entitlements. Elliptic documents API-key authentication. Chainalysis offers both interface and API screening, but its API needs another request to refresh the result; automatic interface alerts do not establish identical API behavior.

- **Screening behavior.** Review Chainalysis’s explanation of configurable thresholds, exposure, and API rescreening. [Read the product FAQ](https://www.chainalysis.com/product/address-screening/).
- **Transaction scan inputs.** Review Blockaid’s official request and response types for simulation and validation. [Review the official request types](https://github.com/blockaid-official/blockaid-client-node/blob/main/src/resources/evm/transaction.ts).

<span id="decision-policy" />

## Define screening decisions before enabling payments

Choose the categories and thresholds relevant to your payment policy, who reviews ambiguous findings, and when an address should be checked again. Define explicit behavior for unavailable services, unsupported subjects, stale responses, and scan errors. An error is not a clean result.

Evaluate representative cases with the provider’s supported fixtures or test process. Keep the result, check time, policy decision, and payment reference together so a reviewer can understand what happened. Screening supplies risk information; your organization remains responsible for its payment decisions and broader controls.

## Payment screening questions

### Is transaction simulation the same as wallet screening?

No. Simulation examines a proposed transaction and its expected effects. Wallet screening assesses address risk. Select the checks your payment flow requires.

### Does a passed screen guarantee a compliant payment?

No. A screening result is risk information for your decision process. It does not replace customer checks, your policies, or other applicable obligations.

### Will a one-time API screen keep an address monitored?

Do not assume that. Confirm the selected product’s refresh and alert behavior. Chainalysis, for example, documents another API call to refresh Address Screening results.
