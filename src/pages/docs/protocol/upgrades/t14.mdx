# T14 Network Upgrade

T14 is the planned network upgrade that brings configurable accounts to testnet and mainnet.

:::tip[T14 status]
T14 is scheduled to activate on testnet on November 24, 2026 and on mainnet on December 1, 2026, both at 15:00 UTC. Its scope may still change before activation. Until T14 activates, configurable accounts run only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet).
:::

## T14 overview

- **Configurable accounts:** each signer has a weight, and a transaction runs once the signing weights reach the account's threshold. The address stays the same when signers change. See [Tempo Accounts](/docs/accounts).
- **Configuration updates:** the current signers replace the signer list and threshold in one transaction, at the same address. See [Account configuration](/docs/accounts/account-configuration).
- **Upgrades from single-key accounts:** an existing single-key account becomes a configurable account at the same address. See [Account upgrade](/docs/accounts/account-configuration/account-upgrade).
- **Configurable accounts as access keys:** a team's configurable account can act as another account's access key, approving with its own signers. See [Account Keychain](/docs/development/account-keychain#access-key-types).
- **Admin access keys removed:** Tempo rejects new admin access keys, and only an account's own key or its signers manage its access keys. Existing admin keys keep paying as access keys without limits. See [Admin Access Keys](/docs/accounts/access-keys/admin-access-keys).

## Integration impact

- **Existing accounts:** single-key accounts and limited access keys keep working unchanged. Upgrading an account to a configurable account is optional.
- **Admin access keys:** Tempo rejects new [admin access keys](/docs/accounts/access-keys/admin-access-keys), and only an account's own key or its signers authorize, change, or revoke its access keys. Admin keys authorized before T14 keep paying as access keys without limits. If you use an admin key to manage a user's other keys, [add that device as a signer](/docs/accounts/account-configuration/configuration-updates#add-a-signer) instead, revoke admin keys you no longer need, and [contact us](https://tempo.xyz/contact) to plan the change before T14.
- **Account upgrades:** until T14 activates on a network, an account upgrade transaction there charges its fee and changes nothing. Send upgrades only after activation.
- **Signature parsing:** configurable accounts sign with the [`0x05` multisig signature](/docs/development/configurable-accounts#multisig-signature-format). Viem builds and reads it. If you parse or verify Tempo transaction signatures yourself, handle this type. It isn't valid as a fee payer signature, in subblock transactions, or in authorization lists.
- **Contracts that check signatures:** to check that a configurable account approved a message, call `verifyMultisig` on the [signature verifier precompile](/docs/development/configurable-accounts#verify-owner-approvals-in-a-contract) rather than recovering a single signer.
