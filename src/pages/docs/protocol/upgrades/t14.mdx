# T14 Network Upgrade

T14 is the planned network upgrade that changes how Tempo accounts are controlled, removes admin access keys, and tightens validator, consensus and Zone Portal rules.

:::tip[T14 status]
T14 is scheduled to activate on testnet on November 24, 2026 and on mainnet on December 1, 2026, both at 15:00 UTC. Its scope may still change before activation. Until T14 activates, the account changes run only on the [Tempo Accounts devnet](/docs/accounts/create#connect-to-the-devnet).
:::

**Integration note:** T14 removes admin access keys. If you use an admin key to manage a user's other keys, plan the change before T14. [See integration impact](#integration-impact).

## T14 overview

- **Changes to accounts:** one address can be controlled by several signers, each with a weight, and a transaction runs once the signing weights reach the account's threshold. Signers and the threshold can change at the same address, an existing single-key account can upgrade in place, and such an account can act as another account's access key. See [Configurable accounts](/docs/development/configurable-accounts).
- **Admin access keys removed:** Tempo rejects new admin access keys, and only an account's own key or its signers manage its access keys. Existing admin keys keep paying as access keys without limits. See [Admin Access Keys](/docs/accounts/access-keys/admin-access-keys).
- **Account changes on Zones:** Zones read account configurations from Tempo, so these accounts also work on Zones.
- **Validator and consensus rules:** a block must pay the proposer's registered fee recipient, validator endpoints longer than 255 bytes or written as IPv4-mapped IPv6 addresses are rejected, and consensus defaults to deferred verification after the fork.
- **Paused Zone Portals:** a paused Zone Portal rejects refund claims and batch settlement until it resumes.

## Integration impact

- **Existing accounts:** single-key accounts and limited access keys keep working unchanged. Upgrading an account to a configurable account is optional.
- **Admin access keys:** Tempo rejects new [admin access keys](/docs/accounts/access-keys/admin-access-keys), and only an account's own key or its signers authorize, change, or revoke its access keys. Admin keys authorized before T14 keep paying as access keys without limits. If you use an admin key to manage a user's other keys, [add that device as a signer](/docs/accounts/account-configuration/configuration-updates#add-a-signer) instead, revoke admin keys you no longer need, and [contact us](https://tempo.xyz/contact) to plan the change before T14.
- **Account upgrades:** until T14 activates on a network, an account upgrade transaction there charges its fee and changes nothing. Send upgrades only after activation.
- **Signature parsing:** configurable accounts sign with the [`0x05` multisig signature](/docs/development/configurable-accounts#multisig-signature-format). Viem builds and reads it. If you parse or verify Tempo transaction signatures yourself, handle this type. It isn't valid as a fee payer signature, in subblock transactions, or in authorization lists.
- **Contracts that check signatures:** to check that a configurable account approved a message, call `verifyMultisig` on the [signature verifier precompile](/docs/development/configurable-accounts#verify-owner-approvals-in-a-contract) rather than recovering a single signer.
- **Validators:** block execution rejects a block whose beneficiary differs from the proposer's registered fee recipient, or whose proposer has no registered fee recipient. Validator endpoints over 255 bytes or written as IPv4-mapped IPv6 addresses revert; use the IPv4 form.
