# Deposit Into a Zone

Deposit stablecoins through the Zone's portal on Tempo, then confirm the private account's credit.

## Overview

A deposit sends stablecoins to the Zone's portal (`ZonePortal`) on Tempo and credits a private account in the Zone. You prepare it, submit it on Tempo, then track the credit.

You need the deployment details and authenticated connection from [Connect to a Zone](/docs/zones/connect), and the operator's encryption and contract tooling.

<span id="submit-an-encrypted-deposit" />

## Setup

<span id="check-the-asset-and-recipient" />

:::::steps

### Prepare the Deposit

The deployment must accept the token, and the depositor and recipient must satisfy its access rules. Choose the private recipient and memo, and a public refund recipient.

<span id="check-the-deposit-fees" />

#### Calculate Deposit Fees

Use the deployed portal's `calculateDepositFee` and `calculateBouncebackFee` helpers. They return the amount the private account can receive and the required failure coverage. Deposit fees come out of the amount sent. Show the expected net credit before authorization. The [deposit fee rules](/docs/protocol/zones/execution#deposit-fees) define the calculation.

<span id="encrypt-and-authorize-the-deposit" />
<span id="send-funds" />

### Submit the Deposit

Encrypt the private recipient and memo with the operator's tooling, which uses the Zone's published encryption key. Approve token spending where required, then submit the encrypted deposit to the portal on Tempo.

The token, amount, depositor, and refund recipient stay public, as the [privacy model](/docs/zones/privacy) describes.

<span id="confirm-the-private-credit" />
<span id="confirm-arrival" />

### Confirm the Credit

After the Tempo transaction finalizes, [check the Zone credit](/docs/zones/balances) with the recipient's authenticated connection. Save the public deposit reference and private credit record together.

:::::

## Track the Deposit

Read the deposit outcome with the [Zone status API](/docs/api/zones). Use the queue hash that `ZonePortal.depositEncrypted` returns, not its transaction hash.

In the playground, select **Try**. Enter the deposit queue hash and the Zone’s numeric `chainId`. Use an API key with `data:read` and access to that Zone. The request tool includes language examples and the response.

<OpenApi.Playground operationId="getZoneDeposit" anchors={false} />

A `pending` deposit hasn't completed. For a failed deposit, inspect `refund.status` and confirm the refund before you retry. Keep using authenticated [balance and activity reads](/docs/zones/balances) for the private account's ledger.

## Handle Deposit Failures

The [deposit lifecycle](/docs/protocol/zones/bridging#deposits-tempo--zone) covers policy failures and refunds.

If funds start on another network, [route them to Tempo](/docs/routes) first. Then deposit through the portal.
