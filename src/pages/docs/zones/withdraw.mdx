# Withdraw

Withdraw through the Zone's supported outbox interface, then track delivery on public Tempo. The source transaction, accepted batch, and recipient's token receipt are separate events.

[Try the withdrawal demo](/docs/guide/private-zones/withdraw-from-a-zone) with test funds. It uses the earlier sandbox interface.

## Submit and track a withdrawal

<span id="check-the-destination-and-access-rules" />


:::::steps

### Prepare the withdrawal

Confirm the token, amount, public Tempo recipient, fallback recipient, and deployment restrictions with the operator's tooling. If using a callback, verify the permitted target and callback interface before requesting authorization.

<span id="include-withdrawal-fees" />

#### Calculate withdrawal fees

Read `calculateWithdrawalFee(gasLimit)` from the deployed outbox interface. Reserve enough balance for this fee and Zone transaction gas in addition to the amount withdrawn. See the [withdrawal fee rules](/docs/protocol/zones/execution#withdrawal-fees).

<span id="submit-through-the-zone-outbox" />

### Request a withdrawal

Use the supported interface to submit the withdrawal through `ZoneOutbox`. Save the source transaction and identifiers needed to follow the withdrawal across the private and public networks.

<span id="track-settlement-on-tempo" />

### Track delivery

The operator includes the withdrawal in a batch, the portal accepts the batch, and the withdrawal is processed on Tempo. Keep it pending until the destination delivery is confirmed.

The hosted [Zone withdrawal status API](/docs/api/zones) can report parent-chain outcomes. Its `zoneStatus: completed` is a checkpoint signal, not proof that a refund was delivered.

:::::

## Read the withdrawal status

Use the `senderTag` emitted for this withdrawal; tags can differ for withdrawals within the same transaction. The API returns indexed outcomes in `data`.

Click **Try**, enter the emitted sender tag and the Zone’s numeric `chainId`, then use an API key with `data:read` and access to that Zone. The request tool includes language examples and the response.

<OpenApi.Playground operationId="listZoneWithdrawals" anchors={false} />

An empty `data` array means no outcome has been indexed yet. Keep the withdrawal pending while tracking both delivery and any refund; the Zone checkpoint alone does not confirm that funds arrived.

<span id="handle-failed-delivery" />

## Handle refunds

A failed token transfer or callback can return funds through a deposit back into the source Zone. That return also needs processing; if minting is blocked, it can leave a pending refund.

Follow [withdrawal failure and bounce-back](/docs/protocol/zones/bridging#withdrawal-failure-and-bounce-back) to track the refund to the recipient.

## Call a contract on Tempo

Withdrawals can invoke contracts on Tempo subject to the deployment's access rules. The public operation and any later Zone credit have separate settlement stages. Use the [composable withdrawal specification](/docs/protocol/zones/bridging#composable-withdrawals) when integrating callbacks.
