# Withdraw From a Zone

Withdraw through the Zone's outbox, then track delivery to a Tempo recipient.

## Overview

A withdrawal moves funds from a Zone back to a recipient on Tempo. You prepare it, submit it through the Zone's outbox (`ZoneOutbox`), then track delivery. The source transaction, the accepted batch, and the recipient's token receipt are separate events.

This page uses the deployment details and authenticated connection from [Connect to a Zone](/docs/zones/connect).

<span id="submit-and-track-a-withdrawal" />

## Setup

<span id="check-the-destination-and-access-rules" />

:::::steps

### Prepare the Withdrawal

Confirm the token, amount, Tempo recipient, and fallback recipient with the operator's tooling. Also confirm the deployment's restrictions. If you use a callback, verify the permitted target and callback interface before you request authorization.

<span id="include-withdrawal-fees" />

#### Calculate Withdrawal Fees

Read `calculateWithdrawalFee(gasLimit)` from the deployed outbox. Reserve enough balance for this fee and Zone transaction gas, on top of the amount withdrawn. The [withdrawal fee rules](/docs/protocol/zones/execution#withdrawal-fees) define the calculation.

<span id="submit-through-the-zone-outbox" />
<span id="request-a-withdrawal" />

### Submit the Withdrawal

Use the operator's supported interface to submit the withdrawal through the outbox. Save the source transaction. Also save the identifiers you need to follow the withdrawal across the Zone and Tempo.

<span id="track-settlement-on-tempo" />
<span id="track-delivery" />

### Confirm Delivery

The sequencer includes the withdrawal in a batch. The portal accepts the batch, and Tempo processes the withdrawal. Keep it pending until the destination delivery is confirmed.

:::::

<span id="read-the-withdrawal-status" />

## Track the Withdrawal

Read Tempo outcomes with the hosted [Zone withdrawal status API](/docs/api/zones). Its `zoneStatus: completed` is a checkpoint signal. Check the delivery outcome and any refund separately.

Use the `senderTag` emitted for this withdrawal. Tags can differ for withdrawals within the same transaction. The API returns indexed outcomes in `data`.

In the playground, select **Try**. Enter the emitted sender tag and the Zone’s numeric `chainId`. Use an API key with `data:read` and access to that Zone. The request tool includes language examples and the response.

<OpenApi.Playground operationId="listZoneWithdrawals" anchors={false} />

An empty `data` array means no outcome is indexed yet. Keep the withdrawal pending while you track both delivery and any refund. The Zone checkpoint alone doesn't confirm that funds arrived.

<span id="handle-failed-delivery" />
<span id="handle-refunds" />

## Handle Withdrawal Failures

A failed token transfer or callback can return funds through a deposit back into the source Zone. That return also needs processing. If minting is blocked, it can leave a pending refund.

Track the refund to the recipient with [withdrawal failure and bounce-back](/docs/protocol/zones/bridging#withdrawal-failure-and-bounce-back).

## Call a Contract on Tempo

Withdrawals can invoke contracts on Tempo, subject to the deployment's access rules. The public operation and any later Zone credit have separate settlement stages. Use the [composable withdrawal specification](/docs/protocol/zones/bridging#composable-withdrawals) when you integrate callbacks.
