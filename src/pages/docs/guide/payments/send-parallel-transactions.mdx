# Send parallel transactions using expiring nonces

Send several payments at the same time using [expiring transactions](/docs/guide/tempo-transaction#expiring-nonces). Each transaction has a deadline, so you don't need to track a sequence number before sending the next payment.

## Parallel transaction demo

Send two payments at the same time. The demo uses expiring transactions and shows a receipt for each confirmed payment.

### Send concurrent transactions with nonce keys

Set `nonceKey` to `'expiring'` for each payment. The SDK sets an expiry time. Submit both payments together and wait for their receipts.

:::code-group

```ts twoslash [example.ts]
// @noErrors
import { Actions } from 'wagmi/tempo'
import { parseUnits } from 'viem'
import { config } from './wagmi.config'

const alphaUsd = '0x20c0000000000000000000000000000000000001'

// Send both transfers in parallel. // [!code focus]
const [payment1, payment2] = await Promise.all([ // [!code focus]
  Actions.token.transferSync(config, { // [!code focus]
    amount: parseUnits('100', 6), // [!code focus]
    to: '0x70997970C51812dc3A010C7d01b50e0d17dc79C8', // [!code focus]
    token: alphaUsd, // [!code focus]
    nonceKey: 'expiring', // [!code focus]
  }), // [!code focus]
  Actions.token.transferSync(config, { // [!code focus]
    amount: parseUnits('50', 6), // [!code focus]
    to: '0x3C44CdDdB6a900fa2b585dd299e03d12FA4293BC', // [!code focus]
    token: alphaUsd, // [!code focus]
    nonceKey: 'expiring', // [!code focus]
  }), // [!code focus]
]) // [!code focus]

console.log('Transaction 1:', payment1.receipt.transactionHash) // [!code focus]
console.log('Transaction 2:', payment2.receipt.transactionHash) // [!code focus]
```

```tsx twoslash [wagmi.config.ts] filename="wagmi.config.ts"

```

## Distinct transactions after T12

After T12 activates, use different `nonce` values to send otherwise identical payments as separate transactions. Your wallet and signing tools must keep the value you supply. Read the [specification](https://github.com/tempoxyz/tempo/blob/main/tips/tip-1106.md).

:::warning[Only after T12 activation]
Run this example only after T12 activates on the connected network. Earlier versions reject nonzero nonces for expiring transactions.
:::

This example sends two payments of 50 AlphaUSD to the same recipient, with the same expiry time. Different nonces give each payment its own transaction hash.

```ts [identical-payments.ts]
import { maxUint256, parseUnits } from 'viem'
import { Actions } from 'wagmi/tempo'
import { config } from './wagmi.config'

const payment = {
  token: '0x20c0000000000000000000000000000000000001',
  to: '0x70997970C51812dc3A010C7d01b50e0d17dc79C8',
  amount: parseUnits('50', 6),
  nonceKey: maxUint256,
  validBefore: Math.floor(Date.now() / 1000) + 60,
} as const

const payments = await Promise.all([
  Actions.token.transferSync(config, { ...payment, nonce: 1 }),
  Actions.token.transferSync(config, { ...payment, nonce: 2 }),
])

for (const { receipt } of payments) console.log(receipt.transactionHash)
```

Use the numeric `nonceKey: maxUint256` shown above with an explicit expiry time; the SDK's `'expiring'` shortcut can reset the nonce to zero. Choose a new nonce for each otherwise identical payment within the same expiry window.

If you add access-list entries only to make transactions unique, you can replace them with different nonce values after activation. Other [payment-lane requirements](/docs/protocol/blockspace/payment-lane-specification) still apply.
