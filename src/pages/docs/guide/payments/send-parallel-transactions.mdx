# Send payments in parallel

Submit independent payment transactions concurrently when each payment needs its own receipt. Use [batch payments](/docs/guide/payments/send-a-payment#batch-payment-transactions) when the calls must succeed or fail together in one transaction.

## Submit independent transactions

<span id="parallel-transaction-demo" />

Connect a test account and send two independent transactions on Moderato testnet. The wallet demo uses separate nonce keys; the backend example below uses expiring nonces. Both produce a receipt for each transaction.

Use the funded Moderato account from [Send a payment](/docs/guide/payments/send-a-payment#send-from-your-backend). This Viem example explicitly selects [expiring nonces](/docs/guide/tempo-transaction#expiring-nonces), so the transactions do not compete for a sequential nonce.

:::code-group

```ts [parallel-payments.ts]
import { parseUnits } from 'viem'
import { client } from './viem.config'

const payments = [
  { to: '0x70997970c51812dc3a010c7d01b50e0d17dc79c8', amount: '10' },
  { to: '0x3c44cdddb6a900fa2b585dd299e03d12fa4293bc', amount: '5' },
] as const

const results = await Promise.allSettled(
  payments.map(({ to, amount }) =>
    client.token.transferSync({
      token: '0x20c0000000000000000000000000000000000001',
      to,
      amount: parseUnits(amount, 6),
      nonceKey: 'expiring',
    }),
  ),
)

for (const [index, result] of results.entries()) {
  if (result.status === 'fulfilled') {
    console.log(index, result.value.receipt.transactionHash)
  } else {
    console.error(index, result.reason)
  }
}
```

```ts [viem.config.ts]
// [!include ~/snippets/viem.moderato.config.ts:setup]
```

:::

Replace the example recipients with test accounts you control. Each payment produces a separate result; one failure does not roll back the others. [Verify delivery](/docs/guide/payments/accept-a-payment#verify-stablecoin-payments) for each receipt before marking its payment complete.

Expiring nonces include a transaction validity window. If a submission times out, check its transaction hash before rebuilding or retrying the payment. See [expiring nonce behavior](/docs/guide/tempo-transaction#expiring-nonces) for expiry and replay rules.
