# Receive payments

Receive stablecoins at a Tempo account, confirm the token and amount delivered, and match the transfer to your payment records. Use [payment references](/docs/guide/payments/transfer-memos) for invoices or [customer deposit addresses](/docs/guide/payments/virtual-addresses) to identify who paid.

<span id="receive-stablecoin-payments" />

## Get a deposit address

Share an account address you control with the sender. For customer-specific addresses that credit a shared account, use [customer deposit addresses](/docs/guide/payments/virtual-addresses); your application maintains the customer ledger. For deposits from other networks, use [Routes](/docs/routes/deposits).

Show the network and token alongside the receiving address, then read incoming transfer events to confirm delivery.

This demo funds a test account and displays its token balances. The examples below use AlphaUSD on Moderato testnet. Configure your client or `RPC_URL` / `TEMPO_RPC_URL` for `https://rpc.moderato.tempo.xyz`; use an account you control as the recipient.

## Detect payments

Use the account balance to display available funds. To verify a payment, match the network, token contract, recipient, and amount in its confirmed transfer events to your payment record.

The event examples below read activity for a token contract. Filter by recipient and use the transaction hash and log index to process each payment once. For virtual addresses, follow the [deposit attribution flow](/docs/guide/payments/virtual-addresses#what-to-verify-in-virtual-address-deposits).

For payments held by a receive policy, see [Handle blocked receipts](/docs/guide/payments/configure-receive-policies#monitor-blocked-receipts).

<span id="check-receiver-token-balance" />

For balance snapshots and display formatting, use [Balances and activity](/docs/accounts/balances#read-a-stablecoin-balance). A balance change alone does not identify which customer or invoice to credit.

<span id="listen-for-tip-20-transfer-events" />

Enter the receiving account as both `address` and `recipient`. Set `chainId` to `42431` and `type` to `transfer` to read incoming payments on Moderato:

<OpenApi.Playground operationId="getAddressActivities" anchors={false} />

For direct transfer subscriptions, use the [CLI, Viem, or Wagmi setup](/docs/accounts/examples#choose-your-tools). Set `account` to the recipient and `token` to AlphaUSD. Wagmi hooks run inside a React component and clean up on unmount:

::::code-group

```ts [Viem]
const unwatch = client.token.watchTransfer({
  token, args: { to: account },
  onTransfer: (transfer, log) => console.log(transfer, log.transactionHash),
})
// Call unwatch() when the view closes.
```

```bash [CLI]
cast logs 'Transfer(address indexed from,address indexed to,uint256 value)' \
  '' "$TEMPO_ACCOUNT_ADDRESS" --address "$ALPHA_USD" \
  --subscribe --rpc-url wss://rpc.moderato.tempo.xyz
```

```tsx [Wagmi]
import { Hooks } from 'wagmi/tempo'
Hooks.token.useWatchTransfer({
  token, args: { to: account },
  onTransfer: (transfer, log) => console.log(transfer, log.transactionHash),
})
```

::::

Use [webhooks](/docs/api/webhooks) for backend callbacks. Read historical activity after reconnecting and follow pagination to recover missed events. The [complete event examples](/docs/guide/payments/accept-a-payment/examples#listen-for-tip-20-transfer-events) cover direct RPC log queries.

## Match payments to customers

Use the memo to find an invoice, or a [customer deposit address](/docs/guide/payments/virtual-addresses) to identify who paid. Enter the candidate transaction hash and its network below to inspect the token movements.

<OpenApi.Playground operationId="getTransactionActivities" anchors={false} />

:::::steps

### Find the invoice

Match the transfer's memo using the [same reference encoding](/docs/guide/payments/transfer-memos#encode-a-payment-reference) your application requested.

### Verify delivery

Check the network, token, recipient, and amount against the invoice. Confirm the successful transaction and the delivered `Transfer` event. For a blocked receipt, funds go to the receive-policy guard rather than the intended recipient.

### Record the payment once

Store the network, transaction hash, and transfer log index as a unique event key. Save that event and mark the invoice paid in one database transaction. An API response or matching memo alone must not fulfill an invoice.

:::::

Use the [complete TypeScript verifier](/docs/guide/payments/accept-a-payment/examples#verify-an-invoice) for receipt checks, memo matching, and a stable event key.
