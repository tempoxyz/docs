# Receive a payment

Receive stablecoins at a Tempo account, confirm the token and amount delivered, and match the transfer to your payment records. Use [payment references](/docs/guide/payments/transfer-memos) for invoices or [customer deposit addresses](/docs/guide/payments/virtual-addresses) to identify who paid.

## Receive stablecoin payments

Share your account address with the sender, then read the incoming transfer events to confirm receipt.

This demo funds a test account and displays its token balances. The examples below use AlphaUSD on Moderato testnet. Configure your client or `RPC_URL` / `TEMPO_RPC_URL` for `https://rpc.moderato.tempo.xyz`; use an account you control as the recipient.

## Verify stablecoin payments

Use the account balance to display available funds. To verify a payment, match the network, token contract, recipient, and amount in its confirmed transfer events to your payment record.

The event examples below read activity for a token contract. Filter by recipient and use the transaction hash and log index to process each payment once. For virtual addresses, follow the [deposit attribution flow](/docs/guide/payments/virtual-addresses#what-to-verify-in-virtual-address-deposits).

For payments held by a receive policy, see [Handle blocked receipts](/docs/guide/payments/configure-receive-policies#monitor-blocked-receipts).

<span id="check-receiver-token-balance" />

For balance snapshots and display formatting, use [Balances and activity](/docs/accounts/balances#read-a-stablecoin-balance). A balance change alone does not identify which customer or invoice to credit.

### Listen for TIP-20 transfer events

Set `TEMPO_RECIPIENT` to your receiving account. The Viem example filters incoming transfers to that address.

    use alloy::{primitives::address, providers::ProviderBuilder};
    use futures::StreamExt;
    use tempo_alloy::{TempoNetwork, contracts::precompiles::ITIP20};

    #[tokio::main]
    async fn main() -> Result<(), Box<dyn std::error::Error>> {
        let provider = ProviderBuilder::new_with_network::<TempoNetwork>()
            .connect(&std::env::var("RPC_URL").expect("No RPC URL set"))
            .await?;

        // Watch for incoming transfers // [!code focus]
        let mut transfers = ITIP20::new( // [!code focus]
            address!("0x20c0000000000000000000000000000000000001"), // [!code focus]
            &provider, // [!code focus]
        ) // [!code focus]
        .Transfer_filter() // [!code focus]
        .watch() // [!code focus]
        .await? // [!code focus]
        .into_stream(); // [!code focus]

        while let Some(Ok((payment, _))) = transfers.next().await { // [!code focus]
            println!("Received payment: {payment:?}") // [!code focus]
        } // [!code focus]

        Ok(())
    }

## Reconcile payments with memos

<span id="payment-reconciliation-with-memos" />

Use the memo to find the invoice, then verify the payment before marking it paid.

:::::steps

### Find the invoice

Read the memo from `TransferWithMemo` and look up the corresponding invoice. Use the [same memo encoding](/docs/guide/payments/transfer-memos#encode-a-payment-reference) when sending and matching payments.

### Verify delivery

Check the network, token, recipient, and amount against the invoice using the confirmed `Transfer` event. For [blocked receipts](/docs/guide/payments/configure-receive-policies#monitor-blocked-receipts), the recipient is the receive-policy guard.

### Record the payment once

Store the network, transaction hash, and transfer log index as a unique event key. Save it and mark the invoice paid in the same database transaction. Replayed events or another payment with the same memo must not fulfill a paid invoice again.

:::::

<details>
<summary>Full TypeScript verification example</summary>

This example verifies one payment of 10 AlphaUSD to a regular account on Moderato testnet. Replace the expected values with your invoice details and set `PAYMENT_TX_HASH` to the payment transaction hash. It prints an event key for your database to record.

```ts [verify-payment.ts]
import {
  parseEventLogs,
  parseUnits,
  toHex,
} from 'viem'
import { tempoModerato } from 'viem/chains'
import { Abis, createClient } from 'viem/tempo'

const client = createClient({ chain: tempoModerato })
const expected = {
  token: '0x20c0000000000000000000000000000000000001',
  recipient: '0x742d35cc6634c0532925a3b844bc9e7595f0bebb',
  amount: parseUnits('10', 6),
  memo: toHex('invoice-001', { size: 32 }),
}

const hash = process.env.PAYMENT_TX_HASH
if (!hash || !/^0x[0-9a-fA-F]{64}$/.test(hash)) {
  throw new Error('Set PAYMENT_TX_HASH to the payment transaction hash')
}
if (await client.getChainId() !== tempoModerato.id) {
  throw new Error('Expected Moderato testnet')
}

const receipt = await client.waitForTransactionReceipt({
  hash: hash as `0x${string}`,
})
if (receipt.status !== 'success') throw new Error('Payment transaction failed')

const tokenLogs = receipt.logs.filter(
  (log) => log.address.toLowerCase() === expected.token,
)
const payments = parseEventLogs({
  abi: Abis.tip20,
  eventName: 'TransferWithMemo',
  logs: tokenLogs,
  strict: true,
}).filter((log) =>
  log.args.to.toLowerCase() === expected.recipient &&
  log.args.amount === expected.amount &&
  log.args.memo === expected.memo,
)

if (payments.length !== 1) {
  throw new Error('Expected one transfer matching the invoice')
}

const payment = payments[0]
const deliveries = parseEventLogs({
  abi: Abis.tip20,
  eventName: 'Transfer',
  logs: tokenLogs,
  strict: true,
}).filter((log) =>
  log.args.from.toLowerCase() === payment.args.from.toLowerCase() &&
  log.args.to.toLowerCase() === expected.recipient &&
  log.args.amount === expected.amount,
)
if (deliveries.length !== 1) {
  throw new Error('Expected one delivery to the invoice recipient')
}

const eventKey = `${tempoModerato.id}:${receipt.transactionHash}:${deliveries[0].logIndex}`
console.log('Verified payment:', { eventKey, memo: expected.memo })
```

</details>

## Receive payments in a contract

When a contract collects payment with `transferFrom`, require delivery before fulfilling the invoice:

- Read the expected token, payer, and amount from the invoice record, and reject an invoice that is already paid.
- Check that the payer authorized the payment and approved the required token allowance.
- Read the contract’s token balance before and after `transferFrom`. Require the expected increase before updating the invoice or delivering the purchased item.
- Revert if the expected funds did not arrive.

See the [TIP-20 contract interface](/docs/protocol/tip20/spec#tip20) and [receive-policy behavior](/docs/guide/payments/configure-receive-policies#understand-receive-policy-behavior) before implementing settlement.

<span id="payment-verification-best-practices" />

## Record a payment once

- Verify the token contract, recipient, and amount in confirmed transfer events before marking an order paid.
- Match a memo or customer deposit address to the expected payment record.
- Store the transaction hash and log index to avoid processing the same event twice.
- Handle partial payments, refunds, blocked receipts, and failed transactions explicitly.

<span id="cross-stablecoin-payments" />

## Convert a received stablecoin

If your application accepts one stablecoin but holds another, [swap the received funds](/docs/guide/stablecoin-dex/executing-swaps). Set the minimum acceptable output from a current quote. Choosing a different fee token only changes how you pay transaction fees.
