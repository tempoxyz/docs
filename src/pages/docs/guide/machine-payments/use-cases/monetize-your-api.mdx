# Charge for an API request

Use MPP to request payment before your API performs a paid operation. Follow [Accept payments for an API](/docs/guide/machine-payments/server) for middleware and request-handler examples.

<span id="the-api-monetization-problem" />
<span id="how-mpp-adds-agentic-api-payments" />

## Choose how to charge

- [One-time payments](/docs/guide/machine-payments/one-time-payments) charge a fixed amount for a request or resource.
- [Payment sessions](/docs/guide/machine-payments/pay-as-you-go) meter usage through a funded channel and signed vouchers.
- [Streamed payments](/docs/guide/machine-payments/streamed-payments) coordinate usage and payment while sending a streaming response.

## Integrate payment verification

Choose the accepted token, price, and recipient in your [server configuration](/docs/guide/machine-payments/server). The server issues a payment challenge; the client retries with a credential. Perform the paid operation after verification and return the payment receipt with the response.

Keep application authorization separate from payment verification. Paying for a request does not grant access to another customer's data.

<span id="next-steps-for-api-monetization" />

## Test and publish the endpoint

Test the request with [Pay with the CLI](/docs/guide/machine-payments/agent), then follow [MPP discovery documentation](https://mpp.dev/advanced/discovery) to make the endpoint discoverable.
