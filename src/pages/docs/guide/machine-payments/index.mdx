# How MPP works

The [Machine Payments Protocol](https://mpp.dev/protocol) (MPP) lets a service request payment as part of an HTTP request. An application or agent handles the payment challenge and retries the request with payment authorization.

## MPP payment flow

<MermaidDiagram chart={`sequenceDiagram
    participant Client
    participant Server
    Client->>Server: Request resource
    Server-->>Client: 402 Payment Required + Challenge
    Note over Client: Authorize payment
    Client->>Server: Retry request + Credential
    Note over Server: Verify payment
    Server-->>Client: Resource + Receipt
`} />

- **Challenge:** the server describes the payment terms in `WWW-Authenticate: Payment`.
- **Credential:** the client supplies the payment proof in `Authorization: Payment` when it retries.
- **Receipt:** the server acknowledges payment with `Payment-Receipt`.

The payment method defines the proof and settlement rules. On Tempo, a credential can carry a signed transaction, a transaction reference, or a payment-channel voucher, depending on the intent.

## MPP payment intents on Tempo

These guides cover two payment patterns:

| Pattern | Use it for | Guide |
| --- | --- | --- |
| One-time payment (`charge`) | A fixed price for a request or resource. | [Accept one-time payments](/docs/guide/machine-payments/one-time-payments) |
| Payment session (`session`) | Metered usage, including streamed responses, using a funded channel and signed vouchers. | [Accept pay-as-you-go payments](/docs/guide/machine-payments/pay-as-you-go) |

See the [MPP intent reference](https://mpp.dev/protocol#payment-intents) for other patterns and their supported payment methods.

## Implement paid requests

Use [Pay for services](/docs/guide/machine-payments/client) for an application, [Pay with the CLI](/docs/guide/machine-payments/agent) for terminal requests, or [Accept payments for an API](/docs/guide/machine-payments/server) for a service. The [Machine Payments overview](/docs/agents) helps you choose an integration.

Payment authorization is separate from account access. Use [Give an agent access](/docs/accounts/agents) to control which account an agent can spend from.

## Learn more about MPP

Use the [MPP documentation](https://mpp.dev) for SDKs, transport details, and payment methods, and the [protocol specification](https://paymentauth.org/) for normative behavior.
