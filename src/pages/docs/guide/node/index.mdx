# Run a node

Run Tempo infrastructure when you need your own RPC access or participate in validator operations. Most applications can start with the [public RPC endpoints](/docs/quickstart/connection-details).

## Choose a node type

| Node | Use it for | Start here |
| --- | --- | --- |
| RPC node | Read network state and serve JSON-RPC without participating in consensus. | [RPC setup](/docs/guide/node/rpc) |
| Validator | Participate in coordinated network operations. Onboarding requires coordination with the Tempo team. | [Validator responsibilities](/docs/guide/node/validator) |
| Standby node | Maintain infrastructure for validator failover. | [Failover](/docs/guide/node/validator-failover) |

A following RPC node verifies consensus finalization certificates and executes transactions locally. Its upstream must serve certified consensus data. Read [consensus and network identity](/docs/guide/node/consensus-and-dkg) for the trust model and key-rotation behavior.

## Run an RPC node

Check the [system requirements](/docs/guide/node/system-requirements), then [install the Tempo binary](/docs/guide/node/installation). Download a mainnet snapshot and start the node:

```bash [CLI]
tempo download --chain mainnet --archive

tempo node \
  --follow \
  --http --http.port 8545 \
  --http.api eth,net,web3,txpool,trace
```

Once the node serves RPC, read its sync status. `eth_syncing` returns `false` when it is no longer syncing, or an object with progress fields while syncing.

::::code-group

```bash [API (RPC)]
curl http://localhost:8545 -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_syncing","params":[]}'
```

```bash [CLI]
cast rpc eth_syncing --rpc-url http://localhost:8545
```

::::

The [RPC setup guide](/docs/guide/node/rpc) covers persistent services and health checks. Review [node security](/docs/guide/node/security) before exposing endpoints.

## Monitor and upgrade

Use [monitoring](/docs/guide/node/validator-monitoring) to track node health and [troubleshooting](/docs/guide/node/validator-troubleshooting) to diagnose failures. For validators, follow [onboarding](/docs/guide/node/validator-setup), [topology](/docs/guide/node/validator-topology), and [key management](/docs/guide/node/validator-keys).

Track [network upgrades](/docs/guide/node/network-upgrades) for required operator actions and the [upgrade cadence](/docs/guide/node/upgrade-cadence) for rollout guidance. The [changelog](/docs/changelog) records software releases; [protocol upgrades](/docs/protocol/upgrades) describe changes to network rules.
