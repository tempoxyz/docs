# Swap Across Zones

Swap `OUSD` in Zone A for `betaUSD` in Zone B through the Stablecoin DEX.

## Overview

A cross-Zone swap trades `OUSD` test tokens in **Zone A** for `betaUSD` in **Zone B**. It uses the [testnet sandbox](/docs/guide/private-zones#testnet-compatibility), which differs from current deployments. The swap settles on Tempo before Zone B credits the balance.

The route uses the sandbox's [SwapAndDepositRouter deployment](/docs/guide/private-zones#sandbox-router-deployment) on Tempo. It withdraws from `Zone A` and swaps on the Stablecoin DEX. Then it deposits the output token into `Zone B`.

## Swap OUSD for betaUSD

The demo runs the full route:

1. Withdraws `OUSD` from `Zone A`.
2. Routes it through Tempo and swaps it on the Stablecoin DEX.
3. Deposits the output token into `Zone B` through its portal (`ZonePortal`).
4. Confirms the credited `betaUSD` balance in `Zone B`.

## Code Example

This snippet assumes a signed-in `rootClient` on Tempo and a `zoneAClient`. It also assumes the shared token and portal constants used throughout the Zone guides. The router address and callback encoding are specific to Moderato's Zone A and Zone B sandbox.

This code covers the routed swap submission. Use the demo to watch the output deposit settle into Zone B.

```ts
import { encodeAbiParameters, parseUnits } from 'viem'

const swapAndDepositRouter = '0xf9b794e0dca9bc12ac90067df792d7aad33436e4' as const
const swapAmount = parseUnits('25', 6)

await zoneAClient.zone.signAuthorizationToken({ zoneId: 6 })

const quotedBetaOut = await rootClient.dex.getSellQuote({
  amountIn: swapAmount,
  tokenIn: ousd,
  tokenOut: betaUsd,
})

const minimumBetaOut = quotedBetaOut - quotedBetaOut / 100n

const callbackData = encodeAbiParameters(
  [
    { type: 'bool' },
    { type: 'address' },
    { type: 'address' },
    { type: 'address' },
    { type: 'bytes32' },
    { type: 'uint128' },
  ],
  [false, betaUsd, ZONE_B.portalAddress, rootClient.account.address, zeroBytes32, minimumBetaOut],
)

const { receipt } = await zoneAClient.zone.requestWithdrawalSync({
  account: rootClient.account,
  amount: swapAmount,
  data: callbackData,
  feeToken: ousd,
  fallbackRecipient: rootClient.account.address,
  gas: routerCallbackGasLimit,
  to: swapAndDepositRouter,
  token: ousd,
})

// This receipt confirms source submission. Verify L1 processing and destination credit next.
console.log(receipt.blockNumber)
```

## Swap Settlement

The swap is asynchronous because the trade temporarily leaves the Zone.

The source token exits through the outbox (`ZoneOutbox`) and transfers to `SwapAndDepositRouter` on Tempo. The router optionally swaps it on the Stablecoin DEX. It then deposits the output token through the destination portal. That routed deposit pays the normal [deposit fee](/docs/protocol/zones/execution#deposit-fees), so the destination Zone receives the post-fee output.

The swap completes when the destination Zone credits the recipient. Follow the [routed-result checks](/docs/guide/private-zones#check-the-full-routed-result) to tell destination credit apart from a callback failure and bounce-back.

:::warning
If the routed withdrawal fails on Tempo, the amount [bounces back](/docs/protocol/zones/bridging#withdrawal-failure-and-bounce-back) to the withdrawal's `fallbackRecipient` inside the source Zone. Failures include a failed swap or transfer, a reverting router callback, or a target deposit that can't complete. The sequencer still collects the fee, so a failed routed swap still costs the sender fees.
:::
