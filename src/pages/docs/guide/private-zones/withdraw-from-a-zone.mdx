# Withdraw OUSD

Move `OUSD` test tokens from Zone A back to your public Tempo balance.

## Overview

A direct withdrawal moves `OUSD` test tokens from **Zone A** back to your public Tempo balance. It uses the [testnet sandbox](/docs/guide/private-zones#testnet-compatibility), which differs from current deployments. The withdrawal exits through the outbox (`ZoneOutbox`) on the Zone. You submit the request in the Zone, then wait for your Tempo balance to increase after the batch settles.

## Code Examples

These snippets assume a signed-in `rootClient` on Tempo, a derived `zoneAClient`, and the usual token constants in scope. The calls target the sandbox's SDK interfaces.

Standard withdrawals omit an encrypted sender disclosure. Authenticated withdrawals attach sender details encrypted to the holder of the `revealTo` public key. Both flows keep the public recipient and amount visible.

<Tabs stateKey="zone-withdrawal-example-mode">
  <Tab title="Standard">

```ts
import { parseUnits } from 'viem'

const withdrawalAmount = parseUnits('100', 6)

await zoneAClient.zone.signAuthorizationToken({ zoneId: 6 })

const { receipt } = await zoneAClient.zone.requestWithdrawalSync({
  account: rootClient.account,
  feeToken: ousd,
  amount: withdrawalAmount,
  token: ousd,
  to: rootClient.account.address,
})

console.log(receipt.blockNumber)
```

  </Tab>
  <Tab title="Authenticated">

```ts
import { parseUnits } from 'viem'

const withdrawalAmount = parseUnits('100', 6)
const revealTo = '0x031dc147467e8f106eb22850fef549dc74b8f6634aeac554ebdd4ab896b67cdf68' // [!code focus]

await zoneAClient.zone.signAuthorizationToken({ zoneId: 6 })

const { receipt } = await zoneAClient.zone.requestVerifiableWithdrawalSync({ // [!code focus]
  account: rootClient.account,
  feeToken: ousd,
  amount: withdrawalAmount,
  revealTo, // [!code focus]
  token: ousd,
  to: rootClient.account.address,
})

console.log(receipt.blockNumber)
```

## Withdrawal Settlement

A direct withdrawal is the most direct way out of a Zone. The outbox burns the Zone balance and includes the request in the next withdrawal batch. Tempo then settles the amount to a public Tempo address.

The Zone accepts the request first. Your Tempo balance changes later, when the sequencer submits and processes the batch on Tempo.

A failed withdrawal doesn't stay stuck. If processing on Tempo fails, the protocol [re-deposits the amount](/docs/protocol/zones/bridging#withdrawal-failure-and-bounce-back) into the Zone to the request's `fallbackRecipient`. The fee is still consumed.

:::warning
  A direct withdrawal can fail on Tempo even with `gas: 0n`, such as on a token transfer or policy check. The amount then bounces back to `fallbackRecipient` on the Zone. The public balance doesn't increase.
:::
