# Network examples

Set up the clients used by the Network guides: [Send a transaction](/docs/network/transactions), [Pay fees](/docs/network/fees), [TIP-20 tokens](/docs/network/tokens), and [Deploy a contract](/docs/network/contracts).

The examples run on Moderato, Tempo's testnet ([chain ID `42431`, RPC `https://rpc.moderato.tempo.xyz`](/docs/accounts/wallets/add-tempo-to-your-wallet)). They pay network fees in AlphaUSD, a test stablecoin at `0x20c0000000000000000000000000000000000001`. BetaUSD, at `0x20c0000000000000000000000000000000000002`, is a second test stablecoin for swap examples. Both are [TIP-20 tokens](/docs/protocol/tip20/overview), Tempo's stablecoin token standard, with 6 decimals: 1,000,000 base units is one AlphaUSD.

Each setup reads the same three environment variables. Keep private keys on your server.

- **`TEMPO_PRIVATE_KEY`.** The sender's private key, used by the Viem and Python clients.
- **`TEMPO_SENDER_ADDRESS`.** The sender's address, used by the CLI and HTTP examples.
- **`TEMPO_RECIPIENT`.** Another test address you control, which receives the example transfers in every client.

Fund the sender with the [faucet](/docs/quickstart/faucet).

## CLI setup

Install the latest [Foundry](/docs/sdk/foundry#get-started-with-foundry) with Tempo support. The snippets use `cast` for contract calls and transactions. `--interactive` prompts for the test account's signing key. The Exchange quote command also uses `jq` to read the JSON result.

Export the shared values. `TOKEN` is AlphaUSD and `BETA_TOKEN` is BetaUSD. `FACTORY` is the TIP-20 factory that creates tokens, and `DEX` is the Stablecoin DEX:

```bash
export RPC_URL=https://rpc.moderato.tempo.xyz
export SENDER="$TEMPO_SENDER_ADDRESS"
export TOKEN=0x20c0000000000000000000000000000000000001
export BETA_TOKEN=0x20c0000000000000000000000000000000000002
export FACTORY=0x20fc000000000000000000000000000000000000
export DEX=0xdec0000000000000000000000000000000000000
```

The [token creation example](/docs/network/tokens) stores its new token's address as `DEMO_TOKEN`. The [Foundry Tempo guide](https://www.getfoundry.sh/guides/tempo) documents current CLI options, including fee tokens and remote sponsorship.

## HTTP requests

JSON-RPC reads use the Moderato RPC endpoint, `https://rpc.moderato.tempo.xyz`, without an API key.

Gas estimation (`eth_estimateGas`) needs the sender address and calldata. Run this block. It reads `TEMPO_SENDER_ADDRESS` and `TEMPO_RECIPIENT` and uses [Cast](/docs/sdk/foundry) to encode a one-AlphaUSD transfer as `CALL_DATA`:

```bash
export RPC_URL=https://rpc.moderato.tempo.xyz
export SENDER="$TEMPO_SENDER_ADDRESS"
export TOKEN=0x20c0000000000000000000000000000000000001
export CALL_DATA=$(cast calldata 'transfer(address,uint256)' "$TEMPO_RECIPIENT" 1000000)
```

JSON-RPC broadcasts transactions that are already signed, so the signing key stays in your application or wallet. For transaction submission, set `SIGNED_TX` to a hex-encoded signed transaction, such as the `signed.encode()` value in the Python `submit` helper. For receipt lookup, set `TX_HASH` to the returned transaction hash.

The [JSON-RPC reference](/docs/protocol/rpc) documents method behavior. The [hosted API](/docs/api) is a separate interface for indexed data and services.
