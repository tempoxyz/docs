# Security and compliance

Start with [Screen blockchain payments](/docs/resources/guides/payment-screening) to choose address screening, transaction monitoring, or a pre-signing security check. Use the providers below for the part your application needs.

Connect these tools to your application's operational checks. For onchain receiving controls, see [receive policies](/docs/accounts/policies/receive-policies); for payment attribution, see [transfer memos](/docs/guide/payments/transfer-memos) and [virtual addresses](/docs/guide/payments/virtual-addresses).

## <span className={`partner-logo partner-logo--blockaid ${partnerLogo().className + ' ' + partnerLogoBlockaid().className}`} aria-hidden="true" />Blockaid

[Blockaid](https://blockaid.io/transaction-security) previews a proposed transaction's effects and returns security findings before signing. See [transaction simulation](/docs/resources/guides/payment-screening#blockaid) for the Tempo scan method and output options.

## TRES

[TRES](https://www.tres.finance) is the accounting and reconciliation layer for digital asset payments. TRES reconciles onchain settlement against internal and custodial records daily, then delivers the output in bank-grade formats such as MT940 and custom formats so finance and treasury teams can keep using their existing TMS and ERP without a rewrite.
